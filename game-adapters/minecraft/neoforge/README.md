# NeoForge：用户现有NAIMEI客户端

目标是用户提供的Minecraft 1.21.1、NeoForge 21.1.248、FTB Presents Direwolf20 1.22.0整合包。游戏和执行检查只在`remote-3080`的`DESKTOP-2QQPN1H`运行；编辑电脑只修改源码、打包和复核保存的证据。禁止Docker、WSL和虚拟机。

`NativeGamePort`读取当前玩家与服务器实际对象，提供正式世界状态、配方查询和渲染目标帧。`NativeBridge`复用Fabric目录中不依赖加载器的`core`源码，包括原有`BridgeCore`、`Wire`、`ControlArbiter`及`LocalJournal`。构建包含本目录的Mojmap Mixin，不包含Fabric入口、Fabric Mixin、MinecraftPort或生存候选，不创建第二个玩家、人格或输入仲裁器。

`POST /api/dsh/game/queries`的`kind: frame, params: {}`取得经过JPEG解码、尺寸、序号、世界和操作归属核对的原始帧回执，再从既有`/frames/<frame_id>`读取图片。它沿用视觉采集的启用开关、单并发、限频、过期和断线取消；不要求视觉模型，也不返回模型描述。原`kind: observation`仍要求真实模型准备与推理，不因原始帧可用而宣称视觉理解完成。

NeoForge接入同一玩家的`use_item`事务：原版食物单次食用、装备和当前准星处的原版实心方块放置。原版盔甲与鞘翅进入对应装备槽；盾牌及其他注册物品放入副手，模组物品仅允许这种库存交换，不能任意激活模组物品。每次点击绑定原租约、世界、玩家、连接和交互对象，并用服务器完整库存包与后续世界观测核对结果；食用和放置还需要对应食物/方块效果，预测不算完成。

键盘、鼠标、光标回中、重复使用与持续挖掘抑制、库存同步、点击修订和合成菜单八项钩子实际加载后才报告`native_core`、`use_item/cancel/navigate/gather/return_base/craft`技能与`cancel_all`功能；缺任一钩子仍报告`none`并拒绝AUTO。八项钩子由六类Mixin提供。物理键鼠在原版处理前撤销自动控制，F10进入PAUSED，其余输入进入MANUAL_COMMENTARY。失焦、界面、断线、换世界及租约撤销沿用唯一仲裁器；清理只恢复本适配器持有的键、移动对象和快捷栏，不清空人工按键，不影响后来任务。接线检查属于完整交付内部工程验证，不能解除Fabric生存执行器的preLaunch拒绝。

`NativeTravel`在同一任务会话中实现有限行走、返回已登记基地和资源采集。`NativeWalkPlanner`只搜索实际已加载地形，每次最多1024个节点和24格水平范围，较远目标分段重算；检查支撑、碰撞、头顶空间、流体及危险方块。当前包含一格上升、最多四格的受限干燥下降、普通挖阶、实际半格起点，以及土径/耕地15/16表面；实际脚底高度仍须满足四格下落上限。树叶按真实碰撞支撑处理。受限水中上岸另须在256节点和160水中tick内核验实际岸边，不能泛化为任意游泳、攀爬、复杂台阶或跨维度能力。走路通过原玩家的任务专属`Input`继续执行，每次原版tick重新核对租约及世界；不瞬移、不直接改速度。具体实现与实机通过范围分别见[自主游玩说明](../../../docs/technical/mc-live-v1/Agent与Mindcraft自主游玩.md)。

采集目前限已知原版资源：部分木料、泥土、圆石类及普通矿物，优先拾取已知掉落物，否则寻找附近安全来源并使用已有快捷栏工具。采集通路可规划需要清除树叶的短路线，但每次实际移动前都必须先按真实视线清除阻挡，并重新确认碰撞；只清除目标视线或通路中的树叶，保留当前玩家和目的站位的支撑。普通导航不清除方块。到达前减速、停稳并连续确认，再交给后续状态验证。挖掘沿用当前玩家与原仲裁器，回执必须有服务端完整或单槽库存包及后续库存净增；净增本身不能独立证明物品来源。方块实体、液体、危险支撑和未知资源均不能任意开采。普通合成与炉具接线见下文；完整补给、资源图和PvE仍待接入实际NeoForge客户端。

实际钩子从未就绪变为就绪时，由原BridgeCore先撤销控制和原任务，再重新建立同一权威连接发布最新能力；保留原启动、世界及账本身份，保持PAUSED，不恢复旧AUTO租约。管理端无需人为断开套接字修复旧能力。能力丢失时同样先撤权，再协商。

`NativeCraft`接入当前服务器收到的普通有序/无序合成配方：背包2×2或已加载、可见且在交互距离内的普通工作台3×3。只接受库存可满足的唯一配方，按实际每批产量向上取整；组件匹配、重叠材料分配、配方重载、产物与剩余物逐批重查。合成使用原玩家菜单和原租约，每次原版点击由`CraftExchange`等待服务器完整库存与光标确认，不靠预测或库存净增认定合成。工作台界面只允许原任务主动打开并按真实菜单/界面对象绑定的那一个；撤权后不点击、不关人工界面，不自动回滚已发生效果。完成后空格子、空光标、完整批次回执及后续观察同时验证。

合成纯事务核心依据既有候选模块的`CraftClicks`提取，补充15位修订序号的新旧判断；原Fabric生存源码、JAR与启动门禁保持原状，NeoForge不加载候选模块。完整自动工作台准备、缺失材料资源图、模组机器、动态特殊配方、补给和完整PvE继续待接入；普通炉具接线见下文。实际通过范围以实机证据为准。

## 配置和构建

配置位于独立游戏目录的`config/ai-talk-streamer-bridge.json`，首次创建为禁用。启用时只接受`enabled`和`endpoint`两个字段；端点必须使用现有桥协议路径，例如：

```json
{"enabled": true, "endpoint": "ws://127.0.0.1:8020/api/dsh/game/bridge"}
```

两个Java依赖的版本、字节数和SHA256固定在[桥依赖锁](../../../configs/mc-neoforge-bridge.lock.json)。先将对应官方Maven文件放入安装内的`runtime/minecraft/mc-friends-s1-neoforge-21.1.248/dependencies`，构建入口复核摘要，再以NeoForge Jar-in-Jar格式嵌入。SQLite原生库、服务声明与许可证保留在原依赖中；不使用Loom加工的Fabric依赖替代官方文件。

在3080的实际源码安装内运行以下入口，`--source`指向已经按客户端锁核对过的私有静态整合包目录，`--jdk`为已有原生JDK21：

```text
python scripts/mc_neoforge.py prepare --source <supplied-pack>
python scripts/mc_neoforge.py build-probe --source <supplied-pack> --jdk <jdk21>
python scripts/mc_neoforge.py probe --source <supplied-pack> --server 192.168.196.204:25565 --world-samples 60 --timeout 900
```

构建记录绑定NeoForge源码、共享核心、协议schema、桥依赖锁、构建脚本和实际依赖。修改这些输入后必须重新构建。每次编译使用新的类目录，成功后才原子替换项目自己的适配JAR；319份原模组不改写。探针保留5至300次世界采样及最长900秒限制，使用创建时即归入原生Job的进程归属回收。

配方扫描在NeoForge显式使用65536项上限，输出仍受16项、每槽16个候选及49152字节限制。模组配方可能没有静态物品产物或在静态查询时抛出异常：仍有已知配方时返回明确不完整的结果，将候选总数和歧义列为未知；没有已知配方时返回投影不可用，不宣称没有配方。查询不代表已经制作或材料足够。

## 工程联查与交付边界

[实机联查宿主](../../../tests/mc-neoforge-live-probe.mjs)只允许在3080运行，使用正式GameManager、HTTP/WebSocket和真实NeoForge客户端。其DSH上下文明确禁用人格注入、弹幕和口播，不代表整套主播已经启动。它保存状态、操作回执、游戏帧、配方结果和重连代际，并保持正式验收为0。主程序仍必须通过自己的原生准备、设备来源、单一DSH写入者及完整发布门槛。

宿主默认只观察状态、查询配方及取帧；显式传入`--execute-items`才授权本次工程检查的`use_item`技能，优先操作原有模组说明书，否则使用当前背包已有物品，并等待远程操作者实际按F10、Shift和移动鼠标。接管证明同时核对正式模式/释放回执、存活游戏界面，以及客户端当前启动/世界/代际的准确停止原因；死亡、GUI或租约暂停均不能冒充F10。它不在本机运行、不调用假的物理输入回调，也不把空闲时接管计作20次任务中断验收。

显式`--execute-travel`另授权上述三个移动/采集技能，按实际观测登记工程测试起点，执行走路、返回与采集，再等待20次运行任务中的F10、Shift或鼠标接管。每次要求任务已运行、移动对象确由任务持有、当前玩家实际发生位置变化，接管后任务取消且输入释放。系统输入测试与真实硬件操作、停止延迟及完整正式验收分别记录；只声明已保存证据确实通过的部分。

该工程模式在暂停状态下先等待`WINDOWS_FOREGROUND_REQUIRED`：3080侧输入驱动须核对本次游戏PID、创建时间和系统前台窗口，再写入当前测试、世界与控制代际的短时确认。每次接管输入前仍重新检查真实前台、存活状态、运行任务和输入归属；窗口不符就拒绝输入。后台测试驱动避免启动控制台改变前台，不承担模型、人格或游戏任务调度。

显式`--diagnose-remote-shortcut`可在正式F10步骤前另行观察当前远程工具发送的按键包。只有原生integrationProbe启用且发生AUTO下按下事件或F10按下时，私有原因回执才保留该次键码、扫描码及撤权前代际；不连续记录键盘输入。工具发送结果、客户端实际事件与正式控制回执分别核对，错误扫描码不能冒充正确F10。

当前按Agent＋Mindcraft物品依赖求解器的原生移植继续自动采集、合成、工作台准备、撤退及普通死亡重生；这是同一玩家的实际任务执行，不是完整上游Mineflayer运行时。日常进度不依赖人工接管。唯一输入所有者、物理停止、租约与新鲜世界回执保留；连续死亡限频十分钟内三次，到期后由Agent重新检查，不关闭保护去刷重生。完整长时间生存、补给、弹幕并发和节目联调仍以[实现进度](../../../docs/technical/mc-live-v1/实现进度.md)为准，所有D01—D15、68项正式验收与100段新人物素材要求保持。

撤退规划优先处理十格内的收到敌人，候选同时比较十六格内其他敌人的距离，避免只远离最近僵尸而接近苦力怕。候选改善最近危险距离，对原本较远敌人保留四格距离，对已经贴近的敌人保留改善距离的短步逃生；没有四格远的候选不代表原地等待更安全。原生短距离撤退同样复核附近敌人和路线。十二格内有实际敌人、食物大于6、落地、干燥、无横向碰撞、未使用物品、航向误差不超过25度且相邻表面高度差不超过1/8格时，可申请原版疾跑键；最终站位仍减速并等待落地停稳。疾跑只走原输入台账与原租约，不直接设置速度、位置或游戏规则。该实现不能替代实际生存验收。

打包格式参考：[NeoForge Jar-in-Jar官方文档](https://docs.neoforged.net/toolchain/docs/dependencies/jarinjar/)。

显式`--execute-craft`用于3080实机原木→木板→木棍→工作台→木工具链。测试宿主仍为惰性DSH：2×2合成、正常准星放置、3×3工作台及后续背包状态均需实际回执。暂停时的工程鼠标准备与自主模型规划分开记录；前台证明的Windows创建时间以十进制字符串传递，原始整数身份仍由3080输入驱动精确核对。

## 普通炉具转换

`NativeSmelt`复用现有`craft`目标、原任务会话、同一个控制仲裁器和玩家。普通熔炉/烟熏炉/高炉只接受实际收到的对应原版配方类；原料必须匹配当前服务端会优先选择的配方及实际产物组件。预留全部原料后按实际燃烧时长分配有限燃料，每批1至4原料、批数与总期限有界；带特殊组件、容器余物或目标产物不会作为燃料。完成需要服务端转换、回收和后续库存共同证明，实际通过范围以当轮证据为准。

打开实际可见且够得着的炉具后，绑定本任务的准确菜单/屏幕对象和第一份完整空炉库存。`CookingExchange`逐槽及光标比对，完整回包确认单次点击；异序单槽更新只有形成原料消耗与产物成对一致的状态才推进转换记录。取消后保留最后已确认部分转换，不继续点击或关闭界面；残留材料/光标需要新的观测和明确恢复流程。烟熏、高炉、配方重载、服务端限制和运行中炉具接管各自需要实机证明。

`--execute-smelt`是3080专用惰性DSH工程检查：实际补料、采集圆石、返回起点、需要时准备工作台、制作/放置炉具及两次木炭增量目标。工程宿主不负责人格、模型、弹幕或口播；暂停时前台身份核对和系统鼠标准备另行留据。可清除朝已知圆石来源的有限土层遮挡，最多24个土层位置、64个无可达站位来源，保留玩家支撑并避开危险/液体/方块实体；它不建立通用地下隧道或完整资源图能力。

普通方块放置预检和执行前均核对实际放置状态、存活条件及实体碰撞；仅可替换的目标格不能单独作为允许依据。服务端仍须分别确认库存消耗与目标方块效果，失败不会自动重复放置。

炉具工程检查的暂停视角准备采用最多20步固定俯仰/水平扫描，每步重新确认前台及当前控制代际。独立测试副本关闭原始鼠标模式以接收Windows相对移动；这属于测试辅助，不是自主选址、模型控制或真实硬件接管验收。

## 采集工具与背包换装

100食物来源扫描限已加载、世界边界内及真实可见的16格球体/上下6格，保留`scan_origin`和原采样时间，每次最多8条。缓存最多一秒且玩家距原点不超过4格，不能把缓存时间改成新观测。耕地候选仍只扫描身边6格/上下3格。干草块是可采集面包原料，不能直接食用；拆解和面包制作继续使用服务器配方及库存回执，不写库存或保证未来掉落。

采集接近目标时若跳步或拾取移动使先前方块进入当前身体范围，先停止挖掘和移动，再在原有64个跳过来源上限内重选。液体、落物、界面和其他不安全条件仍直接停止，不通过放宽身体/支撑保护来继续挖掘。

`NativeToolPlan`检查当前36格库存的实际采掘资格与速度，优先合适的快速工具；同速时优先当前格和快捷栏，并保留最后一点耐久。原版及模组工具均依实际ItemStack能力判断，不根据名称推断等级。缺少合格工具时拒绝继续采掘。

`NativeToolBelt`沿用原采集任务、玩家和输入租约，把选中的背包工具换入当前快捷栏。一次SWAP必须收到完整服务器库存确认，逐项核对全部槽位、光标及物品组件后才能继续采掘；等待时停矿，不重发换装。撤权后只释放所属输入，不反向交换背包；已发生的换装保留为真实库存状态，后续需要重新观测。每个任务的换装次数有界，单槽更新不能代替完整确认。

`--execute-tools`在3080实际制作工具或沿用已有两把石镐，并通过同玩家采集检查背包换装、服务器回包和后续库存。沿用时须另行核对早前实际合成回执与账本，不能写成当前运行新合成。前次真实任务可能已把工具换进快捷栏，因此另用正常`use_item/equip`任务把当前石镐装备到副手，再采石；该准备有独立的服务器装备回执，不注入或重写库存。铁、煤检查单独保留当前加载区域结果，未找到或未取得的资源不得记为已采集；这仍是惰性DSH工程测试，完整资源搜索、生存规划和模型弹幕口播继续按总计划实现。


`NativeStepPlan`为导航和返营补充有限的普通阶梯开路。优先使用已有走路路径；目标在上方且没有完整通路时，仅从当前已加载岩石或土层规划相邻一格上行，保留当前和目标支撑，不开采矿石、木材、容器、液体或落沙。单任务最多8级、24个障碍，开路总时限120秒。实际世界的可破坏检查、视线、碰撞、正确工具、输入租约、原玩家/连接和前台条件继续逐步检查；服务器不确认就停在本级。

`NativeStepReceipt`同时要求本次挥镐之后的对应服务器方块更新，以及客户端实际空气状态；预测消失、别处更新、服务器回滚、撤权后的迟到包均不能授权攀爬。清理完成后再次检查支撑和身体/头部空间，落地后才计入已爬级数。撤权沿用原输入释放，不补挖、不铺方块、不移动物品作为回滚。

`--execute-exit`仅在3080以NAIMEI执行惰性DSH工程检查：从真实矿坑导航到此前观测的工作台落脚点，核对实际高度变化、逐块服务器确认，再用普通合成制作石斧，登记实际位置并检查走路/返营。它不授权传送、指令给物品或公开推流，也不代替资源图、战斗、弹幕和模型主播的整体验收。


阶梯候选还必须有当前实际可站立的最终落脚点；不能因为第一阶可挖就接受不可站立的终点。私有导航回执保留终点站立、完整现有路线和阶梯可用判断。`--execute-exit`在前次已经实际清理的通道上重新检查矿坑往返，再选择当前可达的工作台位置；前次失败任务中清理的障碍单独绑定其原始源码、方块回包和失败账本，不写成最终运行新挖或成功任务。

基地登记遵守正式主控的暂停条件：先完成PAUSED和输入释放，再按实际位置登记；登记后重新获取AUTO租约执行走开与返营，不放宽接口门禁。

## 应用准备接线

当前应用采用独立的[NeoForge3080配置](../../../configs/deployment-profiles/mc-native-3080-neoforge-v1.json)，原Fabric配置及其生存preLaunch拒绝保留。`mc_runtime.py neoforge-status`只核对已安装的NAIMEI客户端、原319个模组、当前控制器源码/JAR/嵌入依赖、复制后的原生库、实际JRE和资产索引所列对象；不启动游戏、DSH、模型或直播。资源对象使用原索引SHA1核对，并将实际SHA256纳入应用准备清单。

完整应用准备另须使用`ws://127.0.0.1:3092/api/dsh/game/bridge`的明确游戏配置；工程探针18974不能获得应用准备证明。设置、生成配置、日志、存档和任务账本不作为不可变依赖，原账号缓存不导入。资产清单通过仍只是应用准备的一个前提，不能证明DSH联合运行、100段新人物、完整节目或68项最终验收已通过。


## 上阶前的原地对齐（v99）

098实测中，角色身体尚跨在邻格时已推进路点，下一步抬升会被真实碰撞检查拒绝。099将路点中心距离收紧至0.1格，接近每个路点时减速；路线搜索或下一步碰撞失败时，可以在当前格子内先用普通移动对齐。每次对齐重新核对落地、支撑、身体扫掠、危险和流体，单次最多40tick、同格最多两次、每任务最多120tick及六次。沿用原输入所有者和租约，不写位置、速度或世界，也不因对齐刷新无进展时限。挖阶后的落点及碰撞仍须重新检查，具体脱困效果以原离线世界实测为准。

## 放置位置变化与采石前准备（v81）

放置或种植动作在发送交互前，重新核对到位置已变化时，返回固定类型的任务失败。只有明确目标的activate动作、当前租约和世界仍有效、游戏界面干净、输入清理及结果送达成功时，才允许Agent按新观察重新选择位置；失败仍记为failed/unknown，不冒充方块已放好。普通异常文本、错误技能/用途、缺失目标、确认超时和清理失败不适用该恢复。

Mindcraft产出圆石或煤采集依赖前，要求准备一张真实持有的便携工作台；已经放在地面的工作台仅能满足合成依赖，不能冒充背包物品。材料不足时继续通过实际配方拆解采木或制作，准备被拒绝则进行有界路线探索，不直接下矿。完整石器链仍须原离线世界实测确认。

## 普通着火与生存动作失败的自主恢复（v80）

普通着火不再作为采样异常抛出并冻结整个离线世界。Agent优先核对新鲜撤离路线，无已收到敌人时保持世界运行并持续重读状态，火焰真实消退后再推进生产，不虚构水源或灭火效果。在移动任务内着火可继续已核验路线或撤离；战斗会退让。工作台事务已打开菜单时保留其有界服务端确认路径，不能把部分点击直接重放；仅在干净游戏界面边界返回明确的危险中断失败。

已知撤退/防御无进展、次数边界和补给不可用在原租约、世界、干净游戏画面、清理及结果送达全部有效时返回真实failed/unknown，让Agent重规划。岩浆和低氧单独标为SURVIVAL_ENVIRONMENT_UNSUPPORTED，仍保留停止边界；未知异常、服务端确认超时、清理失败、物理或明确停止均不自动放行。完整熔炼/补给、GUI异常自动恢复、岩浆/窒息脱险和长时生存仍待实现实测。
