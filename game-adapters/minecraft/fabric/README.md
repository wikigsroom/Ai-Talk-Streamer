## 原生构建与检查

在仓库根目录、`mc`分支执行；先安装JDK21和Node24。Node24用于CPU联合检查，正式DSH仍要求既有锁定的24.22.1。本轮使用24.19.0检查，不宣称已验证正式Node版本。

```powershell
.\scripts\mc_build_fabric.ps1 -JavaHome 'C:\Program Files\Eclipse Adoptium\jdk-21.0.11.10-hotspot' -NodePath 'C:\path\to\node.exe'
```

入口[mc_build_fabric.ps1](../../../scripts/mc_build_fabric.ps1)检查分支/JDK/Node与wrapper哈希，随后运行`test build interopTest`。首次使用wrapper会获取已固定校验值的Gradle8.14.3。已有同版本Gradle可用`-GradlePath 'C:\path\to\gradle.bat'`显式复用；工程拒绝其他版本。`-SkipInterop`只跳过跨语言检查，并在收据中标明，不能作为整组检查通过的证据。只有有意更新依赖锁时使用`-RefreshDependencyLocks`；普通构建按既有锁解析。

脚本仅在调用期间设置构建环境，缓存位于仓库`.setup/mc-gradle`，原生临时文件位于`.setup/mc-gradle-temp`，JUnit临时目录位于本工程`build/test-temp`。中文路径下Gradle工作进程使用`file.encoding=COMPAT`匹配本机原生参数文件编码；Java源码、JSON及契约资源仍显式使用UTF-8。脚本不修改系统环境，不启动Docker、WSL、游戏或模型。

## 客户端接入

本项目约束要求受管游戏实例及其配置、存档留在本项目目录内，例如`.setup/mc-game-instance`。后续原生准备/启停管理器仍需实现；本轮没有创建或启动真实游戏实例。

1. 在该受管实例准备Minecraft Java1.21.1、Fabric Loader0.16.14及上表Fabric API。将构建出的Mod放入该实例的`mods`目录。
2. 采用[配置示例](../../../configs/mc-fabric-bridge.example.json)准备实例`config/ai-talk-streamer-bridge.json`。首次初始化也会生成`enabled:false`模板。仅支持`enabled`、`endpoint`两项；启用桥不自动授予AUTO。
3. `endpoint`指向该安装实际提供的固定游戏WS代理路径`/api/dsh/game/bridge`。示例为本地8020入口；8010固定转发、B接收器路由和A宿主仍需按[部署方案](../../../docs/technical/mc-live-v1/06-部署与故障恢复.md)联合验收。不要把示例地址当作已经运行的服务。
4. 进入世界后先完成能力握手与新鲜快照。在后台显式请求AUTO，B核对世界、控制代数和界面，再经首个心跳引用续租完成第二段确认。重连、换世界和重启均不恢复自动执行。

本地状态位于实例`config/ai-talk-streamer-bridge/mc-control.sqlite3`，当前schema3、WAL/FULL及独占owner.lock；已有schema2先保留一致备份再明确迁移。持久实例标识与账本属于该实例，不跨安装复制。旧`journal.json`首次事务导入前保留逐字节备份；导入后SQLite是权威，历史JSON不再被重读覆盖。原始服务器地址/存档路径不进入对外世界标识。桥写盘在I/O线程，离线维护由独占工具承担，游戏线程不等落盘。数据库路径在正式受管部署中仍需按运行锁解析。

原生备份/离线同安装恢复核心、旧会话归档与容量边界见[B端账本与恢复](../../../docs/technical/mc-live-v1/B端账本与恢复.md)。恢复拒绝活动所有者、错误版本、损坏副本及其他安装身份；当前后台维护入口、统一停控/进程管理和A/B/MC存档联合恢复尚未完成。
