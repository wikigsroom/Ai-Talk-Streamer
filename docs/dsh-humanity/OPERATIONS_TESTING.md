# 原生部署、定期维护、恢复与验收

[总方案](../DSH_HUMANITY.md) · [直播状态](LIVE_STATE.md) · [记忆流水线](MEMORY_PIPELINE.md) · [数据契约](CONTRACTS.md)

本文是后续构建和运行的操作规范。本次文档交付不会安装依赖、创建计划任务、启动 DSH、修改显卡模型或改变现有直播服务。下列新接口和工具只有在对应实现完成后才可执行；标注为“样机”的命令只用于兼容验证。

## 1. 原生环境与路径

| 条件 | 要求 |
| --- | --- |
| 操作系统 | Windows x64，原生进程 |
| 虚拟化 | 不调用 Docker、WSL、虚拟机或其管理命令 |
| 工作路径 | 用户指定的项目目录，工具、home、缓存、数据库和日志均在该目录下 |
| Node | Humanity 要求 >=22；选定并固定经过 P0 验证的补丁版，不把主版本要求当作完整兼容性证明 |
| DSH | 首轮候选 0.2.0-rc.2；完整依赖和 CLI 行为需固定包验证 |
| Humanity | 0.1.17 基础包 + 本项目经审查的连接补丁 |
| SQLite | 选择原生 Windows 可用的驱动，固定版本、ABI 和功能探针；不通过 WSL 编译 |
| 模型渠道 | 用户配置的实际 route/model，验证文本、流式与工具协议 |
| GPU | 沿用 MOSS 04 与 MuseTalk；记忆服务不创建 CUDA context |
| 浏览器 | 复用已安装 Chrome / Edge / OBS 浏览器源；测试后关闭自身不用的 tab/context，不关闭用户页面 |

已有 3080 基线最后一次显存快照约 9,311 MiB 占用、743 MiB 空闲。记忆后端应是 CPU/内存/磁盘服务，不能拿这点余量部署额外 GPU 模型。Node 新增内存、数据库增长与检索耗时均需实测。

## 2. P0 兼容样机

### 2.1 在隔离 home 验证候选包

以下 PowerShell 使用调用者提供的项目根目录，不包含设备地址和密钥。先确认原生 Node/npm 的实际版本符合计划；不要直接执行 npx latest，也不要升级当前已验收的媒体环境。

```powershell
# 样机准备；在用户指定的项目目录执行。
$StreamProjectRoot = (Resolve-Path -LiteralPath '.').Path
$DshToolRoot = Join-Path $StreamProjectRoot 'tools/dsh'
$DshPilotHome = Join-Path $StreamProjectRoot 'state/dsh-pilot'
$DshNpmCache = Join-Path $StreamProjectRoot 'cache/npm-dsh'
New-Item -ItemType Directory -Path $DshToolRoot,$DshPilotHome,$DshNpmCache -Force | Out-Null
$env:npm_config_cache = $DshNpmCache
$env:DSH_HOME = $DshPilotHome
node --version
npm --version
npm install --prefix $DshToolRoot --save-exact '@deepseek-ai/dsh@0.2.0-rc.2'
$DshCommand = Join-Path $DshToolRoot 'node_modules/.bin/dsh.cmd'
& $DshCommand --help
& $DshCommand plugin --help
& $DshCommand web --help
```

项目根目录是外层部署目录，不是随意新建的别处目录。正式启动器必须接收显式 PROJECT_ROOT，不依赖“当前刚好在哪”。npm prefix、DSH_HOME 与缓存路径应检查解析后仍处于该根目录内。

插件管理命令可能需要 pnpm。若固定 DSH 包需要它，使用项目内固定版本，并记录工具 hash 与 store 路径；只配置当前进程所需路径，不修改机器全局 HOME、CODEX_HOME 或用户全局包目录。

确认固定 CLI 支持相应参数后，样机安装基础插件并启动管理端：

```powershell
& $DshCommand plugin --profile web add 'deepseek-harness-humanity@0.1.17'
& $DshCommand web --host 127.0.0.1 --port 3091 --no-open
```

上面安装的是原版基础包，尚无直播 guard、记忆主账本或投影连接器，因此只在 dsh-pilot home 测试，不接入正式弹幕或现有 AI 播报。若候选版本的 CLI 与在线文档不同，修订样机命令并记录结果；不能跳过失败说成安装成功。

### 2.2 必须保存的版本证据

保存运行时补丁版、平台架构、完整 npm lock、DSH/插件 manifest、tarball integrity、连接器 patch hash、profile hash、schema/policy/prompt 版本。项目版本清单不写真实 API key、管理 token 或设备标识。

候选 DSH 和 Humanity 的 peer 范围必须通过实际包管理解析验证，且同一宿主内的 DSH seam 不能悄悄安装两套不一致版本。插件显示为 loaded 不代表所有 optional seam 都已接通。

### 2.3 样机通过条件

1. 原生 Windows 启动，无容器或 WSL 子进程。
2. 真实 standard Agent 的最终模型请求包含发布人格与记忆 section；minimal 的负例必须显示禁用，不得误判为通过。
3. 用户渠道完成一次工具调用和后续最终回答；工具参数、结果、provider usage 可审计。
4. 连接器可以阻断原生记忆写工具、替换对应引导语、禁止过期投影注入，并完成公共 entry 的插入、修订、归档和幂等重放。
5. 工作台记忆编辑被路由到 Bridge；尚未适配时严格只读。
6. DSH cancel 与 disposer 不残留活 Agent；错误、断网、重启不重复创建会话或调用模型。

任一项失败都停留在 P0。可调整连接补丁或选择经用户约束允许的兼容版本，但必须更新规范与锁；不能放宽来源或播放规则掩盖兼容问题。

## 3. 正式启动与健康分层

| 顺序 | 动作 | 失败处理 |
| --- | --- | --- |
| 1 | 解析项目路径、验证锁、取得单实例 owner | 拒绝启动第二个写 owner |
| 2 | 验证 SQLite、迁移版本与最近删除屏障 | 不支持版本只读；禁止自动重建空库 |
| 3 | 回收过期任务租约，失效旧 epoch 与播放 lease | 活动直播进入 RECOVERING |
| 4 | 启动 DSH 宿主、连接器与回环 Bridge | 上游 seam 缺失则 AI 不 ready |
| 5 | 同步人格版本、检查公共镜像和 guard | 镜像落后可读主账本，但不可显示全部健康 |
| 6 | 检查 MOSS、人物服务、媒体协议 | 不预先声明正式 LIVE |
| 7 | 启动演播台与内部调度循环 | 只有显式开播才能进入 STARTING/LIVE |

健康至少分 `process_alive / state_store_ready / dsh_ready / persona_injection_ready / memory_ready / projection_synced / tts_ready / avatar_ready / authority_ready`。某一个 HTTP 200 不能代替这些状态。

模型 key 读入后只能通过受控客户端使用；健康响应仅有 configured/route revision，不回传原值。已有 `channel.env` 的迁移采用本地引用或管理员输入，不能把内容复制到文档、截图或证据 JSON。

## 4. 开播、暂停和下播操作

开播前检查发布人格、角色/房间选择、当前播放权威和模型渠道。开播动作创建 broadcast_id，页面展示 STARTING，全部条件满足才显示 LIVE。后台整理若在运行，立即撤销其提交权。

暂停会清理当前音频并保留同场上下文，显示 PAUSED；暂停不触发夜间整理。结束操作显示 DRAINING，等待当前请求收尾或明确停止，随后 ENDED；界面单独显示“等待整理 / 整理中 / 整理失败 / 已完成”。

示例：22:00 下播，当前句子正常排空后封口，22:02 以后才允许 post_broadcast。若 22:01 再次开播，旧作业 DEFERRED；新场结束并达到静默条件后再处理积压。03:30 到来时仍在直播，daily_merge 也只入持久队列，不启动批量归纳。

即使渲染页面关闭，直播状态也不会自动 ENDED。OBS 和演播台之间的权威切换必须经过管理动作，旧租约立即失效；不能同时把两者的回执拼成同一次完整播放。

## 5. 周期任务运行与积压

所有时间与默认值来自策略示例。调度器每五秒检查持久 schedule occurrence、作业 eligibility 与预算；不得仅在内存 setTimeout 后假设重启也会执行。

| 情况 | 必须呈现的状态 |
| --- | --- |
| 直播未结束 | DEFERRED / reason=live |
| 下播未达到 120 秒 | DEFERRED / reason=quiet_window |
| 每日预算已满 | DEFERRED / reason=budget，给出下次可执行时间 |
| 模型临时失败 | RETRY_WAIT，显示 attempt 和退避时间 |
| 正在开播 | PAUSED，旧 lease_generation 不可提交 |
| 主账本完成而镜像未同步 | PROJECTING / projection_lag |
| 全部块提交且镜像验证完成 | COMPLETED，显示覆盖场次和消费水位 |
| 没有新增内容 | SKIPPED_NO_CHANGES 运行记录，不调用模型 |

长时间直播会延迟整理，这是预期行为。积压多时按已结束场次时间和手动优先级处理，不能为了清队列并发占满模型或略过来源。管理界面允许取消未提交作业、限制范围重建，不能重置费用账本绕过每日上限。

## 6. 备份与恢复

### 6.1 一致性备份

备份 manifest 至少记录：SQLite schema/user_version、数据库 hash、角色/人格版本、所有源与记忆水位、删除 generation、DSH/插件/connector/profile 锁、Humanity 镜像 revision、策略与提示词版本、创建时间和一致性方法。

SQLite 使用驱动支持的在线 backup API 或经验证的 VACUUM INTO 路线，不能只复制一个活跃的 .sqlite3 主文件而漏掉 WAL。Humanity 通过经验证的 flush/导出或停写快照获得；连接器无此能力时，在下播后有序停止 DSH 再复制其 home，不能赌 JSON 文件刚好写完。

备份短暂冻结业务写入并记录起止水位；期间不允许人格编辑和新作业提交。媒体推理可以独立保留，但正式备份优先安排下播。备份文件仍保存在项目目录，不提交 Git。

### 6.2 删除屏障独立保留

最新删除/撤销控制记录应另作受保护的 append-only ledger 或独立导出，不与旧快照一起回退。数据库提交后通过受恢复检查的 outbox 同步该控制副本；未同步完成的删除状态在备份清单中显式标记。

恢复旧快照前必须取得不早于生产最近水位的删除 ledger，并重放后才允许记忆读取。若最近删除记录已丢失，无法保证恢复不会复活旧内容，系统保持只读、禁止自动回扫，等待确定的恢复处置。不能宣称旧备份天然满足最新删除要求。

### 6.3 恢复流程

1. 停止新 AI 请求与整理任务，撤销播放租约，保存当前状态供比对。
2. 验证备份 manifest、hash、schema 与版本锁，在新的项目内恢复目录校验。
3. 应用最新删除/撤销记录；失效其相关摘要、候选与投影。
4. 运行 quick_check / foreign_key_check，验证关键 revision 与源引用。
5. 启动 Bridge，递增 epoch，原活动直播进入 RECOVERING，不重播历史音频。
6. 对账 Humanity 公共投影，保持只读或主账本回退读取，直到同步一致。
7. 通过恢复验收后切换目录引用；保留旧目录供差异核查，不用递归删除作为默认操作。

恢复与降级都不能用旧库覆盖刚产生的新互动。回退代码版本前，先验证该版本能读取当前 schema；不能读取则以只读导出保全数据，保留明确的 Echo 模式，而非重建空记忆。

## 7. 停机与资源释放

有序停机先停止接纳请求，再结算或中断音频，封闭本场并持久化 job；随后停止调度、完成短事务、释放 Agent、flush/关闭 DSH 与 Bridge。权威租约失效，浏览器清空自身缓冲并关闭不用的测试页面。

停止人格后端不意味着 MOSS 与 MuseTalk 已释放显存。若用户要求释放 GPU，需要另外停止对应媒体服务并核验 nvidia-smi；不能用关闭 DSH 代替卸载语音模型。本方案文档构建不执行任何这些停机动作。

## 8. 指标、日志与资源预算

| 指标组 | 必须记录 |
| --- | --- |
| 对话 | queue wait、上下文构建、模型首字/完整回复、工具轮次、最终文本长度 |
| 媒体 | TTS、首发送、首播放、完整播放、取消耗时、音频 gap、实际呈现 FPS |
| 状态 | 活跃请求、过期 generation、拒绝回执、authority lease 变化 |
| 记忆 | 分区条数、检索命中、冲突、来源无效、上下文版本和投影落后 |
| 整理 | 扫描事件/块、提交水位、模型尝试、预算、重试、暂停和 checkpoint |
| 系统 | Node RSS、CPU、SQLite/WAL 大小、磁盘余量、事件循环延迟、GPU 占用 |

日志以 correlation_id 关联，默认不打印完整观众原文和长期记忆。来源详情通过受控管理查询显示。模型费用未配置价格时只报告调用与 token；usage_unknown 必须单列。

性能目标是新增本地检索与上下文准备的可控开销，初始测试目标可设为 5,000 条同分区事实时 p95 不超过 150 ms（不含模型、TTS）。这是设计目标，不是现有实测；未达标应优化索引、分区或缓存，并在报告中说明，不得省略状态和来源检查。

以相同人物、MOSS 04、batch、浏览器、音频缓冲和网络条件对比既有基线；不通过降低输出分辨率、静默换音色、丢音频或关闭审计来达标。长时测试同时观察数据库/WAL 增长与后台暂停是否及时。

| A38 | 最近窗口含另一个观众的专属互动 | 装配前过滤，不能经历史或摘要绕过分区 | 上下文快照与来源 |
| A39 | 引用真实但候选忽略否定、时态或主体 | 自动激活被拒绝；不是引用存在就受理 | 受控事实校验 |
| A40 | 无 Cookie/Authorization 打开网页、管理页和 HTTP API | 无登录或角色门槛，直接操作渠道与记忆；原包整理仍由主调度器统一执行 | 无鉴权 HTTP、浏览器与连接器记录 |

SQL 示例只强制基础关系；A04、A12、A18、A21 等跨组件行为必须使用真实实现与故障注入验证。不能因为示例 DDL 成功执行就勾选整个状态机完成。

## 11. 上线阻断项与发布产物
