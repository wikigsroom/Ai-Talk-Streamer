## 集成缺陷与阻塞

浏览器联调实际发现并已在本分支修复：

1. 正式播放权限与排练启动互相等待。现在 STARTING 状态可以由正式源认领权限，再准备人工播报。
2. echo 人工播报错误地读取 LLM 配置。现在只有 chat 分支读取模型配置；独立回归用例验证 echo 不触发模型调用。
3. 旧直播姬适配器写死女 A 的 8010 地址，且只检查 video 元素。奶妹改用自己的 8052 地址、标题与 512 canvas 检查；旧角色默认值保留。
4. 反向连接不适合长连接的房间事件流。奶妹输出页改用有并发限制的 500ms 状态刷新，避免背景音乐等控制长时间等待。

其中前端修复已在本机 8952 使用，后端最后一版仍待部署。4090 的 Windows-MCP 初始化、工具清单和 ControlStatus 能返回，但 PowerShell、Process、Snapshot、FileSystem 的执行请求持续不返回或超时。直播模型与素材服务仍然可访问。已请求只重启 Windows-MCP，保留 ComfyUI、FlashHead 与语音模型。

源码更新有逐文件散列清单与安装器；只更新 C:/dev/虚拟数字人直播/naimei。`reload_naimei_services.ps1` 核对角色、来源和进程归属，只重新加载奶妹 studio/bridge，保留 8030、9891、9892、8188。`link_naimei_livehime.ps1` 如能找到既有正式客户端，会重新核对真实签名并建立独立来源记录，不复制旧角色状态或伪造客户端已就绪。

验证结果：36 个 Python 用例、71 个 Node 用例通过；素材完整性检查和最新导播界面检查通过。实际播报失败也保留在浏览器记录中，不能用单元测试替代成功的端到端结果。F5 合成、正式播完、打断恢复、延时包装、混音及正式直播姬接入在远程修复后继续执行。
