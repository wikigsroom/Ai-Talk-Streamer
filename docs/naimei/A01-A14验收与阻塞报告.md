# 奶妹 A01—A14：素材、直播接入与实际验收

本轮只在 `naimei` 分支实施 A01—A14，并接入独立的本地直播排练体系。素材、导播、主备语音、真实播放回执及节目调度已经落地。**接入功能通过排练，角色说话画质未通过上线验收**：实时 FlashHead 在部分发音中仍会丢失尖牙、损坏眼睛或模糊脸部。质量标记保持 false，没有公开开播。

## 接入结构与原生客户端

控制端原生 Node 8952，通过局域网认证反向连接访问 4090 上的奶妹 studio 8052；DSH 桥接 3094，OmniVoice/F5 9891/9892。角色流复用既有 FlashHead 8030，ComfyUI 8188 和其他任务继续保留。本轮视频与直播语音推理均在本地设备，未使用 Docker、WSL、虚拟机或云端推理。

4090 安装目录为 `C:/dev/虚拟数字人直播/naimei`。部署包逐文件验证 SHA256，并核验 naimei 分支、来源、显卡与状态目录。启动和重载只处理已验证归属的奶妹服务。控制端启动入口为 `scripts/start_naimei_local.py`，4090 服务入口为 `scripts/start_naimei.py`；局域网连接的私有令牌仅保存在忽略的状态目录，未进入素材包或提交。

官方直播姬版本 8.12.0.11221，通过官方 API 下载。365,064,176 字节安装包已核验官方大小/MD5 与发布者签名；只提取原生程序，没有运行全局安装器。其清单要求管理员权限，普通启动返回 WinError 740；现以仅对子进程生效的 RunAsInvoker 使用当前用户权限启动，未提升权限、修改程序或安装捕获驱动。奶妹的 512 canvas 已在自己的 720×1280 预览中实际加载。测试创建的浏览器页面均已关闭。

客户端当前为登录界面，账号登录、直播间配置、直播姬内部浏览器素材及平台收流没有验收。正式 Chrome 连接只能证明正式浏览器输出可用，不能证明画面已嵌入直播姬。Naimei 预检用 `formal_source_connected` 和 `native_browser_embedding_verified` 分别表达，观众交付仍为 false。将来在 4090 登录后，应添加上表 8052 的正式源地址，而不是静音预览地址；只有一个正式源获得声音权限。公开开播开关当前关闭。

## 已修复的接入缺陷

1. 正式播放权限与排练启动互相等待：允许 STARTING/RECOVERING/PAUSED 状态认领权限，再由导播准备排练。
2. echo 人工播报误读 LLM 配置：只在 chat 分支读取；独立回归确认 echo 无模型调用。
3. 直播姬适配器写死旧角色地址和 video 元素：奶妹使用自己的 8052 地址、标题和 512 canvas；旧角色默认适配保留。
4. LAN 反向连接缓冲房间事件流：奶妹使用有并发限制的状态刷新，背景音乐控制可用。
5. 恢复排练后旧播放租约短暂误判：核对运行代次，并通过有效心跳后才开放混音器声音。
6. 延时节目取消时空闲停止报 REQUEST_NOT_FOUND：先取消排期和队列，仅对实际活动播报执行停止。
7. 原生 Unicode 路径读取、启动错误呈现、真实 canvas 帧数上报和普通权限客户端启动已修复。

首轮 36 个 Python 用例、73 个 Node 用例及接入检查通过；本轮增加原选音色合同与旧缓存保护，共 49 个 Python 用例通过。当前音色独立证据保存于 output/review/naimei-approved-voice-20261031；原始记录保留。代码测试不替代角色画质失败结论。

A15—A22 保持搁置。自动弹幕回复、平台事件自动播报和自动记忆整理关闭。本轮接通的是可人工排练的直播链路，后续公开上线仍需要角色画质通过、奶妹新台词发音与听感复核及账号/观众端验收。用户原选 O07/F07 不应重新选角或替换。
