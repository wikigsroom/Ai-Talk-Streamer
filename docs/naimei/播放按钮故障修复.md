# 奶妹点击播报后没有台词：原因与修复

2026-10-31 用户反馈点击“播报这句话”或节目包装后没有台词。现场确认模型与 O07 语音均已就绪，但只有一个静音预览连接，没有有声播放页。恢复节目请求 req-5549f4d2-ee64-4c90-a74a-056d7af195f1 因此停在 QUEUED。原导播只看模型状态，误显示“本地播报已就绪”；排练状态即使仍为 LIVE，播放页也可能已经关闭。

另一个实际问题是浏览器首次限制声音自动播放时，页面等待 AudioContext.resume 完成，却没有先显示可点击的声音启用提示。先前测试放宽了浏览器自动播放限制，未覆盖普通用户首次打开页面的操作，本次改用要求页面用户操作的浏览器策略验证。

| 修复位置 | 当前行为 |
|---|---|
| 导播的播报与节目按钮 | 在原始点击中打开或复用有声播放页；声音启用后自动继续原操作 |
| 排练准备 | 每次检查真实播放连接；准备排练切换播放代次后再次等待连接有效，随后才提交台词 |
| 首次声音提示 | 等待浏览器启用声音期间，页面立即显示“点击这里启用画面与声音”，支持鼠标和键盘 |
| 连接状态 | 区分模型准备、等待启用有声播放、已连接和可播报；播放页关闭后不继续显示已就绪 |
| 台词与进度 | 显示手动台词或节目完整台词，并查询实际请求的排队、生成、播放与已播完状态 |
| 接口防护 | 缺少有效有声播放源时返回 NAIMEI_PLAYBACK_SOURCE_REQUIRED，不再默默创建待播请求 |
| 节目延时 | 开始执行及动作结束后都复查播放源；关闭播放页会明确报告未播出，不遗留待播台词 |
| 停止与弹窗阻止 | 停止会取消等待声音启用的操作；浏览器阻止弹窗时明确显示处理入口，不提交旧台词 |

实际浏览器检查包含以下六组，测试脚本为 operations/naimei-playback-fix-20261031/check_user_playback.cjs：

1. 缺少播放源时，手动播报及节目接口均拒绝，队列不增加。
2. 原生 Chrome 在 document-user-activation-required 策略下首次打开声音受限，启用提示可见。没有使用允许自动播放的测试参数。
3. 只打开导播，点击播报自动打开播放页；实际语音、字幕、自然结束回执与“已播完”状态一致。预览继续静音且没有播放权限。
4. 点击“恢复”节目，导播显示其台词，正式播放页出现实际字幕，实际语音自然结束。
5. 延时节目等待期间关闭播放页，连接提示更新，节目明确失败且不创建待播请求。
6. 取消等待启用声音的操作及模拟浏览器阻止弹窗时，均不提交旧台词。弹窗阻止分支使用明确标注的前端模拟，其余语音和字幕使用实际本地链路。

首轮六组检查全部通过。49 个 Python 回归用例、27 个语音播放与状态 Node 用例通过，测试创建的浏览器页面全部关闭。证据位于 output/review/naimei-playback-fix-20261031/browser-check.json、first-use-enable-audio.png 和 manual-speech-completed.png。

角色继续使用 naimei 分支、512×512 / 25 帧、原选 O07 主用与 F07 备用。此修复无需重启人物或语音模型；只重载已验证归属的奶妹导播与桥接。没有公开开播，也没有改变既有口型与尖牙画质待验收的结论。
