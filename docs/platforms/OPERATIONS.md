# 平台运行与排查手册

## API

所有路径相对于 `/api/dsh/platforms`。平台页面与接口不要求应用登录、Cookie 或令牌。平台凭据仍按平台的真实协议使用。

| 方法与路径 | 用途 | 产生公开直播吗 |
|---|---|---|
| `GET /status`、`GET /config` | 读取脱敏配置、平台状态、采集状态与事件 | 否 |
| `POST /config` | 保存配置；空密钥保留，null 清除 | 否 |
| `POST /bilibili/client/launch` | 打开已校验的官方直播姬 | 否 |
| `POST /{platform}/prepare` | 按所选模式准备客户端/画面；B站不调用 OBS | 否 |
| `POST /bilibili/window/close` | 关闭空闲的系统预览浏览器 | 否 |
| `POST /obs/launch` | 启动项目 OBS 或复用已有实例 | 否 |
| `POST /obs/prepare` | 创建/更新项目竖屏场景 | 否 |
| `GET /obs/status` | OBS 版本、画布、推流、录制、丢帧、耗时等 | 否 |
| `POST /obs/projector` | 打开窗口化投影 | 否 |
| `POST /obs/record/start`、`stop` | 项目本地录制 | 否 |
| `GET /{platform}/preflight` | 检查人物、语音、渠道、所选输出源、房间和配置 | 否 |
| `POST /{platform}/collector/start` | 启动弹幕；`visible:true` 打开独立登录窗口 | 否 |
| `POST /{platform}/collector/stop` | 停止采集并关闭该采集上下文 | 否 |
| `POST /{platform}/start` | 直接模式开始 OBS 推流；直播姬/伴侣模式准备本地画面和互动 | 直接模式：是；伴侣模式：否 |
| `POST /{platform}/resume` | 恢复同一场直播中暂停或恢复中的本地互动；重新核对所选实际播放端 | 否，不重新推流 |
| `POST /{platform}/confirm-live` | 记录伴侣中的手动开播确认 | 否，不替用户点击伴侣开播 |
| `POST /{platform}/stop` | 结束本模块启动的 OBS 输出；结束对应本地会话 | 结束 OBS 流；伴侣需在客户端另外结束 |
| `POST /events` | 接收统一事件或批量事件 | 否 |
| `POST /douyin/callback` | 接收并验证官方原始回调 | 否 |
| `POST /output/player` | 干净输出源报告连接与播放者信息 | 否 |

正在连接的平台配置需先停止该平台输出和采集后再修改；其他平台仍可单独配置，回复节奏可在直播中调整。

`platform` 可选 `bilibili`、`douyin`、`custom`。UI 保存配置后不自动开播、不自动登录平台，也不自动开始采集。

## 状态判断

| 状态 | 真实含义 | 不应据此推断 |
|---|---|---|
| OBS `outputActive=true` / STREAMING | 编码器已启动对应流输出 | 观众端画面、声音或平台审核已经通过 |
| COMPANION_READY | 直播姬素材或伴侣画面与本地互动准备好 | 客户端已公开开播、观众端已收到 |
| MANUAL_LIVE | 主播点击了“直播伴侣已开播” | 服务端独立验证了平台开播状态 |
| CONNECTED / WATCHING | 消息链路或页面观察器已连接 | 已收到真实新评论 |
| WAITING_FOR_CHAT | 尚无匹配评论节点或需要页面登录 | 平台一定没有观众 |
| RECEIVING | 采集器已收到事件 | AI 回复已经播出 |
| QUEUED | 评论已交给 DSH | 平台观众已听到回复 |
| COMPLETED / 本地播完 | 指定本地播放端确认连续音频样本自然结束 | 网络、CDN、播放器后端已全部播放完成 |

## 停播与恢复

B站正常下播：在直播姬结束公开直播/录制 → 平台页结束本地互动 → 停止弹幕采集。OBS 路径另需停止对应主输出 → 等待当前句排空与 DSH 静默整理。只结束其中一路平台，不终止仍被另一路使用的本地会话。

本地会话处于 PAUSED 或 RECOVERING 时，使用“恢复本地互动”，保留同一广播 ID 与记忆上下文；常规“开始输出”不会隐式解除暂停。若推流请求超时但 OBS 可能已经开始输出，ERROR 记录仍保留输出所有权，可使用“结束平台输出”确认停止，避免遗留未知推流。

桥进程重启不自动重新公开推流。OBS 已有流输出也不能被新的目标覆盖。重连前先检查 OBS、平台控制台与本地会话实际状态；不要只根据保存的输出记录重复点击开始。

网页关闭不等于停播；服务器、OBS 与采集器可能仍在运行。需要停止时使用平台页的结束输出与停止接收按钮。采集器只关闭自己创建的浏览器资料目录和上下文，不关闭日常 Chrome/Edge 或用户其他标签。

## 常见故障

### 有人物，无声音

B站直播姬：确认浏览器素材音量、声音输出到流、素材 720×1280，并检查实际录制文件。独立预览静音，桌面无播放设备也不影响素材内部音频进入混音。详见[直播姬专章](BILIBILI_LIVEHIME.md)。其他平台直接 OBS 推流：确认人物源 `reroute_audio=true`，音量未静音，音频轨道包含该源。伴侣采集：确认 OBS 对该源开启“监听并输出”，监听目标确实可用，伴侣采集同一播放设备。不要把虚拟摄像头当成音频源。用伴侣电平表、OBS 本地录制与另一台设备的观众播放分别检查。

### 有声音，但重复或啸叫

关闭不需要的演播台预览声音、平台回看声音和重复桌面捕获；避免把 OBS 自己的监听声音再次送回 OBS 主混音。伴侣只保留一条人物声音来源。检查 Windows 音量混合器中的实际设备，不仅检查浏览器标签的静音图标。

### 弹幕没有到达

检查房间是否正确、是否正在直播、网页是否要求登录，以及事件表是否出现 RECEIVING/新记录。网页采集不读取打开页面前已有的历史弹幕；请用另一个观众账号发送一条新评论。当前页面 DOM 更新后，检查实际 item/user/text 选择器，或切换 B站 blivedm/官方长链。

匿名平台 UID 为 0 或只有打码昵称时，不强行建立个人身份。需要更可靠的观众区分，应完成平台登录或取得官方数据权限。

### 评论到了，却不回复

检查自动回复开关、回复模式、TTL、同人冷却、全局间隔、本地会话状态、AI 渠道和播放租约。事件表的状态与 reason 解释被跳过、过期或过载的原因。AI 渠道慢时，输入可能在当前回复完成前过期；这比不断堆积分钟级旧弹幕更适合实时直播。

### 画面/声音卡顿

先查看所选客户端的渲染丢帧、编码丢帧和网络重连，再查看本地播放连续性及 GPU 峰值。浏览器预览、OBS、直播伴侣、弹幕浏览器和平台回看会分别使用资源。优先关闭不使用的预览和回看、暂停无关 GPU 任务；保留人物原始推理配置，实测不够时再调整输出或模型。

连续 MOSS 生成前，人物 GPU worker 通过串行 IPC 执行 `release_cache`，释放空闲 CUDA 临时缓存，保留常驻模型张量、精度与 batch。MOSS 返回完整语音后再执行 `prepare_speech`，在实际音频入队前准备人物推理工作区。此顺序用于减少 10 GB 显存下人物缓存、MOSS KV 工作区和 OBS 竞争；不在发声中逐帧清缓存，也不卸载人物模型。取消发生在清缓存期间时，不再提交过期 TTS。

平台事件会持续观察 DSH 中间态，仅在 `COMPLETED/FAILED/UNKNOWN/...` 等真正终态到达时结束同步。`AUDIO_READY` 只表示音频就绪。`UNKNOWN` 常见于播放端重新连接并接管租约，既有语音不会被自动重播；检查 OBS 浏览器源、显存、渲染丢帧和播放端身份变化后再发送新消息。

平台观看存在编码、网络、平台缓冲和 CDN 延迟。网页直连预览的延迟不能作为平台观众端延迟；以观众账号发送的唯一问题和对应回答实际到达时间测量完整链路。

## 定期维护

事件账本默认保留最近 7 天的非待处理平台记录；DSH 的对话与记忆保留独立遵守既有策略。升级平台 DOM、blivedm、OBS 或官方应用协议后，先运行隔离协议测试，再做本地录制与观众端联调，不跳过音频核对。
