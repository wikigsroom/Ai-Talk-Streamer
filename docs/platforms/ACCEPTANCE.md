## 当前直播姬验收

完整步骤、来源哈希、实际测量与失败历史记录在[直播姬独立证据](../evidence/bilibili-livehime.json)，媒体见[当前录像](MEDIA.md)。B站默认路径不启动、连接或调用 OBS，官方客户端已由主播扫码登录。直播姬取本机 720×1280 浏览器素材及源内音频，使用 NVIDIA H.264、30 FPS 录制；人物推理仍为 25 FPS。

```powershell
# 先在官方直播姬开启本地录制；脚本不会点击公开开播。
& '.\tools\node\node-v24.22.1-win-x64\node.exe' --no-warnings '.\devtools\validate-livehime-local.mjs' --echo-only
```

| 场景 | 检查内容 |
|---|---|
| L1 欢迎 | 平台事件进入本地 MOSS 04、MuseTalk，实际客户端播放后确认完成 |
| L2 去重 | 同一个事件重投返回 duplicate，计数增加一次，不再创建语音 |
| L3 讲解 | 不同文本独立生成、画面与声音进入官方客户端 |
| L4 暂停恢复 | 暂停期间消息保持 PENDING，恢复同一场次后播完 |
| L5 连续排队 | 同时提交两条留言，各自独立请求、按序播放完成 |

`--echo-only` 明确表示这五项验证**不包含云端生成回复**，不可称为 AI 实播验收。省略该参数会把 L5 换为真实云端人格回复。初轮渠道 `/models` 返回 200，但实际推理超时；前一轮第五项 `MODEL_TIMEOUT` 保留为失败。随后在主播要求公开开播时重新检查：原 `gpt-6-luna` Responses 渠道的兼容性/记忆工具探针在 16.887 秒通过，独立注入的一条真实 AI 请求也完成本地生成和播放。该后续检查记录在证据的 `cloud_follow_up`，不把原 Echo 五项录像改称 AI 录像，也未更换模型或凭据。

当前真实 B站 595139 WebSocket/心跳连通；验收留言由本地接口注入，未验证真实观众新弹幕。客户端已登录、本地 `COMPANION_READY`、连续样本确认均不等于已公开开播、CDN 已收到或观众已看到。

主播明确要求开播后，首次点击触发官方人脸验证；主播完成核验后再次开播成功，官方客户端进入开播态，B站 API 返回房间595139 `live_status=1`。随后独立拉取公开CDN流10.086秒，H.264 720×1280 / 30 FPS与AAC音轨均解码成功。此次为待机片段，未测量公开流中的可听回复；真实新观众弹幕→回复仍待验收。后续证据见[归档](../archives/2026-10-26-LIVEHIME-HANDOFF.md)与[公开流媒体](MEDIA.md)。

回归包含 76 项 Node、23 项 Python 与 21 路由原生代理探针。播放租约由原 8 秒调整为 30 秒，以容纳已测 11.66 秒人物预热停顿；完成仍要求连续样本和自然结束，详见[配置原因与权衡](BILIBILI_LIVEHIME.md)。真实生成等待保留在完整录像中，不能用节选长度替代响应延迟。

## 实际平台验收脚本

主播准备两端账号：自己的开播账号，以及独立的观众账号。B站在直播姬完成标题、分区及浏览器素材；抖音在直播伴侣完成登录与源选择。每个平台执行以下流程并记录时间、截图与视频：

1. 观众进入房间，确认 9:16 构图、头像身份和背景稳定，连续观看至少 3 分钟。
2. 观众发送唯一短句 A，检查平台事件表收到一次，AI 只回复一次，声音完整、嘴型同步。
3. 同一观众连续发送两条，确认冷却与过期行为符合设置，未产生叠音。
4. 两个相同昵称或两个平台上相同显示名称的测试观众分别告知不同偏好，核对 DSH 检索分区；无平台稳定 ID 时，应明确显示公开对话。
5. 暂停、恢复、本地网络短暂中断后重连，确认不把已经播过的评论再次播出。
6. 结束平台输出，确认平台实际离线；等待 DSH 排空和静默窗口，核对整理任务的分区、来源水位与预算。

人工必须填写：实际直播间 URL、平台客户端/OBS 版本、推流设置、观众设备、网络条件、端到端延迟、视频和音频结果。推流密钥、Cookie 和应用秘密不进入公开验收记录。
