# 07 续接与交接说明

## 1. 下一次接手先读取

1. 本冻结总览、`freeze-state.json`和完整剩余事项；确认仍在`mc`分支。
2. 01中的最后实际安装摘要和本地公共源码摘要，先核对差异再判断哪些文件需要更新。
3. 084i成果/失败、085卡顿证据及086研究状态；旧133秒失败录像和新120秒修复录像不可混淆。
4. 当前私有绑定/来源/状态以3080实际文件及只读预检为准；本冻结没有重新探测远端，历史PID、端口和AUTO不能复用。

## 2. 允许继续工作时的完整路径

| 环节 | 必须满足的条件 |
|---|---|
| 变更设计 | 逐项关联剩余事项、来源、受影响领域与验收，不削减D01–D15，不再拆成面向用户的降级交付 |
| 本地准备 | 仅编辑、打包和审阅证据；运行/构建/推理/游戏均转3080原生环境 |
| 安装更新 | 先核对官方状态和本次进程归属；自有六服务正常停止后，按审查包及摘要更新；运行投影副本同步，不热改运行源码 |
| 状态与来源 | 保持单DSH/Humanity写者，不能整复制.setup或手写来源；数据库/删除链/配置和源码版本一致 |
| 启动 | 设备、profile、来源、依赖/权重/原生程序和实际端口检查；由原流程生成本安装准备记录，逐项真实就绪 |
| 游戏 | 原NAIMEI及原离线世界；已明确停止不能被旧自动开始重放，需新的有效会话授权；日常任务由Agent自主完成 |
| 联机切换 | 等用户提供实际地址；明确模式、身份、模组和取景差异，不自动开LAN或迁移原世界 |
| 媒体复测 | 同时保存游戏实际成果、人物/音频连续性、真实播放回执和时序资源曲线；不以容器FPS代替流畅度 |
| 结束 | 停控并确认输入释放，游戏正常保存退出，停止本安装自有服务和显示要求，保留原官方客户端和用户应用 |

“新会话授权”和紧急停止是控制完整性要求，不是把任务交还人工代打。普通失败、缺资源、遇敌和死亡后补给都仍属于自主能力的待完成范围。

## 3. 状态恢复与留存材料

冻结留存包能恢复本次公共源码、文档、设计、证据摘要和核验样片。它没有替代3080原存档和私有状态的一致备份。实际恢复仍需绑定世界、玩家、A/B业务、Humanity、删除账本、配置、模型和素材版本；不能仅恢复一个SQLite或一个level.dat。

原迁移记录保留241份状态文件的一致备份与120902份离线依赖复制记录。这些是当时已验证的迁移证据，不代表本次重新逐文件检查了全部远端文件。需要灾备时先核对原备份实际存在与hash，保持删除不复活；存在新互动/删除记录时不能直接拿旧库覆盖。

## 4. 冻结维护

- 当前冻结只完成版本留存，不关闭任一功能领域和正式验收。
- 后续修订使用新冻结编号或增补文件，保留本目录原件、JSON、档案和校验记录。
- 若发现本次文档错误，记录勘误、依据和影响；不改旧实机结果，不伪造缺失证据。
- 公开开播、4090恢复、后端切换、世界迁移和新模型更换分别遵守已有用户授权，不从冻结动作推导新授权。
