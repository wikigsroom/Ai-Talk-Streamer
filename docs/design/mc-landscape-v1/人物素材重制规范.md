# MC人物素材重制规范

日期2026-10-29；分支mc；状态：制作计划，未生成新人物媒体。旧720×1280原图、K02素材和原48手势库保留。新MC素材独立版本，不覆盖现有发布指针。

## 1. 目标与人物连续性

主体延续虚构成年角色女A／林知夏、黑色长发与浅蓝卫衣的识别特征。新素材可以重做取景、背景宽度、机位和动作；优先保留日光宿舍的窗帘、木桌、书架与植物呼应。现有原图是身份与光线参考，不是所有新构图必须逐像素复刻的限制。

游戏仍是节目主体。人物不需要全身出镜，也不以保留全部腿部和手部为代价扩大窗口。圆形强调表情，横向强调头肩与可控的小手势；两套素材不能只换文件后缀冒充不同取景。

## 2. 两种候选的交付要求

| 项目 | 圆形素材 | 横向素材 |
|---|---|---|
| 设计母版 | 720×720方形，不预先把四角涂黑 | 1280×720，真实16:9背景和人物构图 |
| 待测推理／合成候选 | 640×640，25FPS | 960×540，25FPS |
| 节目显示 | 264×264外接框、圆形遮罩 | 320×180圆角矩形 |
| 景别 | 头部＋上肩，表情优先 | 头肩／上半身，低幅手势 |
| 背景 | 日光宿舍的一部分保留在圆内 | 按横幅重新布置，不将旧图拉宽 |
| 动作 | 呼吸、眨眼、轻颔首、轻微侧倾 | 同左；额外安排肩侧／胸前小幅手势 |
| 不允许假设 | 原48手势全部在圆内可见 | 裁切旧竖图就能看到原图外的手和背景 |

候选分辨率只是制作与评测输入，不是已经验证的MuseTalk配置。若现有版本对画幅、编码或下游解码存在固定约束，先用旧媒体显示裁切验证链路，再为新媒体设计显式尺寸契约；不能只改角色JSON的宽高。

## 3. 构图与动作安全范围

圆形源以方形归一化坐标为准。遮罩圆心为(0.5, 0.5)，半径0.5；重要面部关键点和头发外缘尽量位于半径0.43的内圆。初始脸部主体参考X0.28–0.72、Y0.18–0.70，眼睛约Y0.38–0.43；具体以真实人物比例和动态逐帧检查调整。

头顶不能贴遮罩边；微倾、点头和说话后仍留余量。肩膀可以被圆自然裁掉，但不能误以为“人物抠像失败”。挥手如确实保留，控制在脸侧小范围且不挡口、鼻和眼；大摊掌、整袖口、膝前操作等不直接沿用为圆形可见动作。

横向源参考人物中心偏右，面部中心约(0.55, 0.43)，左右背景保留宿舍线索。所有关键动作控制在X0.08–0.92、Y0.08–0.92内。手势不得横穿嘴部，不能因扩宽背景而让脸小到320×180最终显示时无法分辨口型。优先头肩构图，再按实际手势需要退到上半身；全身景别不适合这一级窗口。

以下为可执行验收要求：

- 中性静帧、点头极值、侧倾极值、说话张口极值和挥手极值均检查；不能只看封面图。
- 圆形使用实际遮罩后的帧验收，横窗按最终320×180及720P缩放后的约213×120检查。
- 720P中圆形直径为176像素；口型、眼睛和身份仍需可辨，不承诺手机竖持时看清所有手指。
- 镜头固定，不自行推拉摇移，不让宿舍家具／光线在循环接缝跳变。
- 源视频嘴部无遮挡；不烘焙字幕、姓名、计数或礼物提醒。
- 留言、字幕、人物形状切换不触发角色重新开口或回执重复。

## 4. 完整素材范围与内部质量检查

按最新[完整交付规划](../../technical/mc-live-v1/08-完整交付规划.md)，圆形和横窗各交付2段待机＋48段逐项改编动作，共100段，各段按8秒/25FPS规划。中性待机、说话适配／轻回应、倾听微倾和招呼作为内部质量检查样例，比较面部清晰度、动作可见性、循环和新脸框稳定性；所有素材同版交付。

现有索引位于configs/vertical/materials/motion-index.json，包含2段待机和48段手势，总50段、每段200帧、25FPS，即400秒。已生成[motion-reframe-plan.csv](motion-reframe-plan.csv)逐项列出真实旧ID、名称、类别、旧帧段与两种构图的改编建议。所有行都标记为PLANNED_NOT_GENERATED_NOT_VALIDATED。

| 类别 | 圆形改编重点 | 横向改编重点 |
|---|---|---|
| idle | 呼吸、眨眼、头位稳定 | 同左 |
| welcome | 轻点头或脸侧小幅招呼 | 肩侧小招手，不出框 |
| explain | 点头与眉眼回应；不强保大摊掌 | 胸前小摊掌，不遮嘴 |
| emphasis | 轻颔首；减少上下位移 | 低幅头肩／胸前强调 |
| listen | 保留倾听语义，收敛侧倾 | 保留倾听语义与肩线 |
| posture | 袖口、膝前动作改编为上半身微调 | 重做能在横幅中看见的动作 |
| closing | 微笑、点头告别 | 肩侧小幅告别 |

新派生动作使用单独的素材ID／版本和映射表。旧ID仍指向原始动作；不能把“原完整挥手”静默替换成“点头”而不更新映射语义。完成一项才登记一项实测，不把计划CSV当作素材存在证明。

## 5. 素材包结构和元数据

建议新版本结构如下，当前仅为结构约定，尚未创建这些媒体：

~~~text
mc-avatar-circle-v1/ 或 mc-avatar-landscape-v1/
  manifest.json
  neutral.png
  clips/idle-a.mp4
  clips/idle-b.mp4
  clips/welcome-small.mp4
  clips/listen-small.mp4
  motion-index.json
  crop-safety.json
  qa/contact-sheet.png
  qa/result.json
~~~

manifest最少包含角色ID、素材版本、母版尺寸、实际视频尺寸、FPS、镜头、动作语义、源文件SHA256、裁切／遮罩方式和兼容状态。motion-index使用该版本的实际帧数、脸框与素材ID，不继承旧bank绝对路径。

crop-safety记录关键帧、关键点／头部包络、圆心半径或矩形安全框与出界问题；自动指标只能筛查，发丝、嘴唇融合和手部仍需视觉检查。预处理产物和缓存按素材版本分开，避免把旧720×1280脸框套进新方形源。

## 6. 推理、音频和验收边界

优先复用已保留的MuseTalk／Whisper／VAE与O07／F07，不因为换形状引入新TTS或模型。原FP16 batch4是既有设备基线；新画幅的时延、显存、解码和口型需要重新测量。CSS圆形裁切几乎不增加推理工作，但也不会自动减少原有推理成本。

真实素材接入顺序：新源与索引校验→独立预处理→静音视频检查→受控音频驱动口型→唯一正式播放端回执→游戏同机资源和最终编码画面。不得把静态裁切截图算作口型、动作或性能验收。

正式启用前需完成现有分支／部署目标／来源收据检查；本轮没有启动模型、游戏、远程设备或广播。四类小样和完整动作重制均尚未执行。
