# MC横屏直播间设计定稿 v1.0

定稿日期：2026-10-29；工作分支：mc；设计版本：1.0.0；修订：04；状态：DESIGN_FROZEN。依据用户确认，将修订03的布局和风格定型，并纳入“弹幕由后台切换左侧／右侧”的补充要求。

**后续MC实现以本定稿为基准：全屏游戏、右下小圆形人物、连续上滚留言；留言默认右侧，由后台选择左侧或右侧。**

## 1. 固定的设计决定

| 内容 | 定稿 |
|---|---|
| 画布／游戏 | 1920×1080、16:9，游戏铺满底图，不为包装缩小 |
| 人物 | 默认右下圆形，直径264，主体约占画布2.64% |
| 人物备选 | 320×180横向小窗，仍在右下；不与圆形同时显示 |
| 留言 | B站留言姬结构，默认向上滚动，最多4条 |
| 留言位置 | 默认右侧；后台可选左侧／右侧，实时应用并保存 |
| 醒目留言／礼物 | SC进入同一留言流；礼物最多1条短通知，随留言侧边一起移动 |
| 飘屏备选 | 顶部2轨、从右向左；替代连续留言，不双重展示同一评论 |
| 当前口播 | 快捷栏上方，最多2行，随实际正式播放显示 |
| 风格 | 日光宿舍、浅蓝、植物绿、木色；轻量半透明包装 |
| 禁止回退 | 不恢复“正在看的弹幕”精选卡，不增加固定大侧栏 |
| 播放链路 | 唯一正式人物／人声播放权威；留言层不生成声音或游戏命令 |

画布、人物、字幕、HUD保护范围和配色属于定稿结构。左右换边属于已批准的运行参数，不需要改布局版本。后续若改变基本结构，应更新设计版本和变更记录；常规修复按当前设计继续实施。

## 2. 后台左右控制

入口：现有后台 /admin →“画面与包装”→“统一直播包装”→“MC 弹幕位置”。选项为“右侧”和“左侧”，选择后沿用现有保存和实时同步机制。

| 项目 | 规则 |
|---|---|
| 配置字段 | overlay.mc_chat_side |
| 值 | right / left，默认right；其他输入拒绝 |
| 持久化 | 保存到现有Room配置；旧配置缺少字段时补默认right |
| 同步 | 复用现有Room状态SSE和修订号检查 |
| 移动内容 | 留言标题、普通评论、SC、礼物提示及设计保护框 |
| 固定内容 | 人物始终右下，字幕与游戏画幅固定 |
| 换边过程 | 直接换位，不横穿准星，不镜像文字 |
| 连续性 | 保留当前消息节点、先后顺序、待显示队列及计时，不重新入队／播报 |
| 飘屏时 | 记住所选侧边供连续留言恢复；顶部轨道与运动方向不变，礼物仍随所选侧边 |
| 断线时 | 保留上次有效位置；重连／刷新读取服务端值，不反复跳回默认 |

1920×1080坐标：

| 元素 | 左侧 X/Y/宽/高 | 右侧 X/Y/宽/高 |
|---|---|---|
| 连续留言 | 32 / 136 / 408 / 480 | 1480 / 136 / 408 / 480 |
| 礼物提示 | 32 / 632 / 408 / 56 | 1480 / 632 / 408 / 56 |

两侧均避开本方案的准星、底部快捷栏和顶部Boss条保护范围。游戏菜单、声音字幕和服务器自定义HUD仍需实机验收，导播需要保留收起浮层的能力。

## 3. 唯一布局依据与代码入口

权威布局是[configs/layouts/mc-landscape-v1.json](../../../configs/layouts/mc-landscape-v1.json)。本目录layout-spec.json和layout-spec.js由构建脚本从它生成；不要再维护第二套不同的坐标。

| 文件 | 职责 |
|---|---|
| backend/room/defaults.mjs | 后台字段默认值与left/right枚举校验 |
| web/admin.html、web/admin.js | 后台选项，按字符串提交并保存 |
| web/mc-chat-position.js | 将服务端配置投影到MC留言／礼物位置，不操作消息或媒体 |
| 本目录preview.html、preview.js | 定稿样稿和局部交互；默认离线示例 |
| tests/room-control.test.mjs | 配置拒绝、持久化和旧配置兼容 |
| tests/mc-layout-ui.test.mjs | 真实本地后台API→SSE→样稿位置联动 |

在显式启用room_control=1且与Room API同源的HTTP预览中，样稿读取后台配置，本地左右选择会禁用；离线直接打开时是本地位置演示，不会冒称后台已经保存。当前联动测试使用隔离的本机测试服务，不向生产输出注册新正式播放端。

## 4. 后续实施与验收约束

1. 新人物素材按[制作规范](人物素材重制规范.md)和[动作改编清单](motion-reframe-plan.csv)制作，保留原始人物和旧48手势库。
2. 正式MC输出复用同一位置控制器和权威布局，接入现有Room状态；不依赖本地浏览器存储作为后台权威。
3. 真实平台事件先统一校验、去重、过滤，再分发给留言显示和DSH；未知角色不造舰长／房管，未知金额不猜金额。
4. 圆形／横窗、左右位置、720P、SC／礼物、删评／屏蔽、重连、实际口型、原生HUD和音轨逐项验收。
5. 真机运行遵循既有设备分支、来源收据和发布检查；设计定稿不等于新素材、MC游戏或公开直播已经部署。

当前完成范围：定稿文档、权威布局、左右预设、后台配置入口、位置投影与本地联动验证。新人物视频、完整MC正式媒体输出及B站真实联合运行仍按既有实施路径推进，不改写历史实测结论。
