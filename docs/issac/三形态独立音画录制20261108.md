# 三形态独立音画录制

用户本轮要求 M01 日光陪玩、M02 暖夜陪玩、M03 专注对局各录制 30 秒。只检查人物、身体动作和口型，暂不接入游戏。这一范围覆盖原完整共存启动顺序，允许单独启动音画；与完整游戏接入的验收分开。

R11的NCM01和真实512口型曾并行运行，口型短测约67.91FPS；该生成吞吐不能证明完整同屏持续帧率，也不能据另一负载组合否定人物方案可运行。官方窗口黑屏是独立、未解决的问题。

本轮不启动游戏或DSH，不下载模型，不调用云端。调用已在本机的原生 Windows Python、Chrome 和 FFmpeg；不创建 Docker、WSL 或虚拟环境服务。保留其他项目程序和任务。

入口是 `scripts/run_issac_media_rehearsal.py`。仅启动独立 NCM01 服务和 `http://127.0.0.1:8072/` 人物录制页面。使用既有 OmniVoice FP16、32 步、原合并参考、关闭参考预处理；源录音和参考文本不提交、不上网页、不回传。M01/M02/M03 均使用原 FlashHead Lite 512×512、25FPS、4 步、batch1、model+VAE 编译和 FP32 rope。

本轮沿用 R12 已完成的 BF16 初始化修复，实际运行要另行验证。整套代码、工具、回传和文档完成，人工复核、提交冻结以后才测试；不会启动 R12 原全游戏测试队列。

首次独立启动在模型初始化之前被正常关闭协议拒绝：排练控制器传入了允许目录外的停止请求路径。MEDIA30B 统一生成候选专属、位于 `state/issac-stream/stop-requests/` 的请求文件，并让页面和语音使用相同的原生约束。旧失败记录保留；控制器失败现在返回非零退出码。补充实际停止协议回归后，再次完整提交冻结并运行，不将该失败归因为资源不足。

每段保留 750 张原始顺序身体帧：294 张持柄、294 张完整喝水、162 张再次持柄。身体沿用 R11 已逐文件校验的真实候选，不替换首尾、不倒放、不补造动作帧。候选仍是待审素材，本轮不会伪造生产动作库的批准或 18 项整体验收。

真实口型在页面播放与录制期间生成，队列最多 48 帧，不先渲染整段口型视频再播放。沿用现有 `MouthProjector` 的真实模型口腔、舌头和嘴唇及两颗原始上尖牙约束，原图跟踪不变。原生产调用默认仍要求正式动作库；排练只显式传入原尖牙文件及哈希，不创建正式动作库。

每种形态生成两句新 NCM01 台词，分别放在第 0.72 秒和 24.16 秒之后；长度超出不喝水窗口时拒绝，不截断台词。喝水 11.76～23.52 秒期间保持无语音且不贴嘴。

页面完整绘制 1920×1080 的标题、512 原尺寸人物、形态和字幕，标题沿用“奶妹 · 以撒的结合”。画面为空间聚焦的人物排练页，没有游戏背景；不改正式 MC 同屏版式。正常点击录制按钮后，浏览器把同一个可见节目画布与实际播放的音频一起录成 WebM，再无拼接转码到 MP4。它是浏览器整页节目画布的实时录制，不是官方直播姬录像、桌面全部应用录屏或最终游戏同屏录播。

输出在独立 `outputs/issac/media30/<运行ID>/`。保存 WebM 原片、MP4、每帧真实口型元数据、实时送帧记录和浏览器显示数据。必须检查每段时长、实际收帧/显示、声音、开合嘴和尖牙；未实际审过的项目不标通过。视频回传仅包含生成物和脱敏记录。完成后关闭本次独立 Chrome 页面并正常退出本轮音画进程。
