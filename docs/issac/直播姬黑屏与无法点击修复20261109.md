# 4090 直播姬黑屏与无法点击修复记录

日期：2026-11-09，UTC+8。范围：用户重新安装后的官方直播姬界面修复；没有恢复此前暂停的游戏、人物、模型或录播测试。

## 修复结果

在 RTX4090 原生 Windows 上，官方直播姬 8.13.0.11251 已恢复完整主界面。实际鼠标点击“更多”可以展开菜单，点击“素材”可以打开完整素材选择窗口，按 Esc 可以关闭该窗口。正常退出后，通过已修正的桌面快捷方式重新打开，界面仍正常显示。

桌面和开始菜单的原有启动快捷方式均增加：

```text
--disable-ui-gpu-compositing
```

参数只针对直播姬原生主界面合成。日志同时显示 OBS 的 D3D11 在 NVIDIA RTX4090 上初始化成功；本轮没有更改编码配置，也没有验证实际编码或录制性能。

## 已确认的故障机制

故障时，主程序有响应、控件树正常，但主界面和弹窗无法正确绘制。最上方未绘制的新手引导占用了交互，主窗口在 Windows 层面处于禁用状态，导致肉眼看到黑块且点击主界面没有反应。

通过界面原有的“跳过”按钮结束新手引导后，程序可以进入后续提示，但黑屏仍存在。因此，单纯关闭引导不能修复主界面渲染。

本轮对照如下：

| 启动方式 | 内嵌网页 / 原生主界面 | 实际结果 |
| --- | --- | --- |
| 正常启动，不带渲染参数 | 原生主界面日志为 `UI compositor frame sink: gpu` | 黑块、透明区域，按钮不可正常使用 |
| `--disable-gpu --disable-gpu-compositing --disable-gpu-rasterization --disable-direct-composition` | 网页子进程改用 SwiftShader；原生主界面日志仍为 `gpu` | 黑屏未解决 |
| `--disable-ui-gpu-compositing` | 原生主界面日志变为 `UI compositor frame sink: software`；网页保留默认渲染路径 | 界面完整显示，鼠标交互正常 |

专用开关在当前官方安装文件 `bililive.dll` 中检出；其效果已由启动参数、原生日志、真实屏幕像素和鼠标操作共同核验。没有修改官方二进制。

结论是当前机器上直播姬的原生 UI GPU 合成路径存在兼容问题，切换原生 UI 软件合成可以稳定复现修复效果。不能据此把具体责任归于某个驱动版本或显示设备。此次故障无需通过释放人物模型显存解决。
