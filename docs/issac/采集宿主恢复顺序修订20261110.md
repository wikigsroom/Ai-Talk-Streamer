# 采集宿主恢复顺序修订

CYCLE19在4090通过1220项回归、4项跳过，实机已自动识别开场、正常Space跳过、确认FILE 3高亮并通过原生可写槽3核验。22:33:24原生普通暂停确认完成。随后重启官方采集客户端，22:33:40游戏发生ntdll.dll访问异常0xc0000005；系统事件1000/1001保留。该时间关联说明恢复顺序存在采集钩子切换窗口，但不能仅凭ntdll记录断言唯一底层崩溃原因。

同一实际官方UI读取确认：开始直播同时出现一个ControlType.Button和一个同名ControlType.Text，旧脚本计为两个目标，未执行开播。CYCLE19因此没有通过公开恢复验收，失败原始日志保留。

CYCLE20先关闭旧项目游戏，再完整重载项目栈和官方客户端，等待采集宿主稳定，然后才启动新游戏、附加原生桥接、按实际菜单选择槽3。正式开播前再连续核对存活槽3，避免游戏退出后将黑色游戏源推出去。开播控件只认实际可用按钮，不把按钮子文字算作第二个目标；增加只读InspectOnly供实际UI核验。仍只操作正常开播按钮，不能调用关播。

官方客户端的同路径子进程在父进程退出前记录PID、创建时间、路径和哈希，父子全部退出确认后才通过单实例启动检查。父进程中途退出时只使用绑定同一父身份的已记录子进程清单，不按进程名称杀进程。值守保留有限控件失败诊断以便定位，不将等待按钮和成功开播混为一谈。

恢复期间建立的普通暂停此前经由人工pause入口，导致开播失败后误入operator_paused并不再自动重试。本轮改为仅在全新观察状态允许的recovery_pause，继续保留普通暂停输入和槽位核验，同时不制造人工暂停标记。实际人工pause或原生F8仍阻止重启接管；开播前及恢复自动操作前重新检查接管状态。

本轮整轮完成审阅提交冻结后，统一跑六组回归、实际UI只读检查、完整恢复、公开状态和真实音画/游戏推进验证。没有新增模型、切换音色、清记忆、改游戏值或原存档。此文为实现约束，成功只在实机交付回执中记录。

CYCLE20冻结后六组回归全部通过。末端审查进一步发现：最后启用游玩若仍调用人工live入口，核心准入或原生resume失败也会先留下operator_paused标记。CYCLE21将最后一步纳入同一恢复归属：只允许全新observation_only、未armed、未启用生命周期、无F8接管的恢复入口；仍执行原模型、槽3、新鲜状态和正常resume检查，只有全部成功才启动生命周期。失败保留观察状态让独立值守继续重试，不能伪造人工接管。人工live/pause语义保持原样。新增成功、核心拒绝、人工暂停和F8的边界回归，整轮重新冻结后统一验证，不热改在测候选。

CYCLE21本地冻结后专项检查为49通过、1失败：旧完整恢复测试仍断言人工live动作名称，未同步新恢复入口。该候选没有部署至4090。CYCLE22只同步该断言，并强化“开播前不得恢复游玩”的负例，同时覆盖live、recovery_live和resume三种入口；生产实现保持CYCLE21原字节。失败回执保留，重新提交冻结再验证。

CYCLE22本地50项专项通过，未部署。与此同时CYCLE20第一次实机恢复于22:54:28报OWNED_WINDOW_FOREGROUND_NOT_CONFIRMED，独立进程5秒后已自动开始第二次重启，没有再误停人工接管。该异常来自切回已核验窗口的正常激活调用，未进入游戏文件选择，也未公开开播。CYCLE23增加普通输入队列的临时连接后重试窗口激活，任何成功或异常都释放连接；只还原被核验的最小化目标窗口，不合成Alt、游戏按键、不改系统前台锁定设置。依旧以真实GetForegroundWindow及PID/创建时间核验成功，拒绝将API返回值当作前台已切换。开播前同样先核验官方前台窗口，避免按钮缺少InvokePattern时受同类激活失败阻断。

依据为微软官方的[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)、[AttachThreadInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-attachthreadinput)与[ShowWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)接口说明。接口允许系统拒绝前台切换，因此仍保留失败判定和自动重试，不能承诺每次调用必然成功。

CYCLE24补上系统审查识别的另一处同类卡口：喝水流程原来调用人工pause/resume，动作超时、口型异常、状态核验拒绝或恢复API失败后会留下operator_paused，值守无法区分人工。现使用带控制修订号的natural_pause/natural_resume，仅可从实际playing进入natural_paused，并仅恢复同一自动暂停。人工新暂停、修订号变化和原生F8都阻止自动动作恢复。值守只把真实安全暂停回执、同身份同帧、清房、最新状态、未过期且最长60秒的实际喝水当作健康；证据失效或动作超过时限后按20秒异常预算进入整套恢复，不能无限尊重一份过期自动暂停。保留原节目喝水动作、人格、语音、口型和正常游戏输入，不增加新素材或模型。实际长期结果另记回执。

CYCLE24专项71项通过，完整六组中前五组通过，第六组发现旧节目喝水测试仍断言resume，故未启动公开候选。CYCLE25同步该断言，并补上对全部自动暂停调用审查发现的音画故障卡口：素材/映射/帧输出失败原先也调用人工pause，现使用media_fault请求正常暂停并明确进入restart_required，因为已失败的合成管线在同一进程中不可自愈。暂停回执丢失仍报告pending并请求整套恢复，不能变成假人工暂停；显式人工pause/F8保留优先权。记录暂停确认与未确认的差别，测试覆盖正常回执、回执丢失与人工接管，不把回归日志中的旧配置夹具当作实际模型切换。
