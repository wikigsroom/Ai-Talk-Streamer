# 300秒录播游戏帧率修复轮

用户要求：修复已交付300秒录播中游戏运动卡顿，重新交付。仅适用于 `issac`。保留最新淡黄色角标和 `?!播播!?`、奶妹原核心渠道、NCM01、三形态及已确认的512口型。

## 已确认的旧片问题

首版 `d0055dbb84aa292a22a3b28f19ab6b169fd2f2cca8fd9729cf0fb4ab97021481` 虽为30FPS/9000帧，前50秒游戏区域可见更新平均约18.46次/秒；原生游戏逻辑同期约16.23～22.73次/秒。160～190秒游戏区域约28.33次/秒。动态ROI统计排除人物、角标、字幕；静止或正常暂停不能据此判为掉帧。

对应官方原始录制共9735输出帧，渲染卡顿1帧，编码跳帧1帧。因此已有证据指向游戏侧降速，不支持把容器30FPS或口型25FPS当作游戏流畅验收，也不支持将所有问题归因于编码或显存。原生桥具体开销此前未单独计时。

## 完整代码轮

1. `lua_pcallk` 高频钩子改为进程内TinyCC生成的原生C回调，仍按原来顺序捕获实际Lua状态，但仅在有可信请求时进入JavaScript。保留原有Lua返回/渲染兜底执行路径、请求过期、递归保护和Lua栈恢复。原生钩子计数与进入JavaScript的次数分别报告，避免把常驻C钩子误报成完全无钩子。
2. 菜单键的三个键盘API钩子仅在正常菜单/暂停输入的140毫秒租期内安装，释放后移除本桥自己的钩子。处理连续同键的旧定时器，避免旧释放截断新按键。正常玩法无常驻键盘钩子，不改变桌面前台窗口。
3. 渲染钩子按实际地址去重；增加Windows原生高精度时钟的有界600间隔统计，分别报告实际SwapBuffers来源、频率、P50/P95/最大间隔与样本新鲜度。这里只测游戏提交，不能单独等同最终编码画面的有效更新。
4. 增加只读 `/performance` 观测入口，以便录制期间同时保存游戏原生计时、逻辑推进、节目/口型计数及官方录制统计。没有请求时仍不读取GPU像素。

规则的射击、移动、躲避、拾取授权、wiki和奶妹核心职责保持原约束；本轮不通过降低安全检查频率、提高游戏速度、改数值或人工插帧制造流畅。

## 验证和重新交付

首轮候选 `issac-d51b33b6d157-a50d476c` 的48项Node检查、118项主播Python检查通过；627项游戏回归在仅测试进程直连本机后通过。原生实测发现直接改为SwapBuffers执行Lua的兼容性问题：暂停请求失败，随后游戏退出。该候选不交付，已停止宿主并关闭验收阶段。第二轮恢复原Lua返回安全点，只在有请求时挂钩；补充检查确保渲染事件不会执行Lua、Lua请求完成/失败/无渲染超时后钩子都会释放。

第二轮 `issac-0a647997b556-9b9fdf4b` 的48/118/627项检查通过，但干净游戏在初次控制器安装前没有持续Lua回调，无法完成只靠Lua返回点的引导。已正常关闭自有测试游戏、停止宿主并结束该轮；该候选也不交付。第三轮恢复原有完整执行路径，将高频采样改为原生C实现，避免前两轮对调度路径的改变；新增干净游戏无回调时的引导验证。CModule使用Frida内置TinyCC在进程内编译，不引入虚拟化、外部编译器或新的推理模型。必须在真实4090进程中确认编译、引导、暂停、恢复和游戏FPS，单元模拟不证明原生代码可用。

Frida官方说明高频JavaScript拦截有明显开销，并提供独立listener的释放接口：[JavaScript API](https://frida.re/docs/javascript-api/)。这里以实际候选测量确定收益，不能把移除钩子本身当作通过证明。

第三轮真实同机60秒战斗中，逻辑仍约16.2～23.0次/秒，游戏渲染约35.6～55.3次/秒，说明仅原生化桥接回调并没有解决主要耗时，不能交付为流畅修复。干净启动后过早接入还出现了一次原生进程退出；实际等待游戏完成启动后，接入、控制器安装、普通暂停和恢复均已通过。后续操作入口须先确认游戏已完成原生启动，再接入控制器。

第四轮只增加有界120次更新的Lua阶段计时，分别观察安全状态、状态交换、道具权限、移动避让、瞄准输入；按需读取时才计算统计，不向画面或台词加入诊断内容，不修改任何决策、检查频率、伤害或拾取规则。先用实际战斗数据确定下一完整优化轮，当前不宣称修复通过。

第四轮实际60秒同机战斗定位：移动避让阶段约23～25毫秒/次，完整更新约29～31毫秒/次，期间逻辑约17.4～22.8次/秒，清场末段回到30次/秒；声音与真实口型持续运行，核心无失败。该候选已普通暂停、正常关闭自有游戏并停止宿主、结束验收阶段。

第五轮只复用同一次同步预测中的不变数据：九个方向及原十步预测完整保留，碰撞格子的路径值/中心、身体采样偏移与边界大小在该次预测内复用；下一次预测全部重新读取，不能跨帧或跨房间保留。墙体反弹采样偏移与碰撞值、各候选重复使用的敌人/弹幕原生Vector轨迹也在同步回调内复用。仍调用原生Vector运算，不用不同精度的数学替代。候选安全检查仍逐方向完整执行，危险、拾取和核心权限均不减少。新增原算法基线与原生几何/惯性的路径等价、格子变化失效、零值查询复用检查；嵌套耗时另列，不与父阶段重复累加。
