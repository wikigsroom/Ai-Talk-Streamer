## 4. 素材衔接与当前审看边界

上轮已索引 123 条旧动作候选，并从三种形态各抽取静默、持柄、反应、喝水，共 12 条。每条原始 294 帧完整保留一次，以 25 FPS 播放，24 FPS 原片会快约 4%；没有补帧、端点替换或保留旧声音。已经查看三种形态的端点总览和喝水中段，但**尚未看完所有帧，也没有完成正常速度审看**，所以没有审批动作库。

本轮 `state/issac-materials/generations/<candidate_id>/` 单独存放 candidates、clips、inspection、reviews 和 runtime-bank。审批必须对应当前候选、原片哈希、完整帧图和实际速度；不能将上轮检查图片改标签当作本轮证明。喝水必须形成同形态 G0→G0 的完整链，拿杯到放回全部保留；危险战斗中不随机喝水，切换动作不能残留杯子，持杯时不播报。动作首尾与跨片衔接都要审看。

H3 提供身体动作，不能替代当前音频驱动口型。FlashHead 的实际嘴部开合、声音同步、两颗上尖牙和 25 FPS 必须在三种形态当前运行上重新验收。

## 6. 冻结与统一运行工具

开发完成并提交干净工作树后，使用 `scripts/freeze_issac_candidate.py`。脚本读取 `configs/issac/execution-rounds.json` 的活动库存，要求全部代码项完成、人工整轮源代码检查完成、测试尚未开始。生成完整归档、源清单、SHA256 和独立候选 ID。私有状态、模型、程序和历史 outputs/operations 不进源包。

传输必须使用 ZeroTier `192.168.196.87 ↔ 192.168.196.209` 直连，不走代理。安装器独立校验所有字节和来源；运行中的己方组件/锁未结束时拒绝替换。上代清单中的退休源码先备份、核对哈希，再精确移出；新代安装失败时恢复。未知文件和所有游戏/模型/状态保持保留。切换和回退仍须实测，工具实现不等于回退通过。

| 冻结工具 | 用途 |
|---|---|
| `diagnose_issac.py environment` | 迁移自己的 venv 路径和已有 Torch 共享路径 |
| `diagnose_issac.py dependencies` | 分别检查游戏、媒体、声音的真实导入；不加载模型 |
| `diagnose_issac.py owned-status` | 读取自己的登记身份、进程与资源 |
| `diagnose_issac.py native-game` | 启动自己的游戏侧栈，验证菜单、模块、普通暂停；只正常关闭自己刚启动的 0 玩家菜单；不启用 AUTO |
| `diagnose_issac.py retire-stalled-owner --expected-installation-id …` | 仅用于已经关闭失败测试阶段、游戏已结束、此前已在停止中的己方旧实例；先一致备份数据库，再有限等待，必要时精确退场并如实标记不干净；不能制造通过回执 |
| `run_issac_round.py` | 同一冻结候选统一执行环境、依赖、全量回归和素材索引；可加入原生游戏、模型、官方客户端检查 |
| `integration.issac.materials` | 当前候选全帧素材检查及真实审批 |
| `integration.issac.acceptance` | 门槛证据、长时共载、阶段关闭和完整发布审查 |
| `integration.issac.livehime` | 署名、稳定窗口、实际 profile、受限录制按钮和截图；只允许本地录制 |

统一运行器对每项分别保存日志、退出码、用时与哈希；即使一项失败也继续执行其他可达的独立检查。冻结前后源文件均再次校验。模型/官方客户端没有通过时不会伪造后续 600 秒录制。
