# 以撒GPU规则计算与直播共存

用户要求以GPU方案更新当前issac分支、重新交付300秒官方录屏，并同步奶妹项目与agent-gameplay-isaac仓库。后者明确指 `wikigsroom/agent-gameplay-isaac`，不是新的模型仓库。

## 本轮实现

| 部分 | 实现 | 保持的边界 |
|---|---|---|
| 游戏规则 | 九个移动候选、十步预测中的弹丸与敌人扫掠距离，批量交给CUDA Graph | 仍是确定性距离公式，不加载推理模型、不决定道具、不注入游戏数值 |
| 计算服务 | 4090现有64位PyTorch环境；16/64/256轨迹预分配桶，启动时预热；FP64距离公式 | 不下载依赖或权重；与NCM01、FlashHead、官方录制同时实测后报告结果 |
| 32/64位互通 | 已有LuaSocket，持久127.0.0.1二进制TCP连接；一帧一批 | 无需新增32位CUDA DLL；没有HTTP逐实体调用；选择TCP而非新增共享内存插件，复用当前已核验的原生模块 |
| 帧隔离 | 32字节头，包含请求序号、帧、局种子、房间、层、轨迹数、预测长度；回复逐字节匹配 | 过期回复、错误长度、NaN、异常无穷、越界输入不能驱动当前帧 |
| 超时回退 | 默认总预算8毫秒，错误关闭连接并冷却1秒；容量超过256保持完整CPU计算 | 不减少威胁、不复用上一帧、不去掉安全检查；回退和实际GPU命中单独统计 |
| 原生精度 | GPU采用双精度；距离碰撞半径0.25像素以内用原生Vector原式重算 | 原生float32与双精度的微小误差不能跨越近边界；固定地刺、TNT、激光、反弹、末端安全复核保留 |
| 存档检查 | 遍历中先筛选存档/配置候选，再做文件元数据和路径解析 | 原始保护文件及备份仍逐次哈希；新槽1/2、未知sav/ini仍立即拒绝；不改变检查频率或重新建立基线 |
| 启停 | Application拥有GPU子进程与两个独立端口；服务预热后才启动控制器；确认游戏普通暂停后停止自己的服务 | 现有任务、用户进程、Steam及槽1/2不受影响 |

完整需求仍以 `最终总需求冻结20261109.md`、用户后续明确指令为准。奶妹的唯一核心仍为原渠道gpt-6-luna/Responses；DSH、七扩展和离线issac-wiki不变。NCM01/OmniVoice、M01/M02/M03、FlashHead Lite 512×512/有效25FPS、4步/batch1以及角色细节保持冻结。节目沿用MC rev04及用户最后角标要求。

## 验证与证据要求

整轮先审阅、提交、冻结，然后统一运行回归。先验证GPU协议及独立标量距离对照，再检查实际游戏回调GPU命中、Lua分项、原生渲染间隔、Python处理、保护检查耗时、声音与口型共存，以及官方录制的实际掉帧/编码统计。合成计算测试不冒充实际战斗提速；CPU采样、渲染刷新和视频独立画面更新率分别报告。

交付片必须来自官方直播姬连续本地录制，1920×1080/30FPS、至少300秒、含真实游戏和奶妹可闻解说。可以连续裁切起止，不能补音轨、补帧或加速游戏来制造达标。私有声音输入及原转录不得提交或交付。无公开开播。

## 双仓同步

| 仓库 | 分支/范围 | 不同步内容 |
|---|---|---|
| wikigsroom/Ai-Talk-Streamer | issac；Application集成、配置、规则副本、保护扫描优化、测试、方案与脱敏证据 | 私有配置、凭据、声音参考、存档、模型、运行时与大体积测试垃圾 |
