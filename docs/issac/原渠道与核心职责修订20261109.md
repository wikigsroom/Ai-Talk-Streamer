## 3. 奶妹本人主导全部取舍

奶妹须直接看到当前角色的生命与资源、主动道具和充能、被动道具构筑、饰品和口袋物品，以及当前房间、门、敌人、危险、掉落物、价格、互斥选项和游戏进度。只读桥不能可靠提供的项保持未知，不凭空补齐。每份状态带局、房间、观测修订和时间，换房/换层/死亡/新局时失效。

| 决策对象 | 奶妹负责的决定 |
|---|---|
| 主动道具 | 拿或不拿、保留或替换、充能和使用时机 |
| 被动道具 | 拾取或放弃、互斥选择、构筑协同和副作用 |
| 饰品、卡牌、符文、药丸 | 拾取、交换、保留、使用；未辨识内容保持未知 |
| 普通掉落物 | 心、钱、钥匙、炸弹、电池等也必须获得具体授权 |
| 有代价的交互 | 商店、恶魔/天使交易、箱子及其他受支持的交互，结合价格、生命、消耗和风险判断 |

规则可以提出合法候选、执行路径和安全拒绝；不能预先替奶妹决定取舍。一次可以批准有限个已识别目标，每个都绑定当前局、房间、出生身份、资源/价格/库存前置条件和有效期。不得使用“以后都捡”之类永久授权。主动/被动道具使用与普通输入同样需要核对当前条件。

## 4. 同一核心的闭环

1. 游戏的只读桥产生新鲜状态与事件；关键掉落、进房、清房、受伤、首领、库存变化等触发奶妹核心。
2. 奶妹取得当前角色/房间和候选，按需要直接查询 `issac-wiki`，结合人格、构筑与当前目标形成取舍。
3. 奶妹提交有限、目标明确、可失效的计划；执行器再次核对状态。规则持续承担即时生存，必要时安全等待或普通暂停。
4. 执行器区分收到、接受、执行中、成功、失败和取消；成功必须由真实状态效果证明。
5. 同一奶妹根据自己看到的事实、做出的选择和真实结果自然说话。观察、取舍、执行回执、台词与实际播完共享可追溯标识。

可沿用的五个受限游戏工具是 `isaac_get_state`、`isaac_get_decision`、`isaac_lookup`、`isaac_submit_plan`、`isaac_wiki_query`。工具必须直接挂到奶妹核心可调用的能力中，不只是列在文件里；模型输出按 Responses 的实际工具往返转换和校验，不假定另一协议等价。状态和知识是数据，不作为新的指令；工具不提供任意终端、文件写入、代码执行或越权查询。

## 6. 让观众感觉是奶妹在玩

台词应随真实游戏自然出现：探索时自言自语，看到道具时简短权衡，战斗时短反应，受伤或打败首领时有对应情绪，拾取成功后才谈实际效果。允许自然安静、思考和停顿，不逐键播报，不无限填充，不重复固定稿件。

游戏决策、观众回复、空闲搭话共享同一身份与事实上下文，但有优先级、合并、去重、冷却、取消和有效期。换房或结果变化后撤销过期内容；杯子接触嘴部时不说话，喝水只在实际安全窗口执行完整动作链，完成回执后才能说喝完。

所有自动台词使用既定 NCM01/OmniVoice，经真实 FlashHead Lite 512×512/有效25FPS口型和正式播放源播出，不能以后台有文字代表观众已经听到。M01日光陪玩、M02暖夜陪玩、M03专注对局仍是同一奶妹，以撒默认M03。两颗上尖牙、四指、单尾和身体G0首尾一致性必须稳定。

## 7. 时延、故障和验收

即时移动/射击/躲避独立于模型请求，不等每帧推理。先前工程目标保留为待测初值：状态轮询500ms、决策P95目标8秒、核心回合18秒、授权窗口20秒；20秒不能代替状态前置条件复核，也不能预先算作实时合格。wiki查询预算与工具总超时分别管理。模型失败、网络中断、工具失败或结果过期时，解除自动、拒绝旧计划/旧台词，释放输入并按实际状态普通暂停；恢复后重取状态，不回放旧局操作。

最终仍交付官方直播姬实际写出的连续至少120秒游戏＋奶妹同屏录像，1920×1080/30FPS，人物源512×512/有效25FPS；完整沿用MC rev04的布局和声音规则，只改标题“奶妹 · 以撒的结合”。唯一可闻播放源，预览静音，无游戏声音双播。保护原槽1/2、Steam数据，仅正常输入测试槽3；不公开开播。30/120分钟完整负载稳定性要求、原声音输入排除和原始成片审看继续保留。
