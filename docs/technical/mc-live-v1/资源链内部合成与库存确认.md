## 1. 核心业务变化

此前公开craft已使用服务器库存确认，但资源采集树中的CraftInInventoryTask和CraftInTableTask仍会转入旧的搬槽、配方书和输出领取路径。两处现在保留原材料采集逻辑，共用ControlledResourceCraftTask，再交给ConfirmedCraftTask执行实际2×2或3×3合成。原背包任务子类覆写的collectRecipeSubTask也通过工厂保留，不统一替换成默认采集器。

内部RecipeTarget表示目标总库存；公开craft的count仍表示新增数量。内部只制作实际缺口，按服务器配方的单批产量向上取整；已有成品不能再被重复算成新增目标。执行沿原Session、世界、玩家、网络连接和任务期限，不创建另一个公开任务或输入许可。

## 3. 工作台准备与实际库存

3×3需要先沿原任务寻找、制作、放置并打开工作台。工作台本身可能消耗木板，因此打开之后重新读取实际库存和服务器配方，再产生最终分配；原分配不能跨工作台准备而被假定仍有效。若实际材料不足，回到原采集逻辑。

进入每批ConfirmedCraftTask时，只检查尚需使用的已分配槽位：组件必须与原分配相同，数量至少覆盖剩余额度。无关槽位在原任务内因进食或准备工作台发生变化，不再触发整背包逐字相同的误拒绝。开始点击后，仍对整个handler、全部槽位和光标进行每步完整服务器同步核对；这不放宽点击确认。

该分配只属于当前合成步骤，**不等于完整资源链的跨任务材料预留**。采集、进食、工具、防御与建造之间的全局材料预算、依赖去重和资源优先级继续属于D04。

## 4. 父任务、确认与余料回收

客户端点击会立即预测成品进入背包。父ResourceTask如果据此提前结束，余料和光标可能尚未由服务器确认。当前Task.tick和SingleTaskChain保持通向正在执行的ConfirmedCraftTask的原有子任务路径；等待期间不重新运行祖先的资源选择，也不依据预测成品宣布根任务结束。

驱动在上游任务前检查原合成确认期限。FoodChain在活跃合成事务期间不抢占GUI；其他紧急避险仍保留原调度资格。Task.canBeInterrupted同时修正为检查任意后代的强制执行要求，普通祖先不能把后代的强制要求覆盖掉。人工接管、断线及根许可撤销仍直接撤销原Session，不受这条任务调度规则阻止。

每批依次确认材料搬入、实际产物、材料消耗、产物存回及全部余料回收。只有服务器已确认空光标、空材料格，并成功关闭原任务拥有的窗口后，最后一批才设置finished。其他批次也关闭后重新获取窗口租约，原15秒绝对窗口期限不延长；每次点击仍限1500ms。

原背包/工作台包装任务的开始和停止不再整理或丢弃未知光标。撤权清理只忘记原绑定，不发旧点击、关窗或库存回滚；已发生的部分效果继续保留。其他容器、其他上游原始写点与迟到包归属没有因此全部解决。
