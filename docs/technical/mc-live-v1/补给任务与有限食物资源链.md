## 1. 补给进入原公开任务

上游FoodChain的采食选择接到`ControlledSupplyTask.select`，子任务仍使用实际`CollectFoodTask`和其已有拾取、采收、材料及转换树。它不创建第六种公开goal，不请求另一份Permit，不等待模型。普通导航、采集、合成任务的内部补给仍属于原任务、原世界和原输入代次。

同一所有者未结束的补给保持原目标、原起点及原计时。每次上游选择、任务中断/重置不会新建预算；配置在途中改变也不修改已接受的目标。所属根关闭时仅移除自己的引用。后续补给必须是旧补给已经真正结束后的新遭遇，仍受原公开任务总预算约束。

实际驱动每tick在进入上游调度前检查防御和补给。因此防御、火焰或其他紧急链临时抢占时，补给期限继续推进。撤权时现有仲裁器先拒绝旧根，旧补给不借新AUTO或新世界继续运行。

| 有效配置 | 采食目标为1–256整数营养单位，下限为1至目标；矛盾、非法或非有限值固定失败 |
| 数量语义 | 实际安全食物总营养，不是额外再采同样数量；已有库存计入 |
| 同次补给总时长 | 120秒，原计时不因重选或中断延长 |
| 没有库存进展 | 45秒；只有实际安全食物总营养超过先前最高值才更新窗口 |
| 原起点搜索范围 | 96格；越界不能因同时取得食物变成完成 |
| 已超总期限的迟到库存 | 不追认成功；保留本次超时结果 |

移动、转向、重复读数、丢弃后拾回原数量，以及进食后再补回原数量不刷新库存进展。它们仍可能是任务真实行为，但不能构成无限续期的证据。计时使用单调时钟。

这些默认阈值仍需在真实难度、地形、延迟和补给节奏下联验。当前策略没有把生肉、干草或小麦的“转换后潜力”当成已持有的可食库存。

## 3. 实际食物组件与手持复查

库存计数和FoodChain选食使用实际ItemStack的`FOOD`组件。读取实际营养、食用时长、饱和度及效果概率，拒绝无有效食物组件、异常数值、有概率产生非有益效果的食物；紫颂果及带迷之炖菜效果组件的物品不进入这条自动选食路径。原上游对受保护物品的排除保留。补给准入与补给结束共用实际库存营养口径，选食评分继续排除受保护物品；不因选食评分为零而反复抢占已经有足够食物的原任务。

FoodChain计算选食评分与总营养时也使用当前堆栈组件，避免仅按Registry物品默认值计数。原上游装备操作之后、持续按住使用键之前再次检查实际主手；装备到不允许的组件时停止该次进食尝试。此检查不代替完整装备事务、库存同步和食用效果确认。

库存营养计数只描述物品性质和数量；是否能自动消耗仍受原物品保护及当前规则限制。它不把受保护的任务材料变成可随意食用的物品，完整的预留材料/补给规划和冲突恢复仍须实现并联验。

补给完成按真实玩家库存中的安全食物计算，不把游标槽、容器中的预期输出、尚未加工的材料或上游子任务的结束回调作为食物到手证明。已结束的补给在FoodChain计算下一次食物状态前停止并清掉其任务引用，使子树的物品保护按现有停止流程释放，让原资源任务恢复。

## 4. 干草、小麦和面包的有限转换

上游两处`99999999`目标已改成与原采食目标对应的有限总量：面包目标为`ceil(目标营养/5)`，小麦目标为面包目标乘3。40单位对应最多8个面包和24个小麦；256单位上限对应52个面包、156个小麦。这里是限定配方的总目标，已有对应物品由上游任务计入。

转换只产生执行计划，最终是否拿到足够食物仍由后续实际库存决定。原采食树的生食转熟食路径、烟熏炉/燃料/容器、数据包配方和特殊组件尚未闭合；不能凭材料潜力、进入转换分支或创建任务宣称完整补给成功。完整资源链仍须关闭各类GUI/副作用与真实效果约束。
