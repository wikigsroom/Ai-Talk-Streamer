# 采集、合成数量与材料分配

本说明落实[游戏桥协议](02-游戏桥与控制协议.md)中原有的数量要求。第015轮把gather.count写成目标库存总量，与既定协议不符；第016轮纠正代码和当前说明，保留旧轮证据作为历史记录。统一交付范围、布局和68项真实验收保持不变。

第019轮已将这里的分配接入公开craft的专用点击、实际组件和剩余物、服务器同步与后置核验，详见[合成事务与服务器同步核验](合成事务与服务器同步核验.md)。下文第016轮的ItemTarget映射和暂不开放说明保留为历史实现记录，当前公开craft改用ConfirmedCraftTask；不表示特殊配方或真实MC验收已完成。

## 1. 外部任务与内部执行目标

| 字段/事实 | 确切含义 | 例子 |
|---|---|---|
| gather.count | 相对受理后执行开始观测的目标新增数量 | 已有3根原木，要求4，执行器目标总量为7 |
| craft.count | 目标新增产物单位数，按配方批量向上取整 | 已有3块木板，要求新增5，每批4，需2批、计划新增8、目标总量11 |
| 世界目标inventory_at_least | 后台世界目标的独立库存条件，表示至少持有总数 | 至少持有4与额外采集4是不同要求 |

[InventoryTarget](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/InventoryTarget.java)将基线、请求增量和配方每批产量固定为不可变对象。对外Task.goal、DSH参数、观众建议、幂等hash和B账本仍保存原请求增量；只有本地TaskCatalogue/RecipeTarget接收换算后的targetTotal。已有库存再多也不能把新增任务判为已完成。请求增量仍为1–4096；内部目标可大于4096，但不得溢出32位计数。

实际连接是ExecutorTaskSession捕获观测基线，经SurvivalGameExecutor和ControlledAltoClefDriver传给ControlledTaskFactory。工厂在创建采集任务前重新汇总当前玩家库存；与捕获基线不一致则返回GAME_INVENTORY_BASELINE_CHANGED，避免把起始库存变化静默算入新任务。此处没有改写网络Task.goal，也没有把旧任务改成新数量重发。

## 2. 后置核验

执行器完成清理后，仍须等待更晚且同一安装、启动、世界、会话和控制epoch的观测。采集核验用实际after−before与请求增量比较：达到为succeeded/verified；有增加但不足为failed/partial；未增加或减少为failed/unknown。起始3、最终4、要求额外4时，结果只能是partial。

库存证据写明起始总量、结束总量、实际净增量和请求增量。它不能确定资源来自哪个方块或哪次掉落，不得据此口播“已挖掉指定方块”。完整游戏效果关联、服务器同步、资源链及实机验证仍须完成。普通库存增加继续不能充当craft_result。

## 3. 合成任务准备

[CraftPlan](../../../game-adapters/minecraft/survival/src/main/java/dev/aitalkstreamer/mc/survival/CraftPlan.java)已接入实际[ControlledTaskFactory](../../../game-adapters/minecraft/survival/src/main/java/dev/aitalkstreamer/mc/survival/ControlledTaskFactory.java)的craft准备路径：

1. 重新读取当前服务器RecipeManager。无配方返回不可用；多配方返回歧义，不能按字母序或当前材料猜选。
2. 保留形状配方的空槽、宽高与2×2/3×3坐标；无序配方按实际非空槽数选择网格。
3. 计算需要的新产物批数，将已有产物与完整批量相加后传入RecipeTarget，避免已有产物导致少做或空做。
4. 从玩家主背包36格复制实际ItemStack，逐个使用当前Ingredient.test匹配，形成每个配方槽与库存格的可用关系。装备、副手、容器、光标和合成输出不作为材料池。
5. 使用有容量的二分图分配材料。每个非空配方槽需批数个单位，同一库存单位只能分配一次；可重新分配宽泛材料槽，给受限槽保留稀缺材料。材料不足则在创建合成任务前拒绝。
6. 准备结果保存具体材料分配、配方ID、网格和数量目标，创建专门的CraftInInventoryTask或CraftInTableTask；关闭这两个任务的自动收集材料选项。

该分配是执行前的必要条件，不表示上游已经严格按分配搬运。上游ItemTarget主要按物品ID匹配，不能完整表达组件条件；当前遇到带额外组件的输入候选/产物显式拒绝，完整组件语义、动态输出、剩余物、多配方选择、解锁与服务器规则仍列入必须实现范围。默认组件相同也不能证明模组配方全部受支持。

后续仍须将不可变分配绑定到实际GUI、槽位搬运与任务树，核对每批服务器结果和实际产量，并解决配方重载、材料变化及停止收尾。候选端口仍只声明navigate/gather，craft完整绑定尚未开放；preLaunch仍无条件拒绝启动。
