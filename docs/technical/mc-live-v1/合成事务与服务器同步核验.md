# 合成事务、材料搬运与服务器同步核验

047将同一确认流程接入[资源链内部2×2/3×3合成](资源链内部合成与库存确认.md)，保留原材料采集并修正父任务依据预测库存提前结束的问题。下文公开craft仍表示新增数量，内部RecipeTarget则表示总库存。

第019轮接通同玩家公开craft的候选实现，仍属于[单一完整交付](08-完整交付规划.md)内部工程进展。源码编译、固定Minecraft类字节码及协议夹具不代替真实客户端、Mixin与服务器验收。完整生存候选的preLaunch继续无条件拒绝，未安装或启动游戏。

## 1. 原请求与实际执行

外部goal继续使用`craft(item_id, count)`，count表示新增产物单位。`ExecutorTaskSession`固定开始观测的库存基线，`CraftSpec`在前置检查和实际创建任务时分别读取当前RecipeManager、Ingredient及玩家主背包36格；实际创建还必须与原基线一致。多配方保持歧义，不按排序猜选。

公开craft现在使用`ConfirmedCraftTask`，不再把材料分配转换成只匹配Item的上游ItemTarget。`CraftPlan`的每项ingredientIndex、inventorySlot和count用于实际搬运；各批只能消费该项剩余额度。源物品同时核对当前Ingredient.test和原ItemStack的物品及组件，数量、堆叠上限也参与操作预测。组件标识是本任务内对完整ItemStack副本的精确等价分组，不是物品ID或面向模型的摘要。

2×2通过本任务打开的背包；公开3×3复用受控的工作台寻找/打开子任务。047起，进入实际搬运时只核对尚需使用的分配槽位：物品组件与原分配一致，数量足够；无关库存变化不再误拒绝。公开craft不静默重分配，原材料发生变化仍停止。资源树内部先准备工作台，再重新读取实际材料与服务器配方，缺料返回原采集逻辑。完整材料预留、特殊配方与资源链仍须继续实现和实机核验。

## 2. 有界点击事务

| 操作 | 实际约束 |
|---|---|
| 搬入一个材料单位 | 左键拿起原堆、右键放一单位到指定空材料格、余量放回原格；原堆只有一个时省略回放 |
| 同一时间 | 最多一条等待服务器同步的点击，不允许并发点击、配方书自动填充、其他上游开关窗或换料 |
| 每次点击前 | 同一根任务/Permit、线程、世界、玩家、连接、具体handler、syncId及完整前态匹配 |
| 每次点击后 | 等待全量服务器容器状态，材料格、主背包、其他槽位和光标均须符合预测 |
| 期限 | 每次1500ms，超时或分歧即终止；不重发原操作，不放宽任务或GUI租约 |
| 存储 | 只使用玩家主背包中兼容组件的容量或空格；不丢地上、不换成其他组件制造空间 |
| 批次之间 | 服务器已确认光标与材料格清空后，关闭并重新打开GUI；原GUI的15秒绝对期限不续期 |

普通客户端点击含本地预测，服务器正确执行时未必逐次返回所有修改槽位。专用点击通过`CraftClickMixin`只将本次`ClickSlotC2SPacket`的revision改成-1，其余槽位、按钮、动作和预测内容仍由原生交互管理器生成，且实际调用保持在原逐次许可内。固定1.21.1的`ServerPlayNetworkHandler.onClickSlot`先执行槽位操作，revision不匹配再调用`updateToClient`返回完整状态；正常ScreenHandler revision为15位非负数。

这条行为已对本地锁定的真实Minecraft类做字节码核对；[点击包接口](https://maven.fabricmc.net/docs/yarn-1.21.1%2Bbuild.3/net/minecraft/network/packet/c2s/play/ClickSlotC2SPacket.html)与[全量同步包接口](https://maven.fabricmc.net/docs/yarn-1.21.1%2Bbuild.3/net/minecraft/network/packet/s2c/play/InventoryS2CPacket.html)提供对应字段定义。真实Mixin应用、实际原版/模组/插件服务器是否保留该同步行为仍须逐项验收。不支持时停止，不退化为仅凭客户端预测宣布成功。

## 3. 每批产物、组件与剩余物

材料填好且服务器已同步后，再以实际网格构造CraftingRecipeInput，重新核对当前配方对象和matches，调用当前配方的craft计算实际产物。产物物品ID和每批数量必须满足固定目标；服务器输出槽还必须与计算产物的组件和数量完全一致。

剩余物使用当前配方getRemainder结果，并按createPositioned返回的裁紧网格及left/top映射回原网格，保留空槽位置、桶等剩余物的实际组件。取出产物前，先预测产物及全部剩余物回收所需的背包空间；空间不足时不点击输出槽。

输出槽单次取出后，服务器同步必须同时吻合：实际光标产物、每格材料消耗、每格剩余物和其他未改槽位。只有这一种已确认步骤增加本任务的confirmedBatches；普通库存增加、材料搬运或输出预览不计作制作数。随后产物和剩余物逐次放回主背包，每步也等待同步。全部批次和收尾完成后才结束驱动。

当前覆盖已接收、无歧义的ShapedRecipe和ShapelessRecipe，并按实际craft结果处理其组件及剩余物。无法由静态产物找到的特殊配方、每批产量变化、完整多配方消歧、配方解锁/规则投影和模组特殊槽位仍属于未完成范围，不将这些配方伪装成普通配方。

## 4. 结果、取消和迟到同步

`CraftReceipt`固定task_id、world_session_id、epoch、配方、物品、起始量、原请求量、每批产量、计划与已确认批数、最后服务器revision及干净结束标志。自然结束先关闭自有空光标GUI，再保存完整收据。原生会话还等待更晚的同上下文观测：必须有匹配的完整收据，且库存净增不少于实际确认产量，才返回succeeded/verified和craft_result。按每批4制作新增5时必须核对2批新增8，不能只用新增5的下界冒充完整结果。

取消、接管、断线、配方变化、空间问题或执行器失败时，不撤销已发生的游戏效果；已有确认批次写入partial证据。撤权后不再发点击或关窗，光标与网格留给操作员处理。旧任务关闭会清除其事务和待确认状态，回调还核对原所有者、连接、世界、玩家、handler和syncId，不能临时获取新任务的写权限。

原版全量状态包没有本项目task_id或nonce。这里的craft_result表示在唯一待确认操作和上述上下文内核对过的服务器状态变化，不是服务器签名的语义回执。重连、取消后同一背包handler/syncId复用、延迟包、服务器主动改库存及插件异常仍需真实故障用例证明；不能仅凭对象检查宣称所有跨任务迟到包已消歧。这是D03/D04/D14保留的门槛。
