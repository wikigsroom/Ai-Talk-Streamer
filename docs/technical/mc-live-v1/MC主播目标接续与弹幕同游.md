# MC主播目标接续与弹幕同游

第069轮，mc分支。对应完整方案D02/D04/D05/D06/D07；属于完整系统的实现内容，最终交付范围不变。

## 1. 已实现的玩法业务

导播在现有世界目标编辑器登记最多16个明确步骤，保存草稿并在当前世界复核批准。开启游戏规划、明确AUTO并获得有效控制租约后，规划器优先读取已批准目标的下一步，直接调用现有固定技能工具。每一步不再依赖一次新的模型生成。

例如“采集木材→合成木板”，先向同玩家游戏桥发出check_action查询；条件允许后，把原目标编号、步骤和批准修订绑定进任务事务，再向游戏桥发送一次任务。gather.count仍表示额外采集量，craft.count仍表示新增产物量；完成条件是独立核验项，不能混同为当前库存目标或合成配方。

游戏桥的受理、运行、完成和效果证据分别记录。任务成功且效果verified之后，仍等待新鲜、字段已知的后续观察满足步骤条件，才完成该步并接续下一步。真实观测本来就满足条件时，可记录观测完成，不能伪称执行过任务。

正在运行或等待观测的步骤不会触发替代任务，也不会让模型跳过该步骤。失败、部分效果和未知结果保留原账本与阻挡，需要既有复核流程处理。查询不允许时不发送动作，保持原目标待处理，按已有最小间隔再核验。

## 2. 授权与取消

GameTools在异步游戏查询前固定world_goal_ref；查询后再次核对同一目标、步骤和修订，TaskService在写入事务中继续核对。查询期间库存已满足条件、目标修订变化或批准撤回，旧结果不能变成未关联的额外动作。此约束也覆盖原有模型game_start_task入口。

沿用游戏启用、规划启用、人格就绪、AUTO、控制租约、快照年龄、同世界/boot/控制代数、能力及技能开关。人工接管、世界变化、停用规划或宿主退出会取消等待中的查询；迟到肯定结果不再执行。批准目标不授予AUTO，不修改生存执行器preLaunch。

没有已批准活动目标时保留原模型自主规划及观众建议路径。目标全部完成后仍由既有规划开关决定后续自主行为，不隐式关闭AUTO。

## 3. 边玩边聊

固定步骤执行不占用文字模型。公开回应继续由同一个DSH/Humanity宿主、只读游戏工具和既有口播队列处理，可以读取当前库存和任务状态。普通问答、礼物/SC及任务反馈仍遵循现有调度；语音生成、媒体提交和实际正式播放分别记录。

回答弹幕不会取消已受理的有效游戏任务，也不会赋予弹幕写游戏权限。只有正式播放器的有效PCM收据才能标记已回答。任务运行不等于完成，答完一句话也不代表游戏步骤成功。
