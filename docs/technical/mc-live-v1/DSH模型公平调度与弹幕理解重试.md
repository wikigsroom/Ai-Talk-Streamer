# DSH模型公平调度与弹幕理解重试

066补充现有单模型调用调度，使持续口播期间游戏规划和观众动作理解仍能获得调用机会。本说明落实[全端实现蓝图](09-全端实现蓝图.md)与[完整方案实施总纲](13-完整方案实施总纲.md)，不修改冻结布局、用途权限、自动输入门禁或单次模型预算。

## 1. 调度约束

| 编号 | 规则 | 实现与边界 |
|---|---|---|
| MQ01 | 全局一个模型所有者 | speech、game_plan、audience_intent、operator_private、maintenance共用ModelQueue。上一调用的实际SDK结束和dispose完成后，才启动下一调用 |
| MQ02 | 有界等待 | 最多32个排队请求，另有1个运行请求；超过后返回可重试的MODEL_QUEUE_FULL。已取消或溢出的口播不抢占、不计入已开始的口播次数 |
| MQ03 | 普通口播与后台机会 | 普通口播优先；累计开始两次口播，或最早后台请求排队达到3000ms，给予该后台请求一次受保护机会。后台之间按入队先后取最早请求 |
| MQ04 | 不在重试时清空公平计数 | 未受保护的规划或理解被口播抢占后，保留口播累计次数。后台仅仅开始不算完成，避免“每来一条就打断新规划”持续重复 |
| MQ05 | 紧急游戏事件 | 由服务端已有播报条目、原始游戏事件、当前世界、正式回应代次、启用状态与时效共同复核。有效critical游戏事件可打断受保护的规划/理解；普通观众文字、付费身份或自称紧急不授予此权限 |
| MQ06 | 临近执行再次复核 | 紧急判定通过函数在入队抢占和选择执行时重新读取当前有效来源。撤回、上下文变化、来源失效或过期即失去优先权；关闭critical_interrupt也关闭这种越过保护的能力 |
| MQ07 | 私聊与维护 | 继续使用原有取消权限；普通或紧急公开口播不新增对私聊、维护运行请求的自动抢占 |
| MQ08 | 取消必须释放实际所有者 | 等待中的取消立即移出队列；运行中的取消发出信号后仍等待实际finally。非合作调用迟到返回的文本作废，不并发开新调用，不把信号当作完成 |
| MQ09 | 保持原始期限 | 游戏规划原有deadline、世界/控制代次和技能门禁继续生效。保护机会不延长deadline，不保证模型完成任务；等待期限内仍可能正常超时 |

“3000ms”表示在前一个调用结束、选择下一个调用时具备优先机会，并非无条件的三秒响应承诺。正在执行且不合作的模型调用、现有单次超时、紧急游戏事件和调用者主动取消，都会影响等待时间。普通口播在保护期间可能等候到该后台请求结束或原期限取消；真实模型、平台和整场延迟仍需实机测量。

## 2. 弹幕理解的重试

普通口播抢占规划/理解返回有限错误MODEL_PREEMPTED，与观众撤回、工具SDK取消、管理员停止和宿主关闭的MODEL_CANCELLED区分。SDK清理失败保留失败结果，不能伪装成可重试的正常让出。

AudienceIntents只对MODEL_PREEMPTED和MODEL_QUEUE_FULL重新排队。重新排队前再次校验原弹幕仍可见、文本摘要未变、原直播间/世界/bridge仍一致、状态新鲜、隐私未锁定，以及原候选尚未过期。重排保留原编号、来源、created_at、expires_at，沿用首次模型尝试建立的单调时钟期限和最小调用间隔；后续尝试只使用剩余预算。即使模型暂时不就绪，sweep也会结束已经耗尽预算的候选。

隐藏/撤回、世界变化、关闭功能、主动取消及原期限耗尽不会重排。重启取消尚未处理的理解，不恢复旧输入。重排没有产生游戏任务、长期记忆、媒体或“已回答”回执；最终结构化结果仍只进入既有待审核建议，沿用人工审批、AUTO、租约和执行器门禁。已经被执行器接收的游戏任务继续沿用原任务核对，模型被抢占不会把已接收任务改写成失败或成功。

## 3. 关闭与故障

沿用[关闭与隐私重建屏障](DSH关闭与隐私重建屏障.md)：停止准入后取消队列和当前调用，等待实际模型/SDK清理，再刷新和释放Humanity连接器。排队中的理解在执行前再次检查临时会话清理失败标记；前一临时会话清理失败后不启动新的理解会话。关闭超时仍保留写入者供核查、重试，不宣告完整应用已经释放。

## 4. 验证范围

检查包含生产DshHost/ModelQueue的受控SDK边界、实际游戏协议夹具、SQLite来源与建议、正式回应路由，以及既有原生DSH/Humanity连接本地脚本式模型接口的三场检查。原生检查分别验证：保护规划等待普通口播并被有效紧急口播抢占；理解取消后dispose及临时会话清理先于下一口播；排队期限取消与保护调用的宿主关闭。该接口返回固定协议内容，没有真实模型推理。

本轮数字和当前源码对应关系见[066执行证据](../../evidence/mc-runtime-round-066.json)及[实现进度](实现进度.md)。修改过程中的旧断言失败与测试日志输出编码失败一并保留，不用后续通过覆盖原失败。冻结的横屏设计和生产状态没有因此变更。

这些检查不构成真实MC生存/PvE、实际模型公平性与延迟、B站接入、官方播放回执、整场资源压力或最终交付验收。完整跨端公平预算、真实工具/模型取消、Neuro式节目能力和D01–D15全部剩余范围继续保留；最终实机验收仍0/68，新人物仍0/100。
