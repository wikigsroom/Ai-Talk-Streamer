## 1. 唯一口播链路

`backend/game/narration.mjs`维护公开回应候选，继续使用现有StreamState、DSH `speech`用途、人物/TTS、媒体取消屏障及正式PCM回执；没有增加第二个人格、推理宿主或发声队列。游戏规划与即时游戏执行仍各自遵守既定权限和控制时钟。

候选来源为当前B站房间的留言问题、礼物、真实任务终态、已采纳/拒绝建议、已结束/取消投票以及important/critical游戏事件。任务accepted/running不生成任务结果候选；成功、失败、取消及partial/unknown效果从任务事实读取，不能因任务受理而宣布完成。当前仍只支持既有固定格式建议，自由语言映射和平台完整字段生命周期保留为待办。

平台事件先经现有持久去重与Room过滤。MC启用时，B站问题/礼物交给该候选队列，平台记录为MC_NARRATION，避免再次走旧自动回复入口；其他平台及未启用MC时沿用原路径。平台显示、候选入队、DSH生成、TTS提交和已回答分别记账。礼物名称/数量来自原始Room记录，不能从平台队列中缺失的字段、昵称或文本推造金额和身份。

## 2. 数据与有界调度

候选保存在当前设备GameStore的schema3通用`objects`集合，kind为narration，无新数据库表迁移。ID绑定broadcast、world_session、来源类型和来源ID；包含revision、来源事件、房间/世界、组别、状态、创建/原始过期时间、请求历史、尝试次数及终止原因。不复制留言全文到候选；后台预览从仍可用的来源读取。

最多16条未终结候选，历史保留不超过512条最近记录。紧急事件8秒，其他候选30秒；生成前及媒体提交前核对原始期限，重生成不续期。满队列优先替换同组等待项，否则从等待项最多的组让出位置，保护已经提交的请求，使任务结果或礼物能够进入队列。

022轮使用组别轮转；023轮已替换为带等待权重的稳定排序，加入有界主题合并、原始事件有效期和严重事件受控打断，具体规则以[回应调度专项](回应调度与严重事件打断.md)为准。连续两条紧急候选后仍向普通候选让出一次机会。观众冷却用于新的问题/礼物，同一候选的事实重生成不被自己的冷却丢弃；公共最小间隔仍有效。真实模型、完整语义/回顾节目和声音整链尚未验收。

## 3. DSH事实与权限

生成上下文提供候选来源、事实时刻及当前世界/会话/模式/新鲜度，明确历史任务结果不能直接说成当前库存。需要当前数量、位置或配方时使用既有只读游戏工具。speech用途不具备启动/取消游戏任务权限；观众文本和礼物名称只作为数据。

记录生成期间实际读取的事实，忽略序号、计龄等易变运输字段，保留库存、任务版本、控制状态、配方内容等实际值。每个请求最多12次事实读取，单条规范化结果最多65536字符，来源最多16384字符；仍服从现有模型时限和最终口播长度限制。

入媒体前再次读取缓存事实，并对配方/前置条件等只读查询重新核验。视觉按带时间与来源的历史观察使用，不为同一次口播再次启动视觉推理。只在生成阶段发生事实变化时，最多尝试两次；模型失败、来源删除、世界改变等原因不无限重试。实际模型措辞仍需逐样本对照真实事实，不能仅凭输入核对就宣称所有输出正确。

## 4. 完成、取消与重启

候选状态为pending、submitting、queued、thinking、synthesizing、playing，以及answered、expired、discarded、cancelled、failed、unknown。中间状态根据现有StreamState投影。仅当请求COMPLETED且utterance存在有效completion_event_seq时，候选才能成为answered；正式回执仍受播放租约、代数、样本映射及自然完成约束。

来源全部隐藏/屏蔽/移除、世界/房间/节目改变、状态陈旧或导播取消时，先保存候选终止状态，再取消原请求。序列化媒体命令在等待前序命令结束后再次核对来源，防止等待期间已失效的回应进入人物链路。实际取消声学效果仍须在真实模型和正式输出端验收。

Stream DB与GameStore各自拥有事务，不声称跨库原子提交。先保存submitting和幂等键，再接受现有DSH请求，最后保存请求关联。来源标为mc-narration但缺候选关联的孤立请求，在生成前或媒体前拒绝；重开未终结候选标unknown并取消遗留请求，不自动重放可能已说过的话。

## 5. Room“已处理”和“已播完”

手动处理、切到下一条留言和旧action=answered只设置handled，均不能设置answered。旧版未核验的answered标记一次性迁移为handled，元数据answered_semantics_version升为2，不删除留言。

`POST /api/dsh/room/speak`可选message_id，必须引用当前可用留言；请求与来源链接保存在Room的speech_links元数据中。只有实际正式PCM完成事件及数据库完成证明同时存在，关联留言才标answered。事件在Stream DB提交后的微任务分发，消费者按异步事件更新；备用扫描可在恢复后核对持久链接。隐藏/过滤导致所有来源不可用时取消请求。

后台“标记已处理”与“已播完”分别显示。私人导播聊天不会自动公开，私人内容填入播报框时清除先前留言关联。Room显示或候选生成成功均不等于观众已经听到；本地正式PCM回执也不证明平台CDN观众端已播完。

## 6. 接口与后台

| 接口/字段 | 行为 |
|---|---|
| GET `/api/dsh/game/narration?limit=20&cursor=...` | items/history分页；active_items独立返回全部最多16条活动候选，避免活动项落在历史首页之外 |
| POST `/api/dsh/game/narration/{narration_id}/cancel` | expected_revision及reason；拒绝过期revision、未知字段和空白原因 |
| SSE narration | 候选变化后刷新现有后台，不引入新的播放权威 |
| AudienceSummary.feedback.speech_status | 未安排或实际候选状态，不能只根据任务终态更新 |
| narration_id / speech_request_id / speech_reason | 对应结果回应及请求/终止原因；没有候选时为null |
| speech_completion_event_seq | 只有已证明完成时存在；answered反馈的契约要求非空正整数及关联ID |

MC后台“主播回应”显示来源、状态、时间、原因、记录和CAS取消；当前活动项与历史分页合并且按ID去重。任务反馈优先使用服务端实际口播状态。观众文本、礼物及原因均通过textContent显示，不作为HTML。错误主文案为中文，来源ID和诊断代码置于可展开记录。

## 7. 验证范围与保留项

022的协议检查覆盖来源去重、正式/预览完成差异、事实变化与重试、过期、写工具拒绝、真实WS终态与部分效果、礼物、建议/投票、队列准入/公平、CAS、删除、媒体排队后核对、孤立提交和持久重启。浏览器使用实际HTTP/SSE与SQLite夹具，检查安全文本、取消/冲突、活动项分页、手机宽度及任务反馈完成链；所有任务自建浏览器须关闭。

最终结果与原始失败按[022轮证据](../../evidence/mc-runtime-round-022.json)登记。原先同步读取异步完成事件的测试失败、重启夹具切换状态目录及未模拟真正非正常关闭的失败、默认建议筛选隐藏已转换记录的浏览器失败均保留原文和修正依据。协议/浏览器检查不替代真实游戏副作用、实际模型事实表达、完整记忆删除、官方声音取消或观众验收；全部68项完整系统验收仍独立执行。
