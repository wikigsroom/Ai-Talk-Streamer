# 规划反馈与异步视觉

本说明记录083的规划上下文和视觉工具实现约束。运行证明与尚未完成事项以[实现进度](实现进度.md)及[3080联调记录](3080原生整机迁移与启停联调.md)为准；源码实现不自动推进正式验收。

## 1. 规划事实与连续反馈

规划首轮提供有界原生事实、聚合库存、基地、检查点、未完成目标与待核对任务。基地保留原登记会话与观察时间；历史记录不能替代当前库存或任务证据。省略账本的重复传输元数据，不改数据库、人格、长期记忆或执行器原始观测。

重复`game_get_state`先对照当前新鲜投影。库存、危险、生命、位置、控制范围、时间区间、基地修订、目标下一步或待恢复任务发生变化时，返回当前完整投影；只有全部事实一致才以`unchanged_planning_facts`确认与本轮初始上下文相同。该标记不表示空库存、没有危险或没有目标。`game_check_action`仍每次走原生检查，启动任务仍重新检查。

`recent_action_checks`只接收实际完成且`allowed=false`的原生检查，包含真实goal、原因、操作编号、来源序号及年龄。检查期间位置、库存或控制范围改变，不记录为新位置上的拒绝。内存最多六项、上下文最多最近三项、期限两分钟；世界、boot、连接、epoch、位置或库存改变后失效。采集仅改变数量时合并同一资源的近期拒绝。该反馈帮助模型考虑其他物品或技能；它不硬编码替代目标、不禁止重新检查、不建立观众长期记忆、不证明资源永远不可达。

保持原有6000输入估算预算、512规划输出上限、六轮工具限制、加密推理重放保护和单模型队列。超过预算仍拒绝下一次请求，不截断人格或事实以伪造通过。

## 2. 视觉工具保持同一名称

原生截图上传、单观察槽、JPEG校验、模型文件锁、结构化结果和HTTP操作查询均不变。`game_request_observation`采用以下三种互斥参数；仍属于原八项游戏查询工具。

| 用途 | 参数示例 | 返回 |
|---|---|---|
| 提交 | `{"purpose":"screen"}`，另支持building、text | 立即返回operation_id、pending、期限；result为空 |
| 读取 | `{"operation_id":"先前返回的编号"}` | pending、succeeded或failed；成功才有视觉描述 |
| 取消 | `{"operation_id":"先前返回的编号","cancel":true}` | 结束仍待处理的观察并中断本地提供者；已终止操作保持原终态 |

单次DSH工具仍限10秒，不把CPU视觉推理塞入同一次等待。受理后，观察交由原操作期限和原生单并发管理，正常工具结束或SDK释放该次调用不取消已经受理的异步观察。需要停止时显式取消；在受理前已经取消的调用不创建操作。换世界、断线、关闭视觉、宿主关闭和原有视觉期限仍会结束观察并释放提供者。

工具只允许读取或取消由该工具受理的短期编号，不接受任意后台操作编号。每个编号绑定world_session_id、bridge_boot_id和connection_generation；读取要求当前原生状态新鲜且范围一致。最多保留八项编号，已终止项可被替换，待处理项不被静默挤掉；期限为本次视觉期限加30秒，不跨宿主重启恢复。

成功结果每次读取重新计算`age_ms`，保持原`captured_at`、帧编号和序号；不重写操作原始结果，不把读取时间当拍摄时间。它始终标记`vision_inference`，不能覆盖原生生命、库存、位置或任务后置证据。超时、取消、未知编号或过期结果不能变成成功描述。

## 3. 模型如何取得后续结果

规划和口播初始上下文附带当前范围内最近一次`vision_observation`编号、状态和期限，不附加画面结论。pending时应等待后续请求或规划轮，再用operation_id读取；禁止在同一六轮规划内连续轮询或把受理当作看到了内容。该提示不进入观众长期记忆，也不另设人格或播放器。

视觉完成不会自动重播上一条用户请求，也不会绕开口播候选的原始期限。需要讲述时仍由当前有效请求经同一DSH、TTS、人物及官方播放完成链处理。CPU推理耗时、画面文字准确性、游戏和语音共同负载、正式播放效果及统一验收仍须分别实测。
