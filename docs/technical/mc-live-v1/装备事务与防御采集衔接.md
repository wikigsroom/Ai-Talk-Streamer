## 1. 共用装备入口

原forceEquipItem不再遍历所有同类堆栈批量交换，也不写死第二个快捷栏；选择一个实际堆栈，绑定其完整组件和数量。普通工具、武器、建筑材料和任务主动指定物品共用主手入口。原forceEquipItemToOffhand使用原版SWAP副手按钮40。原forceEquipSlot只允许主库存0–35，未知窗口槽、光标及其他容器不自动当作玩家装备来源。

已满足目标且没有其他待确认事务时，可以返回当前装备观测。真正移动物品或更换选中快捷栏时，先确认完整服务器库存基线，再按具体步骤执行。选择另一现有快捷栏不搬动物品，仍核对基线后通过原输入账本选中；选中栏位本身没有原版服务器独立确认回执，实际网络时序和物理接管仍待联验。

原卸下逻辑选择一个不满足危险谓词的实际背包槽，保留全部物品；不把危险光标物品丢到地上。光标非空时不推断其来源和归属，完整上游光标恢复仍待实现。库存刷新改成一次完整状态同步请求，移除旧的逐格取出/放回循环。

护甲任务保留原CataloguedResourceTask获取缺少装备的路径，然后每次穿戴一件ArmorItem或副手ShieldItem，确认完成后再处理下一件。旧护甲放回新护甲原槽，不通过垃圾槽或丢弃腾空间。特殊装备、模组穿戴覆盖、按附魔组件挑选最优装备及完整材料预留继续待完成。

## 2. 装备交换

EquipmentPlan描述精确46槽及光标状态，EquipmentExchange管理完整基线和每步确认。最多一个待确认操作，原时限内没有自动重试。原生适配器在发送前检查真实槽位的canTakeItems、canInsert和容量；护甲不能取出、槽位不接收或数量超限时不发送。

| 场景 | 原生操作与确认 |
|---|---|
| 背包物品换至主手 | 空结果槽读取完整基线，再SWAP至记录的快捷栏；等待完整库存确认 |
| 选择现有快捷栏 | 完整基线确认后，经原所有者选择目标栏位 |
| 换副手 | 完整基线确认，再以按钮40进行一次SWAP并确认 |
| 空护甲位 | 完整基线、取出新护甲、放入护甲位；每一步确认，最终光标为空 |
| 替换护甲 | 完整基线、取出新护甲、与旧护甲交换、旧护甲归还原槽；每一步确认 |
| 刷新库存 | 只做完整基线同步，不搬动物品 |

每次点击借助已有revision钩子请求服务器完整库存；本地预测不能确认。完整槽位、光标、数量和组件全部匹配后才能推进；单槽更新、相同或旧revision、客户端预测、其他物品变化均不代替确认。反向包只记录事实，不取得游戏写权限。原版协议没有任务nonce，复用handler/sync后的迟到包关联仍待实机核对。

开始时合成区及光标须为空，并处于原玩家背包handler、无页面、原世界/玩家/连接、有效线程/焦点及生存状态。护甲交换期间的光标只接受当前步骤预期值；不会另开页面或交给其他库存任务使用。

## 3. 调度与交互

驱动在每次上游tick之前推进装备事务并检查原期限。TaskRunner继续评估各生存链，但装备未确认时推迟UserTaskChain和FoodChain的执行，避免原任务或进食使用预测装备。其他避险链继续有资格运行，移动和视角不因普通任务等待而整体停用。

装备请求不会与现有进食、烟熏或其他非空光标事务叠加。FoodChain、补给完成、采食完成和护甲完成等待装备清理；原任务自然结束也检查未结束装备。正在装备时，原生持续攻击/挖掘/使用及选定直接交互返回等待，不使用预测出来的工具、武器或副手。真实紧急用物延迟、投射物、盾牌阻挡和全部其他写点还须完成。

这次装备会保存到玩家库存；没有消费或丢弃。任务关闭不以旧装备快照覆盖后续操作员库存，也不在撤权后移动光标、关闭页面或恢复旧选中栏。原输入账本继续负责它实际拥有的选中栏和合成输入，真实恢复效果仍待验收。

## 4. 期限及交付边界

每次完整确认1500毫秒，一次装备事务总计8000毫秒，包含基线和最多三次护甲点击。中断、等待、重复查询和新包都不重置总期限。迟到包不能救回超时事务。服务器分歧、上下文变化、超时和撤权归入原任务失败路径，不新增一个独立成功记录。
