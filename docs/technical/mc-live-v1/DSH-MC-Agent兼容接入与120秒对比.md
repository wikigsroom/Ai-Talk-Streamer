## 02. 实际链路和模型主体

服务器真实区块/实体/库存 → 用户NeoForge兼容协议 → 插件McBot/Mineflayer → `mc_observe`重建图片及结构化感知 → 既有渠道`gpt-6-luna`视觉解释 → 同一DSH游戏规划 → 实际插件`mc_*`工具 → 服务器回执与库存核验。

解说由同一DSH读取当前游戏事实和最近动作，经过既有人格、记忆、语言自然化约束，调用同一Luna渠道生成口播，经3080上的O07/TTS和MuseTalk/K02进入唯一官方有声播放源。没有另启第二个主播模型或第二个Humanity状态写者。

模型决定目标、坐标、路线和工具参数；操作人员仅连接用户指定服务器、启停本地节目、开启AUTO及本地录制。记录脚本只观察，不提交采集、移动、制作等游戏任务。

## 04. 画面和声音的比较限制

插件`mc_observe`得到的是从bot所知区块重建的图片，不是Java客户端截图。节目画面使用Prismarine实时重建；动态模组方块ID按名称映射到原版显示状态，无法识别的有碰撞模组方块使用洋红色替代。映射只作用于显示数据，绝不改动游戏世界或bot注册表。

因此，此方案不能声称拥有完整模组贴图、复杂方块模型、原生光影、原生HUD或原生游戏音效。当前渲染器没有游戏声音，录音中的人声仍来自正式主播链。图片给模型看的渲染器与观众看到的Prismarine渲染器不同，都基于同一bot世界事实，须分别审阅。

原生087b对照视频保留真实客户端画面和原生音轨。新片必须连续实速120秒，无后补配音、无拼接游戏成果，不用伪造弹幕填充画面。
