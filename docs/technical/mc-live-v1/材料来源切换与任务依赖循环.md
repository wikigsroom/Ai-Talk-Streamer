## 1. 解决的实际问题

此前默认材料收集器只选第一个完全匹配的目录来源，或第一个可获取的具体物品。该子任务结束后，任何背包数量变化都算进展；没有变化则立即中止。这样会遗漏备用来源，也会把消耗食物、获得无关物品等误当成获得所需材料。嵌套配方还可能沿实际父子链重复请求同一来源，直到耗尽更外层预算。

现在ControlledRecipeResourcesTask按确定顺序选择全部完全匹配的目录来源，再选择可获取的具体物品。已结束而未增加所需材料的来源会登记为无进展，继续尝试其他来源。所有新选择仍消费原根256次总预算；没有重设任务期限或授权新的执行根。

## 3. 来源与库存

每个来源保存种类CATALOGUE或ITEM、目录名称或具体物品ID，以及原材料需求接受的完整物品集合。具体物品入口可能在上游委托给更宽的资源工厂，因此进展以原需求集合为准，不能只认入口物品。例如材料允许橡木或白桦木，选择橡木入口后实际新增白桦木也可满足材料。

只读取主背包36槽。库存指纹按物品ID累加数量，不含槽号；仅移动槽位不算进展，也不能绕过循环判断。进展定义为子任务结束后，接受集合内的总数量严格增加。无关物品增加、进食消耗、材料减少或同量替换均不算新增材料。

目录意图不等同于服务器配方。实际CraftSpec/CraftPlan仍核对当前配方、物品组件、成品预留和真实材料分配。本实现没有宣称按物品ID计数足以证明最终合成可执行。

## 4. 循环与替代选择

选择来源时，若同一来源及接受集合已在实际祖先链活跃，而且该祖先开始时与当前库存数量指纹相同，则跳过该来源。兄弟或无关任务不会形成这个循环。祖先期间已获得工具或材料而数量发生变化，允许再次规划；这不是完整静态配方图证明。

第一次开始以及中断后的恢复都会核对实际祖先链。活跃任务重复tick保留最初循环指纹，不以每帧库存覆盖。原子任务尚未结束时保留原对象与获取前基线，不重新计次或重建它。

单个材料没有可用来源时，会继续考察其他缺料请求，允许其他材料的进展改变依赖条件。当前库存下所有来源均无进展则结束为GAME_RESOURCE_MATERIAL_NO_PROGRESS；仍有实际祖先循环阻塞时结束为GAME_RESOURCE_MATERIAL_CYCLE；没有任何已登记来源仍使用原UNAVAILABLE或UNCATALOGUED。工厂返回null按一次无进展处理，继续有界选择；工厂抛出的执行、撤权或其他异常沿原路径停止，不擅自吞掉再试。

本轮没有实现跨已失败子树的全局回溯、全部配方离线展开、自动重新获得授权或无限重试。嵌套任务异常仍结束原根，由已有后台与重新规划流程处理。

## 5. 失败记忆与生命周期

无进展时同时记住获取前与结束后的库存指纹，避免食物消耗等无关变化导致立即重试同一来源。之后库存确有变化可重新评估；同一来源后续真正增加材料时清除它的旧失败记忆。

记录按任务对象身份持有。停止单个收集器只释放自己的活跃声明，保留原根失败记忆、原子任务和获取基线。清理只改内存，不发库存点击、使用、停止或关窗包。只有原执行根的注册清理才统一清空状态；原世界、玩家或连接不能把状态交给另一个根。

| 编号 | 上限 | 超限行为 |
|---|---|---|
| B01 | 主背包36槽，槽位不可重复 | 固定库存无效原因停止。 |
| B02 | 单次候选来源512个 | 固定材料需求上限原因停止。 |
| B03 | 同根活跃获取声明64个 | 固定预留上限原因停止。 |
| B04 | 同根失败指纹512条 | 固定材料需求上限原因停止。 |
| B05 | 原根总选择256次 | 保持原材料选择上限，不因中断或清空帧重置。 |

两个指纹可能相同，只计一条。一次新工厂选择最多新增两条失败指纹；原选择预算与状态容量分别核对。

## 6. 后台与主播事实

GAME_RESOURCE_MATERIAL_CYCLE的中文提示为“材料依赖出现循环”，解释明确指出实际祖先任务链和未变化库存。NO_PROGRESS改为所需材料没有增加、当前库存下可用来源已尝试。全套材料与合成固定原因增至59项。

共享解释仍是只读派生事实，不更改Task.reason、版本、效果或证据。原任务已有的部分产物按回执保留；后台、DSH和主播不能把循环解释为没有发生任何游戏效果。重连后的显式账本查询保留原因、版本和证据，不重放执行。
