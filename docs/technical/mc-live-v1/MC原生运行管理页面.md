# MC原生运行管理页面

第069轮，mc分支。后台提供受约束的服务运行管理；整套业务就绪、真实MC和公开输出分别验收。

## 1. 启动与入口

在实际本机完成准备后，使用项目原生Python启动：

```powershell
python scripts/mc_runtime.py console
```

地址由configs/mc-maintenance-console.json决定，当前原生页面为3093端口。8010的/mc-runtime只跳转至此独立页面；直接页面在A业务停止后仍可用。原维护台与该入口共用端口，不能同时另起第二监听器，不停止或接管外部服务。

若同时需要原生历史维护功能：

```powershell
python scripts/mc_runtime.py console --journal '<实际MC账本路径>' --runtime '<已有维护运行配置>'
```

runtime参数依赖journal。运行任务与维护任务共享执行锁，不能在维护期间启动业务。没有配置维护账本时，维护API明确返回未配置。

## 2. 页面与作业

| 编号 | 操作 | 实际含义 |
|---|---|---|
| R01 | 检查环境 | 执行原有只读预检；缺少设备、来源或文件保持失败 |
| R02 | 查询状态 | 核对受管服务、MC、视觉、正式采集和新人物事实 |
| R03 | 启动后台 | 调用既有application-start，DSH→工作室→接收器；不启动公开广播 |
| R04 | 停止后台 | 先确认DSH offair，再停止准确归属的后台服务 |
| R05 | 查询原请求 | 原request_id恢复作业结果；网络断开或刷新不重复提交启动 |
| R06 | 关闭管理台 | 关闭自己的监听器及作业线程；已运行的受管后台继续运行 |

四类受管服务为DSH、人物、语音和接收器。MC、原生视觉、官方直播姬尚未统一受管；后台启动成功不能代表这些依赖已经启动。页面分别显示后台启动提交与整套应用就绪，后者仍包含真实采集和新人物缺口。

持久作业位于本安装outputs/mc-application-console/console/jobs.sqlite3。同请求同内容幂等，改内容冲突；仅待执行作业可取消。进程中断的启动/停止保持未知，不自动重放。GET只查询保存状态，不探测模型或创建业务任务。

请求限定start/stop/status/preflight，拒绝未知字段、任意命令、路径和可执行程序。沿用本地Host/Origin约束和既有无应用认证要求。启动重查原安装、固定源码、profile和本机准备，停止保留安全退出能力；不伪造准备记录，不跳过既有设备或广播状态限制。

## 3. 验证与边界

20项Python检查覆盖真实HTTP/SQLite、请求幂等、竞争执行、未知结果、来源变化、广播停机拒绝及有界输出。4项新增浏览器检查覆盖启停、丢失响应恢复、拒绝停机与取消排队；使用明确的应用替身，结束关闭全部自建浏览器、监听器和工作线程。

本轮实际启动过项目3093管理台，仅查询真实status/preflight后关闭，没有启动人物、DSH、MC或推流。测试Python3.10缺少jsonschema的失败记录保留，后续使用已有完整Python3.13验证，不下载依赖。一次浏览器夹具获分配5060导致浏览器拒绝，改为直接绑定可用高端口，保留原失败和浏览器端口限制。
