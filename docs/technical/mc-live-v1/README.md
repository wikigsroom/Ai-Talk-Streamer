## 1. 产品范围与完整能力

完整版本为真实Minecraft Java客户端的双模式主播：AI自主操作，或人工操作同一角色而AI解说。两种模式共享世界、背包、事件、林知夏人格与观众关系；切换控制权不另开Mineflayer玩家。

| 需求ID | 完整要求 | 对应验收 |
|---|---|---|
| R01 | 同一真实玩家的状态、库存、规则、关键事件可核对 | V01–V06 |
| R02 | AUTO、人工陪玩、自动化暂停；本地接管优先 | V07–V13 |
| R03 | 导航、采集、合成、使用物品、回基地、取消六项技能 | V14–V19 |
| R04 | 弹幕与游戏同时处理，口播依据事实，过期内容可丢弃 | V20–V25 |
| R05 | 1920×1080横屏、右下小人物、四条滚动留言 | V26–V30 |
| R06 | 后台留言左右切换，礼物跟随且队列连续 | V29 |
| R07 | 一位人格/记忆权威、一份正式可听人物输出 | V24、V31–V33 |
| R08 | 世界账本、下播检查点、重启先核对再续玩 | V34–V37 |
| R09 | Windows原生、设备契约一致、完整联合运行4小时 | V38–V41、C20 |
| R10 | 真实平台、观众端与跨场能力分别验收 | V42–V44 |
| R11 | 普通PvE、补给与多步骤资源目标 | C01–C06 |
| R12 | 原始帧、本地视觉、未知/超时及负载控制 | C07–C11 |

普通PvE、补给、多步骤资源目标、视觉与完整人物素材均纳入本次完整交付，并逐项保留真实证据。复杂Boss、高强度PvP、任意Mod包、任意世界无人值守及无人深空不属于未限定能力承诺。无人深空仅复用上层协议、人格、弹幕和演出框架，游戏适配另立方案。

## 4. 权威与变更管理

优先级为：用户最新要求、项目AGENTS、[冻结布局](../../../configs/layouts/mc-landscape-v1.json)、[设备规范](../../deployment/DEVICE_BRANCHES.md)、本套技术契约、历史研究。

本技术方案整合现有G01-R1研究；它不把旧竖屏要求或旧功能分支计划带回当前MC开发，也不自动批准硬件切换。布局冻结与游戏依赖运行锁是两份不同契约。

完整交付范围与判定以08章为准；01–07章给出对应工程细节，09章贯通全端实现。规划修订为1.2，游戏WS协议仍为1.0；接口业务扩展单独更新OpenAPI版本。

接口、Schema与章节同步更新；破坏性字段变更增加协议主版本，兼容字段增加次版本。候选库/模型版本以实际兼容运行锁记录，本文不追逐“最新版”。未落地接口保留planned；协议客户端检查通过的服务端操作标implemented_protocol_tests_only，并另标真实游戏验收not_run。
