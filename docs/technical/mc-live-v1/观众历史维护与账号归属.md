# 观众历史维护与账号归属

本模块属于同一完整MC版本的D06/D07/D08/D14，不构成独立产品交付。实现与本地验证以[027证据](../../evidence/mc-runtime-round-027.json)及[实现进度](实现进度.md)为准；真实平台/Humanity、完整游戏、容量与联合恢复仍须实机验收。

## 1. 要解决的问题

平台原事件保留7天，Room留言至少保留最近500条。事件已经清理但留言仍在时，后续删除个人记忆仍须找到账号对应的留言；同名观众不能混淆。清理留言也必须同步撤回其选票、建议支持和未完成回应，处理存储部分失败及服务重启。

## 2. 独立的归属索引

`backend/platforms/ownership.mjs`将可信B站账号的Room用户哈希关联到DSH主体哈希，保存在唯一权威状态库的`runtime_meta`中，按实际`characterRoom`隔离。索引仅含schema、两个不透明标识和首次/最近收到的时间，不复制UID、昵称、弹幕正文或偏好。

只接受`blivedm`/`open_live`且`identity_quality=platform_id`的实际事件；匿名或本地转发声明不会建立个人归属。昵称不参与识别，同一账号重复输入合并时间范围，冲突或损坏记录阻止后续写入/清理。

新事件先在平台事务中准备，再提交权威归属，最后提交平台事务并送往Room。归属失败时平台批次整体回滚，Room不显示该批消息。旧平台记录在清理前补建归属，权威提交失败就保留原事件。两库没有共同原子事务：平台稍后回滚时可以留下最小归属索引，不能因此声称原事件已受理。

## 3. 删除范围和恢复

完整账号删除将已知Room用户别名写入持久删除计划；旧备份中即使缺少最新归属索引，计划仍携带这些别名。指定记忆删除沿实际来源定位事件；普通平台输入可根据权威保存的可信collector、platform、room_id、event_id重新得到事件键，不扩大为整个账号删除。

历史重放同时核对可信收到时间与原发生时间，避免未来发生时间使已经收到的旧内容逃过删除。关联来源缺失时继续报告覆盖不足，不从昵称或文字猜测账号。其他观众独立输入与实际已发生的游戏效果保持其原有事实。

## 4. 协同保留规则

| 数据 | 当前规则 |
|---|---|
| 平台事件 | 收到超过7天，且不再是PENDING；保护正在处理的请求和来源 |
| Room留言 | 超过7天且不在最近500条，或超出最近5000条；相同时间以rowid确定顺序 |
| 单次工作量 | 每库最多移除1000条；有剩余时由平台管理器约1秒后继续，正常维护周期1小时 |
| 保留例外 | 置顶/展示留言、活动或排队口播，以及执行中/效果未知/需恢复的任务来源 |
| 维护记录 | 按实际人物/房间保留最近20次运行；每次记录阶段、已确认数量、失败/中断及是否有剩余 |

保护项可能使实际数量临时超过5000。任务只有实际终态、效果已知或明确关闭未知且恢复状态允许时，才不再保护来源；受理成功不能替代任务完成。原始事件清理与个人记忆删除是不同操作。

现有游戏账本尚未载入时，维护不得跳过其未完成任务依赖。返回`AUDIENCE_RETENTION_GAME_UNAVAILABLE`并保留数据，载入游戏服务后可重试；这不会自动启动真实MC客户端、模型或公开广播。

## 5. Room删除与撤回的恢复记录

Room在同一个事务中删除到期留言并保存待撤回来源键`retention_withdrawal`。随后幂等撤票、重算建议支持、清扫口播并发布完整快照；全部完成后才清除这份记录。游戏库或快照发布失败时记录保留，下一次维护先重放，再选择新的清理对象。

游戏服务延迟载入或重启时，在开始运行前重放Room待撤回来源，避免历史选票残留。撤回只处理业务引用，原任务与真实效果不会被清理或重新执行。记录不包含留言正文和原始账号。

这套恢复机制覆盖到期历史的业务撤回，不能替代观众隐私删除计划；后者还需处理模型上下文、个人记忆及旧备份恢复，见[多人回应记忆与删除恢复](多人回应记忆与删除恢复.md)。

## 6. 维护API与后台

| 方法与路径 | 请求 | 结果 |
|---|---|---|
| GET `/api/dsh/platforms/retention` | 无 | schema、固定policy、归属数量、隐私恢复状态、last_run、recent_runs |
| POST `/api/dsh/platforms/retention` | 空对象`{}` | 执行有界维护并返回同一结构；拒绝客户端改变cutoff、limit或保留规则 |
| GET `/api/dsh/platforms/status` | 无 | 原有状态增加`history_retention` |

维护保持免应用登录约束，使用现有请求体限制及参数验证。隐私删除/恢复或其他维护占用时返回503 `AUDIENCE_RETENTION_BUSY`；服务未就绪返回503，非法请求400。报告仅返回数量和错误码，不导出账号、正文、数据库路径或底层错误正文。

`last_run.status`区分`completed`、`remaining`、`failed`及`interrupted`。服务已不在执行但持久记录仍为running时，显示中断，保留最后确认阶段/数量；不能猜测崩溃期间未提交报告的工作量。统计按每次有界运行计，不冒充跨库事务或历次累计总数。

平台接入页提供“观众历史维护”区和“清理到期历史”按钮，显示归属数量、实际清理结果、失败/中断及历史归属缺口。隐私恢复中禁用按钮；失败后可重试。页面保留真实状态，不显示底层错误正文；冻结MC节目布局不受影响。

本API属于平台管理域，独立于现有MC/Room OpenAPI子集；接口行为由本文和真实本地HTTP检查记录，不将其计入该子集的45项操作数。

## 7. 完整交付仍须完成的工作

本模块没有完成B端7天事件/30天任务的历史投影、摘要与保留；两者属于不同存储。旧平台记录已经不存在、又缺少权威绑定的观众仍需补齐归属或报告覆盖未知。归属索引/隐私删除计划的长期容量与保留、真实Humanity、跨进程负载、全部A/B/MC一致备份和次日恢复，继续列在D07/D14/D15。

本地协议、SQLite和浏览器故障检查均单列证据；实际MC、真实模型、平台和观众端通过数量不因这些检查增加。
