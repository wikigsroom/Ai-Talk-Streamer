# 死亡观测与暂停期间的生存提示

本实现属于第083轮完整方案，补充D02、D03、D04、D08。PAUSED撤销自动操作；v40增加未开放局域网的单人世界菜单保护，是否真正暂停仍以新鲜原生观测为准。多人服务器继续运行，不能承诺角色无敌或自动退服。后台的危险提示不获得任何输入权限。

## 单人停止保护

[SingleplayerPausePolicy](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/SingleplayerPausePolicy.java)由现有NeoForge桥在游戏线程调用，不增加输入写入者或AUTO权限。进入单人世界及每个新的PAUSED控制代次，只有当前玩家存活、未开放局域网、任务结束、自有输入已清空、仲裁器已确认释放且没有既有界面时，才调用一次普通暂停菜单。请求、实际暂停确认及失败分别记录；请求菜单不等于世界已暂停。

菜单调用与模式、控制代次检查共用原仲裁器锁；再次检查原世界、玩家、连接及内置服务器对象。旧世界、旧玩家或旧连接的请求不能操作替换后的对象。清理和暂停确认各有2秒期限；失败不反复弹菜单，也不自动恢复AUTO。加载或已有背包、容器等界面只等待，不关闭、替换或点击；人工在本控制代次的键盘、鼠标或真实光标活动取消待执行保护，物理按键仍按住时也取消。F10保留紧急停止意图。人工主动返回游戏后，同一控制代次不会再次弹出菜单。MANUAL_COMMENTARY、联机、开放局域网和死亡界面均不执行自动暂停或重生。

原生`details.environment`新增可选`singleplayer`、`game_paused`、`local_server_published`事实；老适配器缺少这些字段时继续显示暂停待确认。只有当前连接、新鲜且页面已同步，并同时观测到单人、已暂停、未开放局域网时，后台显示“单人世界已暂停”；死亡优先，低生命等危险仍提示恢复后处理。诊断`native_singleplayer_stop`记录代次、会话、菜单请求次数和实际确认，不输出私有路径、不充当控制许可。

v40检查结果和实际运行结论仅以[实现进度](实现进度.md)与[083证据](../../evidence/mc-runtime-round-083.json)的已收集报告为准；源码或JVM情景通过不代表真实游玩验收通过。

## 游戏端与可靠事件

[PlayerLifeEvents](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/PlayerLifeEvents.java)由现有[BridgeCore](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/BridgeCore.java)在游戏线程逐次观察，独立于200毫秒合并状态发送。检测只使用当前世界会话、界面、生命与位置，不查询磁盘、网络或操作游戏。

| 当前可确认变化 | 事件 | 严重程度 | 证据边界 |
| --- | --- | --- | --- |
| 已知存活转为死亡界面或生命归零 | `player_death` | critical | 只确认客户端所见死亡，死因未知 |
| 首次进入观测就已死亡 | `player_dead_observed` | critical | 不推断刚刚死亡，不补造此前死亡时间 |
| 同一连续观测内，死亡转为正生命且不在死亡界面 | `player_respawn` | important | 不证明取回物资、回到原位置或恢复AUTO |
| 同一死亡界面重复采样 | 无新事件 | — | 不反复生成死亡口播 |
| 初次存活、换世界或中间玩家信息未知后恢复 | 无重生事件 | — | 缺少连续变化证据，不推断重生 |

初始加载菜单中客户端的默认正生命不能建立存活基线。首次正生命须出现在游戏、背包或容器画面；随后才看到死亡时，初始加载菜单不构成“已知存活”的前序证据，应记录首次死态。已经确认的生命在普通菜单中保持连续，死亡后真实正生命仍可形成重生事件。此边界由实际死亡存档重载暴露；原失败与新版本情景检查分开保存。

事件保留原始观察序号、时间、世界、任务引用、位置和前一有效观察序号。`cause_known=false`、`inventory_restored_verified=false`、`requires_review=true`明确表示未知项与恢复边界。生成后复制事实，后续玩家对象变化不能改写旧事件。

游戏线程只向现有64项有界收件队列投递。原I/O线程写入同一个LocalJournal、同一`events`可靠递送流，不增加第二个写入者或游戏控制器。死亡、重生在一次合并状态发送之间发生，也分别捕获；队列满沿用现有停止与故障路径，不静默丢弃。晚到的旧世界事件由原账本按旧世界归档，不能改装为当前事件。每次建立连接后先发送当前快照，再发送可靠事件，避免重连初始事件先于世界身份。

死亡进入非游玩界面后，现有原仲裁器继续撤销AUTO、取消原任务、释放自身输入。此实现不点击重生、不拿取墓碑、不退服、不重新授权，不改变Fabric生存候选的启动拒绝。

## 后台与恢复

[MC世界管理](../../../web/mc-control.html)增加独立的生存提示，操作成功/错误提示继续单独展示。[提示规则](../../../web/mc-player-safety.mjs)依据当前新鲜观测显示：

| 状态 | 显示与处理 |
| --- | --- |
| 连接、页面同步或新鲜观测不可用 | 状态待确认；保留的旧死亡/生命不能作为当前事实 |
| 死亡界面或生命归零 | 明确死亡提示，禁用允许自动游玩，说明重生后物资仍待核对 |
| 新鲜原生事实同时确认单人、实际暂停、未开放局域网 | 显示“单人世界已暂停”；已有危险继续提示，恢复游玩仍需明确授权 |
| 低生命、低饱食、低氧、着火、熔岩或附近敌对生物 | 提示具体危险；暂停时说明自动操作暂停不等于游戏暂停，AUTO时关注真实防御、进食与撤离结果 |
| 已连接世界且未处于AUTO | 提示核对游戏实际暂停状态；无人值守时从游戏菜单正常退出世界 |
| 已连服、AUTO且上述危险未报告 | 不额外显示提示；不据此断言不存在其他危险 |

人工恢复时先保持PAUSED，在游戏中正常选择重生或退出当前世界。重新进入后核对新鲜生命、位置、库存、基地以及未完成任务；未知结果仍从原任务账本处理，不重放旧任务。只有操作员明确允许自动游玩并取得新租约后，原规划器才可继续。正常退出后显示连接/状态待确认，不继续声称在线可玩。

## 主播回应

事件进入原[自动口播队列](../../../backend/game/narration.mjs)，仍受内部LIVE会话、8秒事件期限、世界、新鲜度、公平调度、过期取消与正式源播放回执约束。死亡、首次观察已死亡与重生分别提供解释边界；不得编造死因、击杀者、掉落或回收完成，不把死亡前库存当作当前库存。描述当前物资或位置仍须通过原查询工具取得事实。

没有活动内部会话时不会因事件自行开播或发声，也不会向B站发送弹幕或礼物。事件进入队列不算已回应，正式源的完整播放回执才推进answered。

## 验证与剩余

正式页面入口还受[MC页面运行副本更新约束](MC页面运行副本更新约束.md)约束。实际导入副本、模块HTTP状态及JavaScript类型必须分别核对；v29正式入口404不能被隔离样本通过覆盖。

原生JVM的[状态变化检查](../../../game-adapters/minecraft/fabric/src/test/java/dev/aitalkstreamer/mc/core/PlayerLifeEventsFixture.java)覆盖死亡去重、快速重生、首次死亡、加载菜单默认生命、已知生命在菜单的连续性、未知中断、换世界、原任务/观察序号和不可变事实。[提示规则测试](../../../tests/game-player-safety.test.mjs)、[浏览器检查](../../../tests/mc-player-safety-ui.test.mjs)覆盖死亡按钮、断连、重载、桌面/手机与零自动命令；[口播测试](../../../tests/game-narration.test.mjs)覆盖同一可靠流去重与唯一口播路径。所有执行仅在3080进行。

v37离线新世界已实际收到一次存活转死亡事件、手动重生事件，并核验正式桌面/手机死亡提示。死亡存档重载的首次分类仍暴露失败，v38对加载菜单基线的修正经过原生编译与JVM情景复现；新版本真实死亡档再次复验仍待完成。手动重生和单人菜单时钟冻结是独立通过子项，不能把整体失败报告改成通过。

隔离样本不能替代真实PvE/进食、自动墓碑找回或硬件停止时延验收。v25的实际死亡、手工重生及手工墓碑恢复仍按历史源码与原证据保存；v37离线事件不等于v38真实死亡档复验。实施与验收状态以[实现进度](实现进度.md)及[083证据](../../evidence/mc-runtime-round-083.json)为准。
