## 原任务与实际效果

执行中的固定 Json.Rejected 原因只按明确清单分类。LocalTaskFailure 保留既有防御、补给、烹饪、进食、装备和盾牌的固定类型。任意异常消息、近似前缀、包装原因和 suppressed 异常均不能冒充本次执行的公开原因。

人工接管或原控制已撤销时，原撤权原因优先，任务保持 cancelled。失败之后先清理原任务，再发布终态；清理未成功时继续阻止替代任务。异常仍向本地调用方抛出，故障不会因发布任务记录而被吞掉。

已有且绑定原任务的服务器合成回执继续保留，产生过部分产物时 effect_status 保持 partial。失败或取消不撤销游戏里的既有变化；不能仅凭失败原因就认定没有消耗或产物。没有有效效果证据时继续 unknown。

## 后台与 DSH

后台任务历史显示中文原因、说明、建议处理动作，以及可展开的原始原因编号；世界目标的阻塞步骤显示对应中文原因。所有文本通过 textContent 输出。解释表由固定公开资源路径提供。

DSH 的 game_get_task、口播事实读取与任务结果候选均添加临时 execution_failure 对象，字段为 code/category/label/detail/action。原任务对象和数据库不增加这些派生字段。尚未结束、成功或未知编号的任务不附加失败解释。

execution_failure 不是当前库存、当前观测、成功证明或重新执行权限。主播仍需按 state、effect_status、evidence 和 recovery 叙述过去事实；当前位置或数量仍查询现况。口播只在既有唯一 DSH 与正式播放确认链上完成。

## 重连与验收边界

终态通过原可靠消息和任务账本持久化。重连后保留原编号、版本、原因与效果；对已结束任务，显式调用现有账本查询核对历史，不假定重连会自动再次核对所有终态。查询不得产生新游戏效果。

本地检查覆盖原因分类、清理、人工接管优先级、部分合成、原生 Java 与 Node 传输和重连查询、DSH 派生事实、实际 HTTP 静态资源，以及桌面/窄屏后台。测试中的世界、服务器回包、模型和播放端为夹具；没有启动真实 Minecraft 或模型。原生包的 preLaunch 继续拒绝运行，basic_pve/survival_rules/resource_chains 继续为 false。

完整资源依赖合并、循环检测、跨全部消费者的材料预留、所有配方/组件/容器、真实服务器与官方直播姬整链仍按完整交付计划实现并验收。
