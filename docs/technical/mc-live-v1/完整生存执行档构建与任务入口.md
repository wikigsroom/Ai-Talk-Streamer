## 2. 原生构建入口

在mc分支、项目根目录，使用已安装的JDK21、Gradle8.14.3和Node24执行：

```powershell
.\scripts\mc_build_survival.ps1 -JavaHome '<JDK21目录>' -NodePath '<Node24完整路径>' -GradlePath '<Gradle8.14.3入口>' -OfflineInputs
```

该入口先构建并检查原生桥，再准备固定生存依赖、构建候选、执行JVM检查与静态清单，最后核对包内容和收据。OfflineInputs仅要求固定源码/JAR已有缓存，不表示所有Gradle依赖都已离线准备。首次准备公共源码依赖可去掉此参数；没有模型下载、MC启动、推理或开播操作。正式DSH Node24.22.1及干净环境复现仍需实测，不以本地Node24.19.0代替。

准备器使用源码hash和补丁hash命名生成目录，009–010轮20项、011轮24项补丁逐条核对精确上下文。编译前再次检查构建锁、补丁hash、每一份生成文件、额外文件与本地模块元数据。修改后的生成源码不能直接混入编译，必须明确修改受审补丁或源码输入。ZIP路径、Windows反斜杠/盘符、父路径、重复大小写条目、符号链接、条目数和解压体积均有拒绝条件。

Loom拒绝直接嵌入没有模块信息的本地文件，因此在缓存内生成最小Maven元数据并校验hash，原始编译依赖字节保持固定原值。010轮发布候选只嵌入受控转换后的Baritone，另核对转换前后hash及未改的子JAR，不再直接嵌入原始Baritone。生成目录和依赖不写入公共Git。收据在outputs/mc-validation/survival-build-receipt.json；历史基线见[第009轮证据](../../evidence/mc-runtime-round-009.json)，当前结果见[第010轮证据](../../evidence/mc-runtime-round-010.json)。

## 3. 唯一受理根及输入许可

SurvivalAuthority.Context固定task/controller/lease/world/epoch。一个Session对应一个受理根及创建它的游戏线程。ArbiterBoundary持有原生桥原始Permit及task_id，不得在新AUTO时取新Permit来续命旧任务。

规划与任务树只使用线程作用域，不长时间占用原生仲裁锁。单次输入才进入原生ControlArbiter.actuate，在同一临界区检查原Permit与Session仍有效，再执行有界写入。后台寻路线程不能借用游戏线程作用域。晚到工作捕获原Session，禁止读取当前Session来绑定下一任务。

取消先使Session失效，再停树、强制取消配套路径和清理覆盖。释放失败保留所有权，阻止下一根任务，允许明确重试。旧Session的close不会释放新Session。Task.stop使用finally停止子任务并设置终止状态；受控写点撤权时的Denied不会跳过整棵树状态收束，其他错误仍可见。直接输入所有权、物理持键、视角/GUI完整释放尚未接完，这些逻辑不能表示实机停控已验收。

原20项补丁关闭原始命令、idle继任、无作用域TaskRunner/UserTaskChain及自动客户端tick。InputControls、直接攻击、槽位点击、热栏和容器关闭等中央入口已有许可包装；010轮输入转发避免默认键与点击计数队列，新增移动输入身份所有权。011轮补齐驱动级收尾、脉冲队列和任务订阅归属。分散写点、Baritone事件/tick/异步根、全部上游任务清理及真实物理状态仍未接全。当前候选没有将其描述成所有输入已统一仲裁。
