# 本地输入许可、人工接管与主线程停顿

本文件约束完整MC直播中的同一玩家输入。第008轮已实现下列原生源码与本地检查；真实Minecraft、Mixin运行、物理键鼠与20次接管仍未验收。完整交付继续遵守[08章](08-完整交付规划.md)，不以当前进食执行器替代必需的完整生存能力。

## 1. 每次实际输入持有原许可

[`ControlArbiter`](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/ControlArbiter.java)的Permit固定controller、lease、world_session和epoch。任务开始时取得许可；同一任务每次写键、使用物品和改变视角都通过`actuate(permit, action)`。许可核验与一次有界主线程输入写入持有同一仲裁锁；后台停控不能夹在二者之间。许可不能因后来再次AUTO而更新。

`actuate`不容纳寻路计算、网络、磁盘或等待。它仅封装已经计算好的单次游戏输入。外部执行器也必须把所有写入送入此处；只在任务入口检查一次或仅停止寻路均不足以完成接入。

释放输入同样携带epoch。旧排队释放不触碰新epoch的输入，也不为新epoch确认“已释放”。实际释放抛错时仍保留未确认状态；释放回调不能重新启动输入，嵌套新停控也不能被外层旧释放确认。游戏桥的世界变更、断线、人工/暂停和任务取消分别保留对应任务与控制代数，不让迟到回调取消后续任务。旧的无许可持键/无epoch释放确认入口已移除。

## 2. 主线程进度独立于网络续租

主线程每次有效采样更新本地单调时钟进度；允许的最大间隔为2000ms。恰好2000ms仍可更新，超过即撤销原AUTO。网络心跳/新租约不能代替游戏进度。

I/O看门狗检测超时会先撤销许可、变更epoch，再排队取消任务和释放输入；原因是`GAME_CLIENT_TICK_STALLED`。即使看门狗暂未运行，游戏线程恢复采样时也会先检查原间隔，撤销旧AUTO后才发布新状态。恢复采样、断线重连或迟到续租均不恢复旧任务权限，必须显式重新AUTO。

撤销许可可以独立于游戏线程发生；实际释放游戏按键必须等待游戏线程能够执行。不能据此承诺游戏线程完全冻结时仍在250ms内完成物理释放。真实停控时延和线程负载继续属于D03/D14/D15验收。

## 3. 受理、落盘与实际执行各自核验

原观测时窗约束任务受理；受理后不会因为正常排队超过原观测时窗就机械拒绝。主线程预检查、running转移落盘之后的最终执行分别重新核对：

1. 任务仍是当前任务，且没有取消标记。
2. 完整任务期限尚未到达。
3. 最新样本仍属原世界且界面允许。
4. 原controller、lease、epoch及新鲜观测仍有效。
5. 游戏端依据当前真实状态重新进行前置检查。
6. 最后一次输入写入仍须通过原Permit，消除检查之后撤权的间隙。

任务期限从B受理时计算，包含排队/写盘时间。受理或running期间超时均记终态；尚未建立原生执行对象也不能永久卡在running。超时取消绑定原任务对象，迟到启动/超时回调不能影响下一任务。未核验副作用继续为unknown，不宣称“什么都没发生”。

## 4. 本地停控键、光标与物理按键

默认F10在Minecraft“选项 → 控制 → 按键绑定 → 林知夏 · MC直播控制”中改绑；按键由游戏实例的`options.txt`保存，不修改推理设备配置。支持键盘、扫描码和鼠标绑定。事件在游戏通常处理之前进入仲裁，菜单内也可请求PAUSED；普通真实键盘/鼠标/滚轮/移动将AUTO转人工陪玩。真实游戏的冲突提示、菜单和战斗处理仍须实测。

[`CursorActivity`](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/CursorActivity.java)只豁免通过当前窗口`InputUtil.setCursorParameters`明确登记的一个坐标事件，期限100ms、坐标容差0.01像素。其他坐标立即按正常移动处理并消耗该豁免，不存在整段“忽略鼠标”的时间窗。小于0.5像素的移动累计计入，避免每次微动都被忽略；第一个没有明确程序来源的坐标事件保守地视为人工。窗口回中/分辨率/焦点的实际GLFW回调序列仍待实测。

[`InputLedger`](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/InputLedger.java)仅释放本桥持有的输入；释放当时重新读取物理按住状态。未知扫描码使用实际回调记录，已知扫描码只查询实际回调提供的有效键码，不枚举非法GLFW键。失焦按游戏未持键处理；其硬件行为必须实测。失败释放保留账本，允许后续重试。

## 5. 本轮验证及完整边界

Java检查覆盖旧许可遇新AUTO、controller/lease/world不匹配、撤权和输入写入的串行化、失败写入/释放、旧释放不影响新输入、2000ms边界、网络续租不能维持停顿客户端、恢复先于看门狗、程序光标坐标与小幅移动、物理持键保留和失败重试。

真实编译Java核心与Node宿主还覆盖：阻塞测试游戏线程后，已经排队的旧效果不能执行；最终启动延迟超过任务期限后，原任务可结束，迟到回调不取消下一任务。效果为明确的测试计数器，既不是MC物品也不是硬件输入。

原生Mod编译会校验所声明的Mixin目标及打包资源；这不证明运行期注入成功。未绑定的AltoClef/Baritone仍撤回自动能力，完整执行档接入须遵守[源接口核对](AltoClef接入核对与输入约束.md)。最终报告与中间失败见[第008轮证据](../../evidence/mc-runtime-round-008.json)。
