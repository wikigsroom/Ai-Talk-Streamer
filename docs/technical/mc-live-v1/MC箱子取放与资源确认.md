# MC箱子取放与资源确认

本说明约束普通箱子、陷阱箱、木桶的内部资源取放。它接入现有 AltoClef 资源任务和原任务控制权，不增加第二个游戏控制器或新的公开操作权限。生存执行器仍受无条件 preLaunch 拒绝限制；本地构建、库存协议测试和源码安装不等于真实游戏验收。

## 任务入口与容器归属

`PickupFromContainerTask` 和 `StoreInContainerTask` 保留原来的寻路、开箱和材料获取路径，实际取放、完成判定与停止委托给 `ControlledStorage`。上游改动登记在 `controlled-patches.json`，由离线准备工具对锁定源码逐项匹配生成，不能直接修改生成目录。

支持27格单箱/木桶和54格双箱，对应包含36格玩家主背包的63/90格界面。界面必须由当前任务对预期位置发起打开：绑定原世界、玩家、连接、任务、控制代次及实际界面/handler对象。相同界面类型或相同同步编号不能继承控制权。开窗协议本身不携带方块坐标，位置关联依赖原交互后的首个期望响应，仍须真实服务器验证。

箱子绑定实际方块状态和方块实体。双箱同时绑定两侧实体、连接方向和左右类型；任一侧更换或连接变化即失效。木桶打开后会改变自身的打开状态，因此保持木桶种类和实体身份检查。物理接管、切换世界、焦点丢失或原任务撤销后，不发送归还光标、丢弃或关闭界面的补偿操作。

潜影盒、漏斗、交易、其他容器和任意模组界面不在本次接入范围。附近存储/区域存储的扫描只选择上述普通容器；这些其他消费者仍须分别实现、审查并实机验证。

## 服务器确认与精确数量

首次取放必须取得原容器的完整服务器库存包，并与实际handler所有槽位和空光标一致。不会把预测库存当作初始服务器状态，也不会假设箱子第0格为空而点击它获取基线。

每次搬运先拿起来源物品，再精确放入目标槽；只搬运部分时，逐件放入后将余量放回原来源槽。每一步只允许一个受控 `PICKUP`，发包时通过现有 revision 钩子请求完整重同步，等待更新且向前的服务器 revision。每次完整回包必须同时匹配全部槽位、物品组件、数量和光标，才允许下一步。

点击确认期限为1500毫秒；单次搬运总期限12000毫秒。原容器打开期限1500毫秒，打开后空闲期限3000毫秒、绝对期限15000毫秒，观察或重复确认不能续期。目标槽检查真实插入权限、最大堆叠数与组件兼容性；玩家槽必须完整且唯一映射到36格主背包。

流程不使用快速移动，不自动丢弃腾位，也不在超时或分歧后盲目重试。局部成功和不确定效果保留在原任务事实中；错误不意味着已有游戏变化已撤销。

## 材料保留与外层存储任务

取物目标按玩家背包内的绝对数量判断，光标上的物品不构成完成。存物目标按本任务已确认搬运的数量累计，箱内原有物品及其他人的操作不构成本任务成果。组件仍须精确匹配；目标的可替代物品按同一条件计数，重复替代项不会重复累计同一单位。

存入前根据 `ResourceMaterials` 的真实主背包库存与原祖先任务的材料保留求可用量。在来源取出前检查允许移出的数量；光标向容器放入时再次检查外部可消耗量。暂存于光标的保留余量只能在同一事务中回到原槽，不能供其他装备、进食或库存消费者借用。

`StoreInAnyContainerTask` 和 `StoreInStashTask` 通过有界、原根任务所属的观察者接收已确认的存入事实。区域存储使用实际容器位置过滤；停止任务解除观察，根任务回收清空全部观察者。旧的本地预测槽位事件不再驱动存储计数。剩余目标减去已确认数量，避免换箱后重复存入，也避免背包缺物时误判任务完成。

允许补材料的任务继续通过原任务树获取剩余缺口；区域存储沿用自己的补材料开关。无法满足的物品、材料保留、空间不足和不支持的界面使用固定错误原因返回，后台和模型只读事实显示中文解释，不自动获得重试或执行权限。

## 并发、预算与收尾

从实际开箱等待起保护库存路径，确认期间保留原子任务与祖先路径，并暂停依赖这段库存的用户/进食链切换。原驱动每帧推进等待和确认，避免暂停任务链后无人处理回包。装备、进食、盾牌、补给、资源回退及相关实际动作检查这段库存占用；危险中止仍可撤销原任务。

所有点击仍通过 `SurvivalAuthority` 和既有GUI写入入口。回包只记录事实，不借回调获得新的写权限。一个根任务最多64项取放任务、64个存储观察者；每项最多64组目标、256种目标物品、256种组件身份，每组最多4096件，单堆最多99件。事务确认、空光标和界面收尾完成后，才允许正常任务完成。
