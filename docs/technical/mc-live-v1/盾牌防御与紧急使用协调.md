# 盾牌防御与紧急使用协调

046实现，分支mc；属于同一完整系统交付。真实MC、服务器阻挡及整场联验尚未通过，当前结果以[实现进度](实现进度.md)、[机器状态](implementation-status.json)和[本次证据](../../evidence/mc-runtime-round-046.json)为准。

## 1. 解决的业务问题

上游MobDefenseChain和KillAura分别使用右键、清走主手食物和整理光标来举盾。原版右键可能先使用主手，两个防御入口又可能分别释放同一输入。进食链一旦被防御压低优先级，其待确认库存和原快捷栏恢复还会失去推进机会。

现在两个入口提交当次更新的盾牌需求，共用ControlledShield和ShieldCycle。在原任务许可内直接调用原版副手物品使用；主手可以继续保存食物或工具。举盾和收盾不搬主手、不挪光标、不丢物品、不新建公开任务，也不申请第二套控制许可。

## 2. 原任务更新中的顺序

| 顺序 | 实际入口 | 约束 |
|---|---|---|
| 1 | ControlledShield.beginTick | 绑定同一Session、世界、玩家、网络连接和管理器，清除上一更新的需求；原期限保留。 |
| 2 | 装备、烹饪、进食、补给检查点 | 装备继续等完整库存；被打断的原进食子任务可独立推进确认与恢复，不创建新一口。 |
| 3 | 上游任务与防御优先级计算 | THREAT与MELEE分别提交/撤回自身需求；要求装备盾牌前也提交需求，从而先中断原进食。 |
| 4 | ControlledShield.endTick | 无需求收盾；装备/食物尚在恢复则等待；条件满足后只使用一次OFF_HAND。 |
| 5 | 完成原公开任务 | 先收回仍由原许可持有的盾牌使用，再处理原交互和GUI清理。普通任务完成不能越过待处理盾牌。 |

紧急避险链保留调度资格。持盾需求不增加公开技能；公开入口仍为navigate、gather、craft、use_item和return_base。

## 3. 单次副手使用与协作

盾牌必须是实际副手中的原版单个ShieldItem，冷却结束，玩家存活、窗口聚焦、没有打开容器；光标和玩家合成格必须为空。装备事务须先完成，进食须先确认零/一次消耗并恢复原库存。等待时不预测装备完成，也不清空未知光标。

使用经过SurvivalActions和原根输入记录发送，明确指定OFF_HAND。接受返回后还检查实际active hand、active stack、副手堆栈与冷却。比较保留除耐久损耗外的物品组件，允许原盾牌在格挡中正常损耗。该检查是客户端使用观察，不是服务器确认阻挡了某次攻击。

持盾和等待期间，原版重复右键及选定的挖掘/世界交互不能误用主手。持盾期间拒绝其他GUI写入。没有盾牌需求的更新不触碰其他库存事务；没有持盾或等待需求时，游戏更新之外的正常攻击继续沿原控制入口执行。

近战出手经过原视线、距离、冷却与每刻一次检查后，先收盾，再攻击，并压制本次更新的近战重新举盾。当前存在投射物/爆炸防御需求时保留盾牌，攻击等待。MELEE的撤回不能解除THREAT的需求，反向亦然。两个入口不再直接控制SNEAK或JUMP，避免代替其他避险任务释放输入。

## 4. 中断进食、释放与撤权

防御需求会中断正在进行的原进食任务。原任务预算和库存交换记录保留，原检查点在没有其他物品正在使用时推进恢复；不会因FoodChain没有获胜而一直搁置。消耗、健康同步、回收剩余物、恢复背包及选中栏仍遵守[自动进食与装备确认](自动进食与装备确认.md)和[共用装备事务](装备事务与防御采集衔接.md)。

正常收盾在仍有效的原许可内释放该任务持有的使用键，并发送原版RELEASE_USE_ITEM，即使本地动画已经结束。必须仍属于原盾牌请求，不能停止另一个正在使用的物品。盾牌本地失效先收回旧请求，之后才可能在新更新、原预算内重新尝试；不在同次更新重发。

人工接管、断线或原根撤销后，订阅清理只忘记该盾牌状态，并由既有输入记录释放原任务持有的输入。不发旧盾牌停止包、不整理库存、不覆盖接管者当前动作。真实物理输入恢复和服务器迟到包仍需实机验证。

## 5. 有限预算和失败

| 项目 | 固定上限 | 行为 |
|---|---:|---|
| 等待原装备/食物/上下文可用 | 8秒 | 等待期间不发物品使用。 |
| 同一次连续持盾 | 10秒 | 不通过重复需求刷新持盾起点。 |
| 同一防御遭遇 | 60秒 | 多次启停、优先级变化或任务重选不刷新遭遇起点。 |
| 同一遭遇的使用请求 | 64次 | 防止服务端不断取消后持续重试。 |
| 新遭遇的释放静默间隔 | 2秒 | 必须已收盾且没有新需求；短暂调度空隙不能重置预算。 |

固定失败为SHIELD_TIMEOUT、SHIELD_LIMIT、SHIELD_USE_REJECTED和SHIELD_CONTEXT_CHANGED，沿既有LocalTaskFailure进入原任务结果。具体错误不替代服务器效果证据。

## 6. 实现与验证路径

主要实现位于survival/src/main/java/dev/aitalkstreamer/mc/survival的ControlledShield、ShieldCycle、SurvivalActions、ControlledEatingTask、ControlledAltoClefDriver和SurvivalGameExecutor；受控源补丁替换实际MobDefenseChain、KillAura的启停及装备前入口，并让TaskRunner等待原盾牌处理。

ShieldCycleTest覆盖多个需求源、逐次更新失效、待装备、冷却、使用失败、持盾及遭遇期限、次数预算、近战收盾、撤权、时钟和空闲路径。ShieldBindingTest检查实际生成上游与编译产物、明确副手、唯一原许可入口、进食恢复、原版重复使用拦截、原生释放及撤权清理。构建核对要求新类和实际绑定均进入最终JAR。

先保存构建前输入，再执行原生Windows/JDK21/Gradle离线构建、桥接Java和Java↔Node互通；全部进程终止后保存实际XML/JAR/门禁报告，再修正复核发现并只重建受影响代码。当前证据不把两次执行的同名测试重复计数。公共源码包还要实际导出、独立安装、逐文件一致，不能用目录清单代替安装结果。
