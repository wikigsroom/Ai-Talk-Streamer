# 任务收尾、输入代次与事件订阅

本专项对应完整发布内部第011轮、D03–D04及D14。[完整交付规划](08-完整交付规划.md)的全部15域、68项、4小时、次日与100段新人物范围保持不变。候选仍保留无条件preLaunch拒绝，没有向MinecraftPort发布完整生存能力。

## 1. 输入代次

InputOwner在客户端线程中为每个生存任务创建固定Scope，包含InputLeaseFence.Ticket。按键、点击、移动输入及ArbiterBoundary中的通用副作用均检查原代次，并使用原ControlArbiter.Permit；视角/交互不能绕过代次校验。全局输入恢复成功后代次递增；恢复失败保留原代次和未释放项，允许明确重试。

旧Scope在新的代次不能写入，旧释放也不会清除下一任务重新按下的同一键或替换其移动输入对象。人工接管后的全局恢复同样使原Scope失效。物理持键仍由原生账本在释放时重新采样，不因代次递增而主动清除人工持键。

## 2. 任务收尾链

ControlledAltoClefDriver使用实际ControlledTaskRunner管理唯一Session，启动入口要求已绑定InputOwner的原生ArbiterBoundary。无绑定的测试边界不能进入实际游戏驱动。

收尾首先撤销Session，然后尝试停止任务树、注销任务订阅、取消路径、清除寻路按键覆盖、清空脉冲队列，最后始终尝试桥端原代次输入恢复。一项失败会保留错误并继续其余步骤；任一步未完成，Session仍占有根任务，不能开始新根。重试成功后才释放根任务。

ArbiterBoundary固定原task/controller/lease/world/epoch。正常结束通过原epoch释放输入并更新本地释放状态；接管已推进epoch时，只处理原Scope仍持有的代次，不重新取得新许可。旧Session再次close不会清理后来Session。

上游正常结束与取消都可能触发完成回调。这里仅在原Session仍有效且处于游戏线程作用域时接收通知；正常完成也只发出EXECUTION_FINISHED_REQUIRES_EFFECT_VERIFICATION，由后续真实状态核验决定成功。取消、超时、异常和撤权都不冒充效果成功。

完成通知在清理后调用，可以开始下一个根任务。通知本身抛错时，只保留该错误，不取消其已开始的新任务。清理期间重入cancel不递归收尾，也不允许重入start。

## 3. 脉冲队列

AltoClef InputControls新增clearControlledQueue，仅清除待释放队列与单击去重集合，不直接操作键鼠。任务准备和收尾均调用它，防止上一根排队的释放在下一根首tick清除新按键。

该方法要求当前线程仍属于原Session的owner作用域。被撤销的close可以清理自己的内部队列，但不能借此执行游戏副作用；普通requireScope和原生Permit仍拒绝新动作。

## 4. 事件订阅

任务作用域内创建的Subscription固定捕获原Session，并登记关闭时的unsubscribe。事件到来时，仅原Session有效且在原游戏线程才进入其作用域；迟到、下一任务和工作线程事件不能重新绑定当前任务。原任务最多登记1024项订阅清理，超过上限明确失败。

进程级观察者在任务外创建，回调会临时清除发布者的任务作用域，异常时也恢复原作用域。即使由某个任务发布事件，观察者也不能借用该任务的游戏权限；它们仍可观察事件。跨线程事件如何正确调度回游戏线程、Baritone自身事件/tick/路径结果的原任务绑定仍需后续接通，不能由本项订阅改造代替。

EventBus以订阅列表快照分发，回调在topic锁外运行。回调内新增订阅从下一次事件起生效；注销会立即标记并移除。异常和嵌套事件都经过finally清理，不再依赖一个可能残留的全局lock标志；任务关闭不必等待下一条同类事件才释放订阅。

## 5. 检查与未关闭事项

新增检查实际使用原生InputLedger、OwnedValue、InputLeaseFence、ControlArbiter、受控任务运行器，以及按固定补丁生成的EventBus、Subscription与InputControls。游戏效果仍使用显式夹具，尚未执行真实物理键鼠、MinecraftClient或生存任务验收。构建、用例结果和包hash见[第011轮证据](../../evidence/mc-runtime-round-011.json)。

本轮原生桥86项JVM、生存65项JVM、11项Java↔Node及14项Python准备检查，共176项不同本地检查均实际执行通过。最终打包顺序复核沿用本轮同源码的86项单测结果，11项联调重新完整执行，不将重复执行累计成更多用例。生存准备器核验433份源码和24项精确补丁；最终包、受控Baritone、原生输入API和门禁策略的hash均通过核对。

首次联调为10项通过、1项在测试桥首次连接前超时，原日志保留。测试桥已加入启动阶段诊断，构建明确要求打包完成后再运行依赖实际时间的联调，12000ms启动等待未放宽。后续完整复跑通过，但首次超时成因及历史高I/O/通用ACK仍未证明解决，继续列入D14。

静态清单为998类、13552条未分类指令，包含读取和内部赋值；37+50处选定门禁不表示全部副作用覆盖。
