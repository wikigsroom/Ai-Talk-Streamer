# 原生运行持续监督与故障回收

第063轮，mc分支。实现接在原有[启动事务](原生启动事务与失败回收.md)之后，覆盖同一事务新增的原生进程族。完整交付仍执行[实施总纲](13-完整方案实施总纲.md)和[全部待办](实现进度.md)，不以进程测试代替模型、MC或官方节目验收。

## 1. 已接入的行为

| 场景 | 当前行为 |
|---|---|
| 人物、语音整组启动成功 | 新增独立监督进程，持有本次Job及各根进程的显式复制句柄；原启动入口可以退出 |
| 任一未请求停止的根进程退出，包括退出码0 | 记录FAULTING，终止本次Job，查询ActiveProcesses为0，再核对并清理本事务原登记；结果为FAULTED |
| 监督进程意外退出 | 正常提交后保留KILL_ON_JOB_CLOSE，最后Job句柄关闭时由Windows终止其进程族；查询不再显示RUNNING |
| 单独停止人物或语音 | 原操作锁内先登记精确停止意图，再执行既有停止过程；同组另一个服务继续被监督 |
| 全部根进程按请求退出 | 清理剩余同组子孙，实际核对Job为空，清理原登记，记录STOPPED |
| DSH在开播中拒绝关闭 | 保留原shutdown拒绝；撤回仍存活根进程的停止意图，继续监督 |
| B端接收器停止 | 同样登记停止意图，保留精确进程核验和原停止过程；不加载推理模型、不停止公开直播 |
| 更早已存在的服务或替换登记 | 不加入新Job，不终止其他组；清理时只删除内容仍等于原写入的登记 |

入口为[人物/语音](../../../scripts/launch.py)、[整组演播台](../../../scripts/start_studio.py)、[DSH](../../../scripts/dsh_control.py)与[接收器](../../../scripts/receiver_control.py)。设备、来源、模型准备、唯一DSH写者和开播保护仍在各原入口执行。

## 2. 句柄移交和提交窗口

[native_operation.py](../../../scripts/native_operation.py)在COMMITTING阶段创建[native_supervision.py](../../../scripts/native_supervision.py)的独立worker。服务通过创建时JOB_LIST归属Job；worker在该受管Job之外创建，只显式继承复制后的Job、根进程和标准输入输出句柄。

worker按原生创建时刻、GetProcessId和IsProcessInJob校验收到的根句柄，写入ARMED。父入口等待ARMED后保留kill-on-close标记，再检查根进程是否存活；写入并同步COMPLETED操作记录。worker读取首字节锁之后的元数据，见到对应操作的COMPLETED才进入RUNNING，父入口确认RUNNING后关闭本地句柄。监督过程不以可复用的PID或端口开放代替实际进程句柄。

移交等待最长12秒，worker等待提交最长25秒。创建、准备、最终提交或等待失败，父入口回收新Job并终止自己创建的worker。父入口在未提交窗口崩溃时，worker观察精确父身份及提交记录，回收未提交的组；持久提交后的父入口正常退出不结束监督。

Windows依据见[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)与[Job扩展限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)。进程创建、句柄轮询、终止和等待由[native_windows_process.py](../../../scripts/native_windows_process.py)实现；不使用进程名称批量终止，也不调用虚拟化环境。

## 3. 停止意图与记录一致性

新进程登记带native_supervision_version=1及native_operation_id。每组的input、status、stop和log均保存在本安装`.setup/native-supervision`，不随公共源码导出。停止入口必须持有原安装操作锁，核对原路径、key及完整登记，再原子写入该组允许停止的根身份。旧格式不自动接管。

监督先观察根进程退出，再读取停止意图，避免正常停止与轮询同时发生时误判。停止失败只撤回仍存活根进程本次新增的意图；已退出的预期根不被追认成异常。清理登记也使用同一安装锁，最多重试8秒；锁长期占用或登记损坏时保留registry_cleanup_confirmed=false，不冒称全部清理完成。

状态及控制JSON使用同目录临时文件、flush/fsync和替换。读端显式允许read/write/delete共享；对Windows 5/32/33文件争用做最长1秒的有界重试，超时保留原目标及明确失败。实际平台仍可能拒绝替换被打开的目标，不承诺持有任意长读取句柄时更新立即成功。API依据为[CreateFileW共享规则](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)和[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。

## 4. 查询与故障处理

```powershell
python -X utf8 -B scripts/mc_runtime.py supervision-status
python -X utf8 -B scripts/mc_runtime.py operation-status
```

第一条只读列出各组的phase、supervisor_alive、family_empty_confirmed及registry_cleanup_confirmed；第二条查看最近一次安装操作。两者都标明service_readiness_checked=false。没有监督记录的查询不创建worker或监督目录。

若存储状态为ARMED/RUNNING/FAULTING/STOPPING而监督身份已退出，查询投影SUPERVISOR_EXITED，不凭旧状态冒称正在运行。监督自身崩溃后没有新的Job为空回执，family_empty_confirmed保持原事实，不能把内核发起终止当成完整GPU释放或SQLite恢复成功。

故障后保留状态和日志，核对原服务登记、模型与SQLite退出事实后，走现有停止/准备/启动入口处理。代码不自动重启模型或切换状态根。064在DSH正常关闭中补充[模型用途排空与隐私重建屏障](DSH关闭与隐私重建屏障.md)，仍需与真实进程退出、媒体及设备恢复联合验收。

## 5. 验证与未完成部分

[监督检查](../../../tests/test_native_supervision.py)使用真实Windows进程、父子孙、Job与文件争用；[启动事务检查](../../../tests/test_native_operation.py)及[生产入口检查](../../../tests/test_native_entrypoints.py)使用临时标准库进程，模型、设备、端口、健康接口与平台关闭答复均为明确替身。当前共51项通过，新增22项；其中包括生产人物单独停止保留语音、生产接收器停止，以及直播拒绝关闭后恢复监督。

初始提交后孤儿复现失败、已关闭测试句柄误用、状态读取争用和长读取下立即替换的错误测试预期均保留；检查代码后还调整了停止意图读取顺序。两次早期故障回执异常没有保留worker日志，精确原因未证实，继续列为未关闭诊断，不能凭最终通过追认其根因。最终计数不叠加重复执行。源码安装、当前字节绑定、其他检查及审计见[本轮证据](../../evidence/mc-runtime-round-063.json)。

仍需MC/视觉/官方端全栈依赖监督、跨不同启动组的故障策略、单个根停止时与后续派生并发的完整处理、旧部署接管、长期日志/容量/磁盘故障、实际模型/GPU与SQLite恢复、服务就绪及完整节目长测。同组其他根仍运行时，已停止根留下的未知后代可能等到全组结束才整体回收；本轮没有实现每个根的独立嵌套Job。完整生命周期不标记完成，实机验收仍0/68，新人物仍0/100。
