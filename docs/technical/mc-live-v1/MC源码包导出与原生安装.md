# MC源码包导出与原生安装

对应实现032，属于[一次完整交付总计划](12-一次完整交付总计划.md)的D01。导出与安装项目源码、准备本机运行环境、验收完整直播系统分别记录证据。本文的源码ZIP不包含完整依赖、模型、人物素材、游戏实例或平台账号，不能当作可直接开播的完整安装包。

## 1. 来源与准备分别核验

| 记录 | 生成条件与用途 |
|---|---|
| ZIP内mc-source-manifest.json | 真实mc分支/HEAD和实际公共源码文件的SHA256、字节数、整体清单摘要；脏工作区如实绑定到文件，不声称HEAD已包含改动 |
| .setup/mc-source-origin.json | 校验已核对的整包SHA、清单与全部文件后，由安装命令生成；绑定新安装绝对路径、包摘要和完整清单 |
| .setup/mc-native-preparation.json | 在安装目录配置真实原生程序、私有参数、既有模型/声音/依赖和MC工程候选后，由prepare完整检查并生成；启动前重新核对 |
| .setup/deployment-origin.json | 原有设备来源记录；源码安装不创建或改写。已有记录时仍核对3080目标和deploy/rtx3080来源，外设备记录拒绝 |

无Git安装的启动入口只有在完整本机准备证明有效时，才使用已验证的源码包来源；仅放一个origin文件、复制另一安装的准备记录或修改分支名都不构成准备。3080/batch4、原DSH状态根及真实设备检查继续执行。记录不授予游戏自动控制权或正式声音权。

SHA256核对给定包的完整性，预期值应来自已经审查的导出记录或可信发布渠道。它不是发行方签名，也不证明第三方内容的许可证合规。本地可写记录不替代操作系统访问控制。

## 2. 实际公共源码范围

纳入backend、web、integration、scripts、deployment、configs、tests、game-adapters、运行时使用的docs/dsh-humanity及docs/technical/mc-live-v1/contracts；另含根依赖清单、忽略规则、AGENTS、README、LICENSE/NOTICE/THIRD_PARTY_NOTICES及根目录CMD/PowerShell入口。062新增tests根目录及夹具、固定检查清单和安装后自检入口，见[源码包自检与核心测试复现](源码包自检与核心测试复现.md)。

032发现旧清单漏掉游戏服务实际加载的game.schema.json、根启动脚本和许可证文件，已保存修正前真实Python3.10.22来源清单与六个遗漏文件的摘要。新清单覆盖这些文件。生成的contracts/verification.json是文档检查结果，排除于运行源码证明。

| 分离内容 | 处理方式 |
|---|---|
| 私有绑定、平台凭证、私有策略和token/密钥 | 不导出；若被强制跟踪并进入待导出来源，拒绝导出，避免静默泄漏 |
| .git、.setup、state、缓存、node_modules、构建目录、模型及录制产物 | 不进入公共源码包；不复制活动数据库、运行证明或PID |
| 生存上游源码、依赖及工程JAR | 本包只带项目内公共工程源码/锁；完整上游源码对应、许可和运行依赖仍须进入最终发布清单 |
| 人物、声音及视觉资产 | 沿用各自版本与完整交付要求；本包不创建100段素材，也不取得下载新模型的授权 |

安装后重新扫描公共目录和根入口，修改、新增、删除文件均使来源检查失败。运行依赖和私有绑定由runtime_files及原生准备检查独立核对。

## 3. 可执行命令

使用原生Windows，确认当前检出为mc。导出与安装不安装依赖、不执行包内脚本、不启动服务或模型。执行命令的Python不自动成为正式人物环境；正式绑定仍要求实际3.10.22与完整人物依赖。

```powershell
python -X utf8 -B scripts/mc_runtime.py export-source --archive .\outputs\mc-source-review.zip
```

父目录须已存在，ZIP文件须不存在。保存输出的sha256、source_snapshot_sha256及source_files，审查来源与内容后使用预期摘要。同一公共源码及HEAD导出的ZIP字节一致；存在旧包时不覆盖。

```powershell
python -X utf8 -B scripts/mc_runtime.py install-source --archive .\outputs\mc-source-review.zip --sha256 '<已审查导出记录中的64位小写SHA256>' --root .\installations\mc-native-3080
```

installations父目录须预先创建，mc-native-3080须为尚不存在的新目录。不要把当前检出或旧安装作为目标。程序先在同一父目录的独占临时目录核对和写入，全部成功后改名发布；目标已存在、提交时被其他操作创建或校验失败，均不替换旧目标。程序从当前已审查入口执行安装，不运行ZIP内代码。

```powershell
python -X utf8 -B .\installations\mc-native-3080\scripts\mc_runtime.py describe
python -X utf8 -B .\installations\mc-native-3080\scripts\mc_runtime.py preflight
```

纯源码安装应能核对公开profile及源码。缺少私有配置、原生绑定、模型或运行文件时，preflight如实失败，不创建成功准备记录。环境齐备后才执行[原生准备](MC原生应用profile与准备.md)；生存preLaunch拒绝及D03/D04门槛继续独立执行。

## 4. 包检查与失败处理

ZIP索引分配前核对原始目录尾、条目数和归档大小；清单、单文件和总解包字节数分别限额。只接受无加密的普通文件及指定压缩格式，拒绝ZIP64/注释/多卷、目录/链接/设备成员、重复成员、重复JSON键和大小/摘要不符。

路径必须属于公共范围；拒绝目录穿越、绝对路径、Windows盘符/数据流、反斜杠、设备保留名、尾点/空格与大小写别名碰撞。实际路径拒绝符号链接及junction。临时目录有本次随机归属标记，只清理归属仍可确认的本次目录；被替换或无法确认的路径保留并报错。

导出前后重新核对源码；安装前后对同一打开的归档句柄重新计算整包摘要。导出采用同目录不覆盖发布，安装采用Windows不覆盖的目录改名。普通中途失败清理本次临时内容并保留旧目录及旁路文件。断电或文件系统错误后的孤立目录不能当作有效安装，须先核对归属及证据。
