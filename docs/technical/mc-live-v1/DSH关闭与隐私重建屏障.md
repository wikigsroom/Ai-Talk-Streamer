第064轮，mc分支。补齐公开回应、游戏规划、观众理解、私聊和维护共用模型队列的关闭过程，衔接[原生持续监督](原生运行持续监督与故障回收.md)。完整系统继续按[实施总纲](13-完整方案实施总纲.md)和[全部待办](实现进度.md)交付；本轮不代表真实模型、MC或官方节目已验收。

## 1. 触发问题与最终行为

原宿主close直接处置当时active中的会话，再刷新Humanity和释放框架；没有统一撤销所有已受理用途及队列等待。修改前检查已复现：关闭完成后，正在运行的模型用途仍未收到取消。

当前[host.mjs](../../../backend/dsh-bridge/host.mjs)按以下顺序关闭：

1. stopAdmission立即标记停止接收、ready=false，撤销本宿主所有已受理调用的共同信号。
2. 队列等待、当前调用及工具获得合并信号；已撤销等待项不得进入模型适配器。
3. quiesce等待所有已受理generate的finally，包括SDK会话dispose及临时理解会话清理，再等待模型队列结束。
4. 检查active为空；随后close刷新Humanity，再释放框架fiber。

取消后的用途返回MODEL_CANCELLED。停止接收后的新调用返回DSH_HOST_CLOSING；旧宿主实例不能再次start，隐私重建使用新实例。公开回应抢占未完成规划及理解的既有优先规则保持；已获准的MC动作仍由游戏任务、租约及停止过程负责。

## 2. 关闭期限、重试与所有权

| 项目 | 实现与边界 |
|---|---|
| 受理记录 | 五种用途都登记finished，finally后移除；不只检查已创建SDK会话 |
| 排空期限 | 默认10秒，只约束模型调用排空；等待时保留唯一写入者 |
| 不合作调用 | 到期返回DSH_HOST_DRAIN_TIMEOUT，不提前flush或释放fiber；停止接收状态不恢复 |
| 排空未证明 | 仍有未跟踪active会话时返回DSH_HOST_DRAIN_INCOMPLETE，不强行重复dispose |
| 关闭并发 | 并发close共享同一完成Promise；已成功关闭不重复flush或dispose |
| 失败重试 | 排空、flush或dispose失败允许再试；已成功flush不因后续dispose失败而重复 |
| 有限错误 | flush/dispose未知异常投影DSH_HOST_CLOSE_FAILED，不把异常原文或路径返回调用端 |

10秒不是整个程序停服上限。Humanity刷新、框架释放、其他后台任务和实际GPU资源还需全栈故障验收；不合作回调也不会被JavaScript强制终止。原生入口与Job监督继续负责进程归属和异常回收，不能把服务响应、模型取消或关闭请求受理当成整台设备已回收。

## 3. 隐私重建与服务入口

[server.mjs](../../../backend/dsh-bridge/server.mjs)的restartHostForPrivacy先等待旧宿主quiesce，再列出会话、关闭旧宿主、执行原清理并创建新宿主。原先仅轮询active最多5秒，不能证明排队工作或最终清理完成；现在不会在模型用途仍可创建会话时采集待清理列表。

Bridge关闭先停止模型受理、撤销请求，再关闭游戏、Room、平台和宿主；宿主成功关闭后才关闭HTTP与业务数据库。并发调用等待同一关闭Promise，失败不再被closed布尔值伪装成第二次成功；数据库在宿主失败时保留归属。信号及HTTP异步关闭记录有限的bridge.shutdown_failed错误。

关闭期间普通业务HTTP返回503 BRIDGE_STOPPING，health仍可查询；关闭重试入口保留。POST /api/dsh/shutdown仍要求当前没有开播会话，直播中继续返回SHUTDOWN_REQUIRES_OFFAIR。没有增加应用登录或鉴权要求，也没有自动重启模型、切换DSH状态或开始公开推流。

## 6. 065：业务收尾与延迟启动隔离

原HTTP处理器可能正在等待人格发布或记忆投影，宿主close却已刷新并释放其连接器。065在实际HTTP/SQLite检查中复现了人格发布尚未完成、host.close已执行的顺序；完整安装复测同时暴露出旧夹具只借用单个Bridge方法，缺少新生命周期原型。原顺序失败、GameStore分页结果误判和两次夹具不完整的安装失败均保留在[065证据](../../evidence/mc-runtime-round-065.json)，最终成功不删除失败记录。

StreamBridge现在登记实际已受理的HTTP处理、启动、游戏延迟加载、隐私重建、公开口播、媒体命令，以及由Bridge定时器发出的维护和记忆投影。游戏调度器的观众理解和规划在正式Bridge下也加入同一登记；登记以实际Promise的finally完成为准。它不把模型返回或取消信号本身当成业务收尾。

关闭顺序如下：

1. 关闭新业务准入和定时调度，撤销模型调用及公开回应；游戏立即取消规划/理解并断开连接、清空本地租约，停止继续发放自动输入。
2. 保持业务存储和旧宿主，等待已登记请求的提交/失败处理、投影回执和媒体命令结束；收尾中产生的取消命令也纳入等待。
3. 登记归零后封住额外取消命令，关闭游戏、Room和平台组件，再关闭DSH宿主和HTTP监听，最后释放主数据库。

业务等待默认10秒，可在内部检查中设1–60000毫秒；超时返回BRIDGE_WORK_DRAIN_TIMEOUT，保留存储及宿主以便工作实际结束后重试，不重新开放业务。该期限与064模型用途的10秒排空独立，不能推导整个应用必定在10秒或20秒内退出；平台、网络、磁盘和其他组件仍有各自收尾条件。

关闭后才完成读取的普通写请求返回503：Bridge、Room及平台在读完请求体后再次核对；游戏配置和任务路由重查关闭准入。健康接口返回停止状态，不再发起媒体探测。离播shutdown重试入口和开播拒绝关闭规则保持。

延迟游戏导入返回时先检查关闭标记，不能再构建服务。隐私重建每个关键等待后检查关闭；若新宿主已经开始启动，它先登记为当前拥有实例，关闭过程等待启动返回并收回它，不能重新发布ready。正常初次启动同样受登记和这些等待后的检查约束。
