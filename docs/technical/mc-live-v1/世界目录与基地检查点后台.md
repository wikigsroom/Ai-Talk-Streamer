本说明记录同一完整版本中的世界管理实现，不构成独立交付。第014轮已完成服务端及本地浏览器检查；真实MC、完整历史投影、次日恢复和最终联合验收仍未通过。

## 1. 两种世界上下文

顶部状态始终表示实际MC当前世界、会话、控制模式、连接和观测年龄。目录选择表示后台正在浏览的稳定世界，不执行世界加载、传送、控制切换或任务派发。

| 场景 | 显示及操作 |
|---|---|
| 默认进入 | 跟随实际当前世界；目录中保留当前世界入口，即使它不在首批目录结果内 |
| 主动选择历史世界 | 会话、目标、任务、基地、检查点按所选world_id查询；页头仍显示实际MC状态 |
| 自动刷新或SSE变化 | 保留主动选择；不把历史视图悄悄跳回当前世界 |
| 同一标签页重新加载 | sessionStorage保留所选稳定world_id；其他标签页不共享选择 |
| 返回当前世界 | 清除浏览选择并重新跟随实际状态，不启动游戏自动控制 |
| 保存的世界已不存在 | 显示不可读取和返回当前世界入口；仍保留可取得的实际MC状态，不伪造空世界 |

历史视图禁用AUTO授权、新目标、基地及检查点创建；观众建议和投票不混入其他世界的页面。紧急停控与人工模式仍针对实际MC，界面明确该作用对象。实际当前世界变化时，历史浏览选择继续保留。

## 2. 服务端接口与作用范围

接口前缀及完整请求体以[OpenAPI](contracts/openapi.json)为准。GET `/tasks?world_id=…`新增稳定世界筛选，跨同一世界的不同会话取历史；不传world_id保留原全局查询。空值、非法标识和未登记世界不降级为全局列表。数据库以绑定参数过滤JSON中的world_id，游标、limit和排序语义保留。

| 操作 | 服务端条件及实际效果 |
|---|---|
| 世界标签修改 | 世界revision CAS及幂等；允许离线维护标签，不创建游戏命令 |
| 登记基地 | 当前新鲜世界/boot/会话、非AUTO、输入已释放、gameplay界面、世界revision；使用实际观测坐标，登记后设为活动基地 |
| 选择活动基地 | 新鲜当前上下文、非AUTO、输入已释放、无automation_ready、租约及活动任务；同时核对世界和基地revision，拒绝已归档基地；仅更新活动基地引用和世界revision |
| 归档基地 | 现有接口核对世界和基地revision、非AUTO且无活动任务；标记归档，若为活动基地则清除引用。该旧接口不宣称具有选择接口的全部上下文门槛 |
| 创建检查点 | 当前新鲜上下文、非AUTO、输入释放；不允许普通活动任务，保留已有恢复场景的检查点记录条件；保存观测与任务/基地引用 |
| 查看检查点 | 展示持久记录的原世界、会话、观测及引用；不发起游戏执行 |

后台比旧归档接口更严格：仅当前新鲜世界停控后开放基地操作，并受正在提交和同步状态约束。服务端仍独立执行其契约校验，不依赖按钮禁用保证正确性。

选择基地使用BaseSelectRequest，包含原上下文、request_id、expected_world_revision及expected_revision。同一请求重复返回已有账本结果；相同幂等键换正文拒绝。更新与幂等记录、审计在同一数据库事务中提交，随后发布world事件。选择不发送移动、导航、按键或控制命令；真正回基地仍须独立任务、许可和效果核验。

## 3. 表单、分页和迟到响应

世界目录、任务、基地和检查点使用有界分页。当前及主动选中的世界保留可选入口；展开后刷新已有页，不能因后台周期刷新丢掉用户已经加载的任务。世界切换清空旧作用域数据与游标，重新读取目标世界，不临时显示另一世界的任务行。

所有作用域请求绑定视图代次。旧世界的成功返回和失败返回均不得覆盖新视图、清除实际状态或显示过时失败。当前查询失败时，保留已成功读取的实际MC状态，作用域内容标为待确认。SSE断开或当前刷新失败时，全体游戏写按钮立即重算；缓存的connected字段不能冒充后台仍已同步。

表单打开时保存世界、会话及revision快照；另一个操作者修改后，提交旧表单收到冲突，重新读取并由操作者决定，不能自动以新revision覆盖。切换世界关闭旧作用域表单。提交期间禁用重复操作；取消及Escape关闭后焦点回到触发入口。所有标签、任务和详情使用纯文本渲染。

## 4. 检查点与备份的边界

检查点是账本中的不可变观测快照，包含世界/会话/bridge身份、快照和任务、基地引用。页面提供创建及查看，没有存档恢复按钮。它不保存MC世界文件、不证明服务器落盘、不撤销游戏动作，也不恢复键鼠或未知任务。

真正恢复仍按[部署与故障恢复](06-部署与故障恢复.md)执行：停控并确认释放、保存一致备份、核对源码/设备/数据库版本和删除账本、核对MC世界与B任务，再由操作者决定续接。B完整历史向A投影、保留清理、Humanity删除以及联合备份/次日恢复属于同一最终版本的剩余工作。
