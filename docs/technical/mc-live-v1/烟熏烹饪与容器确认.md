## 1. 资源与配方

实际CollectFoodTask选择ControlledCookingTask，保留尚未结束的烹饪/燃料子任务，包括紧急链打断后的续接。驱动在上游调度前检查原上下文和期限；FoodChain在烹饪未清理时保留优先级，防止普通进食/装备进入同一容器事务。

使用当前客户端收到的SMOKING配方和实际原料组件。每次复核当前首个匹配配方仍是捕获的同一个配方对象，且输出组件、数量和安全食物属性相符；配方重载、输出或世界/玩家/连接变化停止任务。当前每次处理一个原料和一个输出，配方时长1–120游戏刻，熟食营养须高于原料。

选择原行为保护之外的材料，燃料限普通组件的煤/木炭，每次最多放入一个。缺燃料通过原资源树取得有限目标，仍受同次补给预算约束；不解禁受保护材料。完整材料预留及动态冲突恢复继续待完成。

食物潜力是实际安全库存加烟熏配方营养增量；普通小麦/干草只折算一次整份面包，移除旧函数的重复累加。额外组件的小麦/干草不套用普通转换估算。潜力只用于选路，不能当作熟食到手；完整数据包面包配方与其余加工链仍待完成。

## 2. 容器与确认

只接纳本任务实际交互请求打开的烟熏炉。GUI许可绑定原任务、世界、玩家、炉子位置及方块实体、具体屏幕、handler和sync ID；其他炉子、手动页面、已替换方块实体和迟到响应不能继承许可。初始物品状态必须来自服务器完整库存包，且与当前handler相同。

开始时炉子的原料、燃料、输出和光标均须为空，预检熟食回收空间；不会清空已有炉子、丢弃物品或代用其他组件腾地方。原资源树负责找到或准备烟熏炉，制炉、建筑、燃料获取与全部容器效果仍待闭合。

1. 从已选堆栈移入一个原料，其余原料收回原槽。
2. 如余热尚未完成加工，移入最多一个燃料并归还其余燃料。
3. 等待服务器确认原料消耗和确切熟食产生，允许分包及不同顺序；单条输出更新不能构成转换完成。
4. 收取熟食到玩家库存，收回未耗用燃料；每次搬运均等待完整确认。
5. 三槽和光标确认清空后关闭本任务GUI，然后补给才能结束或开始下一份加工。

每次PICKUP使用精确组件令牌和完整槽位/光标预期状态，至多一个待确认操作。专用revision钩子向原版服务器请求完整状态同步；本地点击预测不构成确认，超时不重发。仅允许本次原料、单个燃料消耗与单个熟食产生；其他数量、组件、光标或库存变化停止任务。

真实InventorySyncMixin在原版应用库存包后，经McBridgeClient、MinecraftPort向原执行器传递完整库存和单槽事实。回调只记录事实，不获得写权限；原任务、世界、玩家、连接、handler与撤权检查保留。单槽包不能确认一次点击；15位revision回绕可用，旧确认不能推进事务。
