# 同玩家直接交互绑定

适用`mc`分支，039–041。属于[完整总纲](13-完整方案实施总纲.md)的D03/D04，与[输入协议](02-游戏桥与控制协议.md)、[同玩家执行器](真实玩家执行器接入与效果核验.md)共同阅读。真实MC、生存任务树和物理接管仍须统一验收，生存工程的preLaunch无条件拒绝保持。

## 1. 真实对象与输入作用域

`InputOwner.Scope`创建时捕获实际world、player、network handler和interaction manager四个对象，`NativeContext`按对象身份核对。世界名称、玩家资料或连接参数相同，均不能替代原对象。每次`current()`还核对输入代次、玩家存活、焦点和暂停状态；`ArbiterBoundary.actuate`在原Permit保护范围内执行核对。

GUI handler不固定在这四个对象中：任务打开背包或工作台会合法更换handler，应由已有`TaskGuiLease`独立核对。输入释放继续使用原代次，不要求旧世界仍在线；过期清理不能释放新代次。这层绑定补充已有任务/世界会话/epoch/租约及时效，不创建新的控制权。

## 2. 固定直接交互入口

`gate-policy.json`中13个固定方法签名接入11种`action_*`入口，源码主工程与嵌入Baritone分别按named/intermediary处理。离线编译器保留参数和返回类型；策略拒绝错误动作签名，编译器拒绝静态调用冒充实例方法和直接方法句柄绕过。

| 入口 | 实际核对与处理 |
|---|---|
| yaw / pitch | 当前真实玩家；角度有限，pitch在[-90,90] |
| sprint / swing | 当前真实玩家、有效手及原任务许可 |
| attackBlock / breakProgress | 实际manager、合法高度、世界边界、已加载区块及MC自身方块交互距离 |
| attackEntity | 同一世界/ID的真实实体，存活且未移除，MC交互距离和视线，可受攻击；不攻击玩家 |
| interactEntity | 同一真实实体、原玩家/manager、有效手、距离和视线；玩家不作为此普通PvE入口目标 |
| interactItem | 原玩家/manager、有效手、正常游戏界面；实际调用原生交互 |
| cancelBreaking / stopUsing | 只处理本任务记录过的持续交互；无记录时不取消操作者动作 |

实际动作在`SurvivalAuthority.write/effect`内重新核对原任务许可和真实输入作用域，再调用MC。非GUI动作要求正常游戏界面；交易或其他容器仍遵循既有GUI停止规则，不取得容器写权限。

boolean/ActionResult仅是原生即时结果，不证明服务器完成了挖掘、伤害、使用或采集。任务仍由既有`ExecutorTaskSession`核对更新事实和效果；公开能力不会由这些内部绑定直接变成`basic_pve=true`或完整资源链可用。

## 3. 交互归属与清理

`InteractionLedger`分别记录本根任务发起的挖掘和物品使用。调用前先记录；原调用抛错或即时返回否，均不能推定未开始。合法停止失败保留该项记录，直到后续停止或撤权清理；不自动重发原操作。

自然完成时，`ControlledAltoClefDriver.beforeComplete`在原许可有效时先处理已记录交互，再关闭自己的空光标GUI，最后交给既有效果核验。失权后，树清理只丢弃原任务记录，不发送取消交互的游戏包，避免取消物理操作者的新动作；合成键仍由原输入账本释放。

撤权后的真实挖掘/使用恢复、服务器收包顺序和接管延迟尚须实机验证。记录清空不代表服务器已经停止，失败清理也不能记为正常完成。

## 4. 证据与完整剩余范围

构建器检查策略摘要、源/产物对应、实际路由、原生类和嵌入资源。检查包括对象更换但旧Permit仍新鲜、断开后的原代次释放、动作开始后抛错、撤权后不写、固定MC方法签名及编译产物接线。它们使用原生JVM和真实版本字节码，不启动MC；具体结果由[实现进度](实现进度.md)及当轮证据登记。

039覆盖上游直接调用。040补入下节的原生持续按键入口；实际Mixin应用、间接网络包、反射/选项、其他容器、全部异步回调及清理仍须完整核对。普通PvE目标选择、战斗/补给/危险和全资源链效果也仍须完成。原静态扫描继续保留全部UNREVIEWED行，选定入口数不代表全部写点覆盖率。

完整交付仍覆盖D01–D15、两套100段新人物及68项真实验收；本轮不改变冻结横屏布局、唯一DSH/Humanity、K02/O07/F07或设备约束。

## 5. 持续按键进入同一个任务（040）

采集和进食不止发生在执行器调用的瞬间：合成键保持后，MC会在后续游戏循环再次进入攻击、挖掘或使用方法。`HeldInputMixin`完整包裹固定MC版本的`doAttack()`、`handleBlockBreaking(boolean)`和`doItemUse()`，通过`McBridgeClient → MinecraftPort → HeldActionRouter → ClientExecutor → ControlledAltoClefDriver → ControlledTaskRunner.effect`重新进入原根任务；不从当前AUTO状态领取替代许可。

`InputOwner`按自己的合成键账本区分来源。非本适配器持有的物理输入沿原生路径运行；本任务持有的攻击/使用键，必须由仍活动、未进入完成/关闭状态的原根执行。原Permit、输入代次、真实四对象、游戏主线程、焦点和界面条件均在实际调用前核对；更换世界或撤权后的新授权不能复活旧根。原生调用即时返回值保留，异常后的动作不自动重放。

在原许可内，`SurvivalActions.vanilla`核对当前真实准星目标、距离/视线及玩家排除，并在动作前记入同一个交互记录。使用键的工作台预检集中在该入口，第一下点击与持续使用共用一次预检，避免重复预检把合法首次开台误认为已在等待。专用`use_item`事务已直接发起一次物品交互，仍持有的使用键不再驱动原生重复使用。

三个固定方法的签名、Mixin声明/映射、实际桥与执行器接线及原根生命周期均有离线检查。它们不证明真实MC已应用Mixin，也不证明服务端停手、普通PvE策略、补给/资源链或整场节目已验收；这些继续属于统一真实验收范围。

## 6. 实体防御节奏与有限追击（041）

实体攻击增加本根共用的原生冷却与每个玩家age刻一次的尝试记录。上游距离预检改用实际MC距离、视线和实体身份；具体防御、风险/追击/撤离期限、被其他生存链抢占时的检查、原采集恢复及固定失败原因见[普通PvE专项](普通PvE防御与有限撤离.md)。原实体/玩家和原Permit约束仍在实际写入前核对，不形成新的公开技能或服务端击杀证明。
