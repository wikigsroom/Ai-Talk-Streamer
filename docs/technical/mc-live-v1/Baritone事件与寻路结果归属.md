# Baritone事件、输入对象与寻路结果归属

对应完整发布内部第012轮、D03–D04及D14。[完整交付规划](08-完整交付规划.md)的15域、68项、4小时、次日恢复及100段新人物范围保持不变。本轮接通候选执行器的事件与结果归属；MinecraftPort尚未发布完整生存能力，候选仍无条件拒绝preLaunch，不能安装运行。

## 1. 固定输入与转换

继续使用构建锁中固定的Baritone1.21.1二进制、AltoClef源提交及Yarn映射。离线编译器只转换GameEventHandler、PlayerMovementInput、PathingBehavior三个精确类，检查既定方法签名、计算调用、结果局部变量和异常处理边界；发现形状改变或重复转换即拒绝。全部原始类、转换类和最终包均按hash核对。

新增23项生命周期转换与已有37+50处选定副作用门禁分别记录，不能将两者相加当作完整覆盖。事件/输入/路径转换为17/3/3项。受控寻路模块提升为dev.aitalkstreamer.pinned:baritone-controlled:1.21.1-ats.2，避免继续解析旧组件；版本、JAR、POM和依赖锁同步。原始编译依赖保持固定，原生桥API没有复制第二份仲裁器。

## 2. 事件入口

实际驱动在原任务的准备作用域中显式绑定主Baritone事件对象，关闭时注销。分发只使用该对象的绑定，不在回调发生时从全局临时取得新任务。它用于本机玩家线程的原生同步事件；工作线程不能因此获得输入权限。

| 路由 | 方法 | 行为 |
|---|---|---|
| 原任务事件 | onTick、onPostTick、onPlayerUpdate、onPlayerRotationMove、onPlayerSprintState、onPathEvent、onBlockInteract、onPlayerDeath、onSendPacket、onReceivePacket | 原任务、原客户端线程和原许可均有效才执行；异常撤销该根，并由实际任务运行器接收错误和清理 |
| 无任务权限的观察 | onChunkEvent、onBlockChange、onWorldEvent、onRenderPass | 保留世界/区块/渲染维护，清除发布者的任务作用域，结束或异常后恢复 |
| 禁用原生命令入口 | onSendChatMessage、onPreTabComplete | 不解析Baritone聊天命令和补全，不产生绕过任务受理的执行入口 |
| 任务监听器 | registerEventListener | 任务内注册的监听器捕获原Session，关闭时立即移除；保留的旧代理也不能借用下一任务。启动期监听器继续保留；撤权清理和后台计算不能注册永久监听器，AltoClef事件总线遵守同一限制 |

来自非客户端线程的可操作事件当前跳过。不能把任意网络事件缓存后延迟重放，因为其中对象可能有线程或释放期限。真实网络事件所属线程、世界维护完整性和其他副作用仍须实机与源码分类验证。本机制不是任意第三方Mod的执行沙箱。

## 3. 输入对象

PlayerMovementInput在构造时保存不可变Binding，包含原Session和自身对象身份。后续tick不根据事件总线的新绑定改换主人。有效时进入原任务作用域，继续使用逐次门禁；失效或执行失败时，在原客户端线程把该对象的8项移动/跳跃/潜行字段清零，防止旧值继续被消费。

清零只作用于这个原对象，不创建新许可、不操作其他输入对象，也不释放人工持键。原键盘输入和移动对象恢复仍由[桥端InputOwner及原代次](任务收尾与事件订阅.md)负责。工作线程不能写入或清零输入对象。真实改键、扫描码、物理输入和Minecraft消费时序仍待验收。

## 4. 工作线程计算与客户端应用

固定PathingBehavior.findPathInNewThread中的一处Executor提交捕获原Session。编译器把既定工作lambda拆成两部分：工作线程执行原calculate；原有路径选择、路径执行器创建、状态更新及锁/异常处理移入客户端结果应用方法。工作线程只有计算来源标记，没有游戏操作作用域。

结果进入原任务的有界队列，实际任务tick或绑定事件在客户端线程消费。关闭、撤权、世界/租约失效后的结果不能进入新根。应用前还要求inProgress与原计算对象为同一实例，避免同一根重新寻路后，旧计算覆盖或清除新计算。

启动和关闭均清空原PathingBehavior的待分发路径事件队列，避免上一任务留下的完成/取消通知进入下一任务。清空入口要求原owner作用域，允许撤权后的状态清理，不能用于重新授权游戏操作。

## 5. 失败、预算与锁顺序

每根最多8项在途计算、64项待应用结果。拒绝提交会返还预算；重复交付同一个执行封套只计算一次。线程错误、计算异常和结果溢出保留首个异常并撤销原根。运行器在检查根是否仍有效之前读取异步错误，因此撤权不会把错误吞成无原因的结束；所有原收尾步骤继续尝试。

检查原生仲裁器时不持有结果队列的锁。客户端接管可能已持有仲裁器并关闭队列，反向持锁会产生互等。新增检查实际阻塞工作线程于ControlArbiter，并通过ThreadMXBean确认它没有同时持有结果队列监视器。关闭只丢弃本根结果，不中断共享线程池的其他工作。

## 6. 本轮检查范围

107项生存JVM检查和14项Python准备检查在本轮执行，共121项不同本地检查。检查包含固定真实命名类转换后的JVM校验、保留原异常处理结构、转换幂等拒绝、原输入/监听器归属、撤权清理及后台计算拒绝永久注册、有界队列与清理，以及锁监视器状态。最终构建实际重跑全部107项生存检查；原生桥86项和Java↔Node11项沿用第011轮同源核对结果，不计入本轮执行数量。

独立可执行夹具使用明确伪造的API类型，不加载真实Minecraft客户端。它实际执行转换后的计算lambda和结果应用方法，验证工作线程与客户端分离、只应用一次、同根新计算身份、任务关闭丢弃及原事件队列清空。真实类的加载校验与夹具效果检查不是Minecraft生存或物理输入验收。

原生桥86项与Java↔Node11项沿用第011轮同源结果，本轮没有冒充重新执行。最终包、输入/输出hash、失败记录和缓存/执行区分见[第012轮证据](../../evidence/mc-runtime-round-012.json)与[实现进度](实现进度.md)。
