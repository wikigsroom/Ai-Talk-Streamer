## 1. 实际执行路径

| 顺序 | 处理 |
|---|---|
| 1 | 实际Task.tick捕获直接子树抛出的Json.Rejected，交给本任务的onChildFailure；默认拒绝处理 |
| 2 | ControlledRecipeResourcesTask只接受自己的当前子任务，并核对原会话、世界、玩家和连接 |
| 3 | 检查固定材料原因、原权限、全部相关库存事务、使用状态及实际GUI归属和空闲状态 |
| 4 | 停止失败子树，作废旧代寻路结果，取消路径并清理原任务持有的按键、交互和空界面 |
| 5 | 保存来源、失败前后库存指纹和原因；释放该次声明，保留原根的其他声明及失败记忆 |
| 6 | 等旧计算实际退出、结果队列清空后，重新计算缺料并选择备用来源 |

子任务停止完成前，Task不会脱离该子树。清理失败保留原异常为suppressed原因并沿原根失败路径结束，不带着未完成清理启动另一分支。内部节点耗尽全部来源时，既有材料错误可继续传到外层采集节点，由外层选择其他来源，因此支持跨多层失败子树回溯。

工厂创建任务时的同类固定失败也进入同一清理和记录路径。它每次失败后让出当前tick，等待实际计算退出再作下一次选择；没有重建原执行根、更新授权或重置截止时间。工厂返回null仍沿用既有无进展处理。

## 2. 可回溯原因和明确边界

只接受以下10项固定规划或来源原因：

| 原因 | 含义 |
|---|---|
| GAME_CRAFT_MATERIALS_MISSING | 当前配方缺少可用材料 |
| GAME_CRAFT_RECIPE_UNAVAILABLE | 当前来源没有可用配方 |
| GAME_CRAFT_RECIPE_AMBIGUOUS | 当前来源无法唯一确定配方 |
| GAME_RESOURCE_CRAFT_MATERIALS_UNAVAILABLE | 资源合成材料来源未满足 |
| GAME_RESOURCE_MATERIAL_CYCLE | 实际祖先路径存在未取得进展的循环 |
| GAME_RESOURCE_MATERIAL_NO_PROGRESS | 当前来源未取得所需材料 |
| GAME_RESOURCE_MATERIAL_UNAVAILABLE | 当前材料来源不可用 |
| GAME_RESOURCE_MATERIAL_UNCATALOGUED | 当前材料缺少登记来源 |
| GAME_RESOURCE_SMELTING_FUEL_UNAVAILABLE | 当前熔炼来源无法准备适用燃料 |
| GAME_RESOURCE_SMELTING_RECIPE_UNSUPPORTED | 当前熔炼来源超出现有配方支持条件 |

服务器超时/分歧、库存事务、组件或上下文变化、GUI归属变化、撤权、预算耗尽、任意异常及Error不自动回溯。包装异常中的原因文字不用于猜测是否可恢复。原任务已获得的部分物品按当前事实保留，不把分支失败改写为根任务成功，也不重放已经提交的任务。

后台与主播继续使用原81项固定材料/合成/烹饪解释。运行中的原任务不会因为内部选择了另一来源而获得伪造的终态；最终仍由既有任务、效果和证据通道报告。

## 3. 清理前提和库存

回溯时不能有活跃的确认合成、烹饪、食物准备、进食、装备或盾牌事务。光标必须为空，玩家不能正在使用物品。没有界面时须回到实际玩家handler，且没有仍等待打开的任务界面。

已打开界面必须属于原任务。背包和工作台的合成格及结果格都要为空；炉具的输入、燃料和结果格都要为空，并且已有该实际handler的完整服务器库存快照，快照中的光标和三个炉具格也必须为空。这样不会把等待首包的空白预测界面当成已清理，也不把留在炉具里的原料当成不存在。

这里只处理已支持的实际界面和既有消费者。通用容器的完整事务、全部迟到包和服务端变化仍须补齐并实机验证；本地空闲检查不构成所有服务器效果已经确定的证明。

## 4. 计算代次与真实等待

每个原根的SurvivalAsync状态增加generation。提交时捕获该代次，工作线程和返回队列都携带它。失败分支停止后先递增代次，再取消路径及清理原事件；旧任务尚未开始则不计算，已经开始则可结束，但其结果和后续计算异常不能覆盖或撤销新分支。

当前代计算的真实异常继续撤销原根。已经记录的当前代异常不能通过作废代次隐藏。排队结果最多64项、并发计算最多8项的原预算保持；作废代次清理结果队列，但不把仍在运行或等待投递的旧工作从并发计数中抹掉。

采集器进入settling状态，读取真实jobs和pending计数；两者清零才选择新来源。等待不创建新任务、耗用新选择或续期，原根仍受原截止时间和撤权规则约束。中断后的恢复保留该等待状态。

此代次用于已接入的寻路计算与结果队列；所有其他上游线程/回调及正常任务切换的完整审计继续列在D03，不能由本轮检查宣称全覆盖。

## 5. 有界失败记忆

失败按实际来源及数量指纹保存，最多512条。登记前同时计算失败前、失败后两个指纹的容量，检查通过才一起提交。同一指纹保留已有原因，不因后续较笼统的无进展覆盖原先失败。

库存确实改变后可以重新规划；同一来源后来正常取得材料，清除该来源的旧失败记录。停止单个节点只释放自己的活跃声明，原根清理才清除全部记录。64个活跃获取声明及原根256次来源选择上限继续生效。
