## 1. 同时分配预留和实际消耗

ResourceMaterialsPlan.singleUnits接收每个消费者真正允许的库存槽位，先保留现有目标成品，再将所有单位需求一起交给MaterialAllocation。配方、组件、普通燃料、保护状态等由原生入口核对，分配器只能使用入口允许的槽位。

例如槽0有普通煤、槽1有自定义煤、槽2有原料，而原任务需要保留一块煤。旧的先预留再逐槽选择可能保留槽0，留下不能燃烧的槽1。现行分配可将保留额度移到槽1，再选择槽0作燃料。物品总目标仍按原契约计数，不能借此将自定义煤当成普通燃料。

| 情况 | 必须满足的结果 |
|---|---|
| 同一堆栈兼作原料和燃料 | 必须有两份可消耗单位；预留的一份不参与转换 |
| 原料要求更严格、燃料可选多个槽 | 调整虚拟分配，为严格原料保留唯一匹配槽 |
| 任何一个消费者缺料 | 不返回部分消耗选择，继续既有采集或失败路径 |
| 成品尚不存在 | 不用未来成品占住无关材料 |
| 仅需统计可用食材 | usable在保留成品的同时最大化允许槽位的可用数量 |

每次最多64个单位消费者，沿用36个主背包槽、640个要求和200万步分配上限。分配不点击界面、不搬物品、不改变原任务额度，也不重新授权。所有容量重新读取同一原根的当前库存和活跃声明。

## 2. 实际消耗入口

| 入口 | 现行衔接 |
|---|---|
| ControlledSmeltingTask | 原料与燃料同时分配，仍核对当前配方、具体组件、普通专用燃料和足够燃烧时长 |
| ControlledFoodCookingTask | 补给烟熏准备和补料；原料与煤/木炭同时分配 |
| ControlledEatingTask | 选择食物时检查容量；装备回包确认后、真正使用前再次检查当前手持槽容量 |
| FoodChain.calculateFood | 使用可消耗主背包堆栈副本及准确数量，保留既有食物评分和实际物品使用条件 |
| ControlledCookingTask.foodPotential | 潜在加工只计未保护、可分配的原料；小麦/干草与直接烟熏走单一路径，避免重复计算 |

补给的库存目标继续统计实际已拥有的安全食物。它与“允许现在吃掉多少”是不同事实，保留原先防止受保护目标食物导致反复补给的规则；没有将消费分数零改写为库存不存在。潜在加工量只供既有有限收集树规划，不是服务器产物或成功证明。

## 3. 补给炉具准备与转换

ControlledCookingTask.select现在创建原任务内的ControlledFoodCookingTask。它固定原世界、玩家、连接、原配方对象、原料组件、实际输出及补给目标；通过已有ControlledRecipeResourcesTask补料，保留来源切换、祖先循环判断及原根256次选择预算，不另起公开任务或控制器。

准备任务先备齐原料和煤/木炭，再制作/放置/打开烟熏炉。炉具打开后丢弃旧采集器的完成判断，重查现有原料和燃料；如制作耗料，则关闭自有空炉具后再补料，避免把旧采集器直接恢复到已打开的炉具内。普通熔炉、高炉及资源烟熏也应用同一耗料后重选修正。

只有原界面的完整服务器初始库存包就绪，才创建真正的ControlledCookingTask并固定转换槽位。转换仍逐次核验实际组件、数量、产物、回收余料及空光标；原补给8000ms加工期限、120秒补给总期限、45秒无新高及96格范围保持不变。

## 4. 调度、中断和清理

实际Task/SingleTaskChain沿原祖先路径保留准备任务；FoodChain在准备或其燃料子任务运行时保留原补给链。CollectFoodTask和ControlledSupplyTask等待准备、转换及装备/进食清理后才完成，驱动检查继续核对原配方、原会话及期限。

停止准备任务不关闭界面、不移动库存、不发停止包；暂停保留原实例和已有子任务。原根撤权后的状态清理由同一所有者回调处理，不借新许可恢复旧动作。后台与DSH继续使用现有80项固定材料/合成/烹饪原因，部分效果、原编号和无重放规则不变。

## 5. 验证、复用和未完成边界

本轮实际执行602项生存检查及7项固定原因检查，共609项，新增27项。17项容量检查包含两项独立穷举：15552种小库存/候选/保留组合核对可行性，1944种组合核对最大可用量；这些组合属于测试内部枚举，不额外计作独立用例。另10项检查读取实际编译类，覆盖消费入口、装备后复查、炉具准备、原任务保留、初始服务器包、补给完成条件和无副作用停止。

此前332项桥、39项互通、119项其他Node和5项Python HTTP结果仅在对应源码及产物未变后沿用，共495项；未声称本轮再次执行。当前验证并集1104项，不代表全应用回归或实机通过。当前119项受控源补丁，15050项静态清单仍全部UNREVIEWED；候选preLaunch继续无条件拒绝，basic_pve/survival_rules/resource_chains仍为false。未启动浏览器、真实MC、模型或官方客户端。

现行联合分配贯通上述选定消耗入口，尚未覆盖所有放置、容器、工具及其他消费者；替代成品集合仍保守按物品种类预留。全部消费者的全局依赖、回溯、最小预留、完整普通生存/PvE、应用与媒体素材及全部68项真实验收继续保留。
