# 热栏输入归属、同玩家通知与失败恢复

日期2026-10-31（Asia/Taipei）。对应实现记录031，属于完整发布的D03/D04与D14。全部范围仍见[一次完整交付总计划](12-一次完整交付总计划.md)。本文说明同玩家热栏写入的本地实现与工程验证边界；真实键鼠、客户端/服务器和普通生存联合验收继续待完成。

## 1. 已有缺口与统一入口

原候选对AltoClef与Baritone的selectedSlot字段写入做了逐次权限检查，但这些直接赋值没有登记原选中槽，因此换工具或采集后的任务收尾无法依靠桥端输入账本恢复。固定输入中的位置为AltoClef源码2处和Baritone字节码7处；这是选定字段的9条写入，不是全部游戏副作用覆盖数。

现有[gate-policy](../../../game-adapters/minecraft/survival/gate-policy.json)将该字段标为select转发。原任务Session、不可变Permit与输入代次依次通过SurvivalInputs、ArbiterBoundary和InputOwner.Scope，最终在原ControlArbiter临界区核对实际PlayerInventory身份、槽位0–8及当前玩家/世界/连接。外部传来的其他背包不能作为当前玩家写入。

同一InputOwner也用于原生eat/equip/activate任务，热栏选择与收尾共用[HotbarSelection](../../../game-adapters/minecraft/fabric/src/main/java/dev/aitalkstreamer/mc/core/HotbarSelection.java)，不会另建第二套合成输入或第二个游戏角色。

## 2. 本地字段与服务器通知

一次选择先记录原槽，再写本地字段，并经捕获的同一ClientPlayNetworkHandler发送原版UpdateSelectedSlotC2SPacket。连续选择保留第一次记录的原槽。收尾只在当前槽仍属于本记录且原玩家/世界/连接仍有效时恢复，并尝试通知同一连接。

网络发送成功返回只说明调用已完成，不证明服务器处理或实际换工具结果。包没有本任务的确认编号，不为此伪造效果回执。真实槽位切换、网络延迟/断开、服务器纠正及与原版交互管理器同步仍需实机验证。

| 状态 | 处理约束 |
|---|---|
| 未取得归属 | release不写字段、不发包 |
| 连续有效选择 | 原槽不变，记录最近安装槽 |
| 字段设置在写前或写后抛错 | 保留原槽与两种可能的本地值；停止新选择，允许明确收尾 |
| 选择时发包抛错 | 本地归属保留，原任务不能继续换槽；允许收尾恢复 |
| 恢复字段后发包失败 | 保留恢复状态；下次明确重试仍发原槽，即使本地已经显示原槽 |
| 其他来源改变当前槽值 | 新选择拒绝；收尾保留该值，不强行覆盖或发原槽 |
| 玩家、世界或连接变化 | 旧记录释放归属，不向新上下文写字段或发旧包 |

失败状态不会自动重试游戏动作，也不会把已发出的包或已发生的游戏效果撤销。InputLeaseFence只有完整释放成功才推进代次；失败保留原票据供明确重试。成功释放后，旧票据不能清理新任务的热栏或重新取得新Permit。

## 3. 原生编译与包核对

命名空间内的PlayerInventory.selectedSlot:I和固定Yarn映射后的class_1661.field_7545:I分别生成接收者与int参数完全对应的SurvivalInputs.select调用。最终转换位置不再保留该原始PUTFIELD。策略不能把select标到其他字段、类型、所有者或声明；PUTSTATIC不被当作实例背包转发。

编译器拒绝选定写点的直接setter方法句柄，包括常量句柄和invokedynamic参数中的句柄；只读getter句柄保持读取用途。完整反射、动态常量、间接网络包及其他写点的审查仍属D03，不能以这组拒绝条件宣称所有动态访问已覆盖。

[包核对器](../../../scripts/mc_check_survival_build.py)核对固定来源的2＋7条字段转发、实际桥内HotbarSelection类、已有输入Mixin及映射，并保留受控生存JAR的无条件preLaunch拒绝。原构建输入锁、受审源补丁、唯一仲裁器与DSH写入者、3080参数及冻结横屏布局保持原约束。
