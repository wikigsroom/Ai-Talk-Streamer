## 明确选择与准备

初次创建世界的[配置示例](../../../configs/mc-player.example.json)：

```json
{"schema_version":2,"mode":"singleplayer","world":null}
```

`world:null`启动到标题画面，不指定联机目标。在受控目录已经有符合命名限制的存档后，可在服务全部停止时将`world`设为该存档的实际文件夹名，再重新准备。v39源码补充内部空格支持，接受1–64位ASCII字母、数字、下划线、连字符和内部空格，首字符为字母或数字；拒绝尾随空格、Windows设备名及以连字符起始的空格分隔片段。具名存档必须在本安装的`work/saves/<world>/level.dat`存在；不允许绝对路径、父目录、路径分隔符或参数拼接。名称保留为一个独立参数，传给Java的参数文件继续逐项加引号；不修剪或合并空格。

```json
{"schema_version":2,"mode":"singleplayer","world":"MC Live Offline 083"}
```

上例只适用于实际存在且同名的存档。本轮游戏正常创建的文件夹是`MC Live Offline 083`；v37/v38使用`world:null`，v37的正常菜单加载有现场证据。v39的3080客户端30项、配置3项和部署43项已分别通过；实际交付包Java读取参数文件后，两种名称对应的40项游戏参数均逐项一致，第二个双内部空格名称只是参数边界检查，没有创建第二份存档。首个部署检查的300秒超时报告保留，剩余检查单独补跑。v39已按停服、审查升级、原生构建、八项就绪和环境/设备核对流程接入实际具名目标，自动载入现有存档并正常保存退出。没有为匹配示例而重命名、复制或重建存档。
