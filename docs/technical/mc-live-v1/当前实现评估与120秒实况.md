# 当前实现评估与120秒实况

评估日期：2026-11-02。分支：`mc`。本次按用户要求暂停功能开发，只核对既有实现，并在原生3080上采集和导出一次真实节目样片。录制不改变功能源码，不公开开播，不恢复4090流程，不以人工游玩补足效果。

## 当前判断

当前系统已能在原离线世界中，由应用Agent配合真实Mindcraft物品依赖求解器控制NAIMEI，完成部分采集、制作、导航及明确失败后的重新规划；已有石镐和石斧的真实库存及正常保存证明。已具备采集内部实况的基础，尚不足以承诺长时间稳定、完全自主的生存直播。

本次连续实况进一步暴露采集与路线阻塞：最新133.204秒观察窗口没有新增效果核验成功任务。当前视频只能展示开发现状，尚不能作为稳定自主游玩或成功直播内容的交付证明。旧场制作石工具的成功和本场再次受阻的失败均保留。

正式完整联合验收仍为0/68，新人物素材仍为0/100。这两项是完整交付口径，不能据此推断所有功能都未实现；同样，局部用例或一段录像也不能将完整验收改为通过。

## 实际架构与Mindcraft接入范围

当前链路：游戏新鲜观测与库存/配方 → 应用Agent目标调度 → Mindcraft物品依赖拆解 → 原生固定技能检查与执行 → 当前NAIMEI客户端 → 服务端效果回执与后置观测 → 下一轮。语音、人格与需要模型处理的决策继续使用同一DSH链路和既有外接模型`gpt-6-luna`。

实际嵌入的是固定上游提交的`ItemGoal/ItemWrapper`算法，见[来源锁](../../../backend/game/mindcraft/upstream.lock.json)及[自主游玩说明](Agent与Mindcraft自主游玩.md)。当前没有整体运行上游Mineflayer代理、寻路、自保和全部技能。内置工作台、木镐、石镐、石斧、熔炉、面包启动目标由确定性求解优先推进；不是每个动作都调用大模型。

原生控制现有图形客户端是本项目采用的架构，执行器缺口和故障属于本项目应完成的工作。不能将其全部描述成Mindcraft模型适配，更不能用“模型已连接”推断“所有游戏能力已具备”。

## 主要难点与实际影响

| 编号 | 难点 | 当前表现及影响 | 完成判据 |
|---|---|---|---|
| 1 | 原生执行器在复杂现场的可靠性 | 土径15/16高度、半格落脚、矿坑、目标改变及采集站位会影响路线与交互；已有重复无路线及采集无进展 | 同一原档连续完成补给、制作及离开阻塞区域，效果由新观测和服务端回执证明 |
| 2 | 生存中断后的自主恢复 | 普通重生已有实证，但死亡丢物会重置物资进度；多敌、着火和取回物资尚不足以支持长节目 | 遭遇危险后自主存活/重生、恢复工具与食物并继续目标，不靠人工接管、写库存或回滚 |
| 3 | Mindcraft规划与实际可执行能力的边界 | 求解器能列材料依赖，执行器仍可能拿不到原木、到不了工作台；整合包标签曾含613个候选 | 规划只依赖实际支持且当前可执行的动作，阻塞后改走可验证的替代链，而非反复生成同一失败目标 |
| 4 | 弹幕、游戏和讲话的并发 | 同一人格和语音优先调度已存在，但没有真实新弹幕样本支撑完整链路验收 | 真实595139事件在实际游玩期间被去重、理解、回应并正式播放，危险处理仍优先且不串音 |
| 5 | 节目媒体及单机资源协调 | 游戏、数字人、语音、CPU视觉、接收器和官方录制在同机运行；完整冷启动较慢 | 实测FPS、首声/音画时延、混音和长时资源；不能用“服务端口都在线”代替节目稳定 |
| 6 | 素材、视觉与完整交付 | 新人物尚未生成；视觉死亡帧已有子项成功，但准确率与完整负载截止时间未验收 | 两套完整素材及遮罩/接缝/口型，视觉准确率/时限，68项正式验收与干净安装全部独立完成 |
| 7 | 模型工具上下文预算 | 本次开场请求在上下文预算检查以STREAM_CONTEXT_BUDGET失败；后续自动任务反馈仍能正式播放 | 新鲜游戏事实、历史和工具返回在预算内准确传递，既不超限也不丢失决策必需信息 |
| 8 | 节目推进与口播质量 | 多条语音重复解释相似失败，角色反复受阻，内容推进不足 | 同一主播能说明目标与真实进展，合并重复失败反馈，持续游玩并及时回应真实观众 |

当前最大的工程风险位于执行器与持续生存，而非再接一个模型。提高功能数量不能直接消除这些风险；必须依据真实失败分类、实际效果和连续运行证据判断质量。
