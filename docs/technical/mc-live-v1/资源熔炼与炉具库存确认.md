## 1. 实际入口及任务衔接

| 入口 | 现行实现 | 保留的约束 |
|---|---|---|
| SmeltInFurnaceTask | ControlledSmeltingTask / furnace | 原任务、世界、玩家、连接及SMELTING配方 |
| SmeltInBlastFurnaceTask | ControlledSmeltingTask / blast_furnace | 原任务及BLASTING配方；精确高炉screen/handler |
| SmeltInSmokerTask | ControlledSmeltingTask / smoker | 原任务及SMOKING配方；精确烟熏炉screen/handler |
| CollectFoodTask | 原ControlledCookingTask补给入口 | 原补给总期限、营养目标、单份转换及旧烟熏期限 |

资源包装器保存全部SmeltTarget的绝对成品目标、允许材料和可选材料，不只执行第一个目标。每轮检查现有主背包成品，依次处理尚未满足的目标；一次转换使用一份原料、一份燃料和服务器配方实际产物批量，允许最后一批超过需求。游戏内配方对象、输出组件、数量及原会话发生变化则终止，不将旧动作转给新任务。

原Task和SingleTaskChain保留尚未结束的实际ControlledCookingTask。FoodChain区分资源炉具与补给炉具，避免为补给抢占资源熔炼；补给自己创建的确认合成也继续获得补给优先级。装备、进食、盾牌和合成在炉具真正拥有库存后才被互斥，制作炉具前仍能准备必要工具和材料。

## 2. 原料、燃料与成品数量

读取当前RecipeManager的三类原生配方及首个匹配结果。只从目标允许的原料中选择可产生目标成品的实际配方，搜索限制为4096条配方、65536个材料候选。缺料通过原ControlledRecipeResourcesTask采集，沿用来源切换、实际祖先循环判断、材料净增及原根256次选择预算。

成品声明进入ResourceMaterials已有预留，原料和燃料只使用扣除活跃声明后的可用数量。同一个库存槽既可作原料又可作燃料时必须有两份；缺燃料的采集目标也计算这份原料，不能因为已有一块原木而误判燃料备齐。炉具制作可能消耗原料或燃料，因此打开炉具后重新读取库存、配方和燃料，不沿用制作前槽位。

燃料读取原生createFuelTimeMap。普通熔炉使用原始燃烧时长，高炉/烟熏按实际双倍耗燃速率折算；一份燃料必须覆盖整个配方。仅接受普通、未保护的煤、木炭、煤炭块、干海带块及原生LOGS/PLANKS标签物品；排除有配方剩余物的燃料、自定义组件物品和工具/装备，不将岩浆桶纳入这一有限实现。

替代成品集合目前按每个允许种类保守预留目标数量；这可能多留库存，不代表全部消费者的最小全局分配。所有消费者的依赖图、完整回溯、容器/工具/基地优先级及任意数据包配方仍在完整待办内。

## 3. 炉具与服务器库存确认

OpenWorkstation使用精确炉具方块和有限制作成本，沿用原任务的界面归属。SurvivalGui核对原方块位置、实体、screen/handler对象、syncId、世界、玩家和连接；普通熔炉、高炉、烟熏炉不能互相冒用租约。

打开炉具后先缓存服务器完整Inventory同步包，包含39槽、光标及revision。资源转换只从这个原界面基线开始；没有完整初始包则等待，不能以客户端预测充当服务器确认。每次点击仍使用唯一待确认动作、实际槽位和完整组件数量，等待原服务器同步；配方产物、余料回收和空光标全部核对后才结束。本次也允许原料/燃料/产物具有相同物品组件，角色由槽位和精确数量区分。

| 时限 | 现行规则 |
|---|---|
| 原补给烟熏 | 原8000ms转换、原GUI期限不变 |
| 资源烟熏 | 配方最多120tick，等待tick×50+3000ms，最大9000ms；仍受原烟熏GUI绝对期限限制 |
| 普通熔炉/高炉资源 | 配方最多1200tick，等待tick×50+3000ms，最大63000ms |
| 新炉具GUI | 开启1500ms；已开启空闲65000ms、绝对75000ms；观察不续期，进展不突破绝对期限 |

普通200tick熔炉配方获得13000ms等待，实际100tick资源烟熏配方仍为8000ms。所有时限还受原根控制和生命周期约束；超出者停止，不以本地动画当作加工成功。中断时只释放当前声明，不丢弃物品、不用新许可清理旧任务；人工接管沿用原优先级。

## 5. 本轮实际验证及边界

本轮实际执行桥332、生存最终575、Java↔Node互通39、Node126（含一次桌面/窄屏浏览器）及Python HTTP5，共1077项不同检查通过，新增49项。新增覆盖三类实际编译包装器、原生配方/燃料接线、完整初始包、原任务保留、数量/预留、同份原料兼燃料、配方时长、相同组件、多份产物、GUI期限、固定原因及主播事实。7项原因检查另行重查，不重复计数。
