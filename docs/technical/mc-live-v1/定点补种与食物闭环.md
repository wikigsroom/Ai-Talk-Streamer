# 定点补种与食物闭环

当前在3080的原生Windows、NAIMEI和现有离线存档`MC Live Offline 083`中联调。采收、补种和进食分别产生任务及证据；政策检查、原生库检查和界面检查均不能替代真实世界效果。

## 已接入的操作

| 编号 | 操作 | 成功条件 |
|---|---|---|
| P01 | 采收成熟小麦、胡萝卜、土豆、甜菜，收集西瓜片或已有食物掉落 | 当前来源与安全路线通过检查，服务端库存回执与实际新增量符合任务目标。采集数量表示新增量。 |
| P02 | 在明确空格补种小麦、胡萝卜、土豆、甜菜 | 同一任务、世界会话和控制权限下，服务端确认消耗一个种子或作物，指定格出现对应的零龄作物，输入正常释放。 |
| P03 | 使用背包中的食物 | 服务端确认消耗和食物效果，再核对当前饱食度；补种本身不增加饱食度。 |

P02使用已有的`use_item`固定技能，`purpose=activate`，不增加任意命令执行能力。例如：

```json
{
  "skill": "use_item",
  "item_id": "minecraft:wheat_seeds",
  "purpose": "activate",
  "target": { "dimension": "minecraft:overworld", "x": 1361, "y": 75, "z": -152 }
}
```

示例坐标仅说明格式。`target`必须取自当前实际观测，表示耕地上方准备种作物的空格；不能把下面耕地方块的坐标当作播种格。本操作不代替移动，目标必须已加载、位于世界边界内、为空气且无流体，下面为原版耕地，顶面射线可见且够得到；原版放置与作物存活条件还会再次核对。

仅四种物品可以在`activate`时带`target`：`wheat_seeds`、`carrot`、`potato`、`beetroot_seeds`，均限`minecraft`命名空间。四种作物补种必须有目标。进食、装备和其他方块放置不能带这个字段；已有普通方块放置继续使用真实当前准星。

## 各端衔接

原生适配器通过`capabilities.features.targeted_planting`明确声明能力。缺失或为false时，后台对定点补种的预检与派发均拒绝；旧Fabric物品适配器也明确拒绝目标字段，防止忽略目标后操作当前准星。

该能力还须在完成初始化的真实NeoForge客户端通过26项注册表及回执边界核对：四种种子与作物绑定、零龄确认、错误作物/空格/非零龄拒绝及普通方块回执兼容性。结果保存在原生`native_planting`诊断中；失败即不声明该能力。独立JVM缺少NeoForge加载器上下文，不能初始化这套注册表；独立规则与几何检查和真实客户端核对分别记录，前者不替代后者。

`details.nearby_food.planting_sites`提供最多八个可见、够得到的空耕地位置，另有截断标记；沿用六格水平、三格垂直的有限观测范围及最多一秒缓存。列表不是种子库存、作物存活或执行成功证明。任务开始和实际使用前均重新核对位置，不能凭旧缓存继续播种。

后台在世界目标、投票与建议整理的物品用途里提供“补种作物”，列出四种作物和当前可补种位置；没有位置时不生成默认坐标。世界目标的补种步骤使用“任务有已验证的成功证据”作为默认完成条件。保存草稿和采纳建议仍不授予AUTO权限。

模型只有在适配器声明该能力时才得到定点补种的工具说明。它需先核对食物储备、已有种子和位置，调用只读前置检查，再提交单次固定任务。胡萝卜、土豆既可食用又可播种，一次播种会消耗一个，不能把采收的毛增加量当成播种后的净库存。

## 执行与回执

执行沿用唯一输入所有者和原任务的permit；需要换热键栏时先等待真实库存交换确认，受控转向目标并确认潜行，再调用一次原版物品使用。它不直接设置方块或库存，不修改饥饿、物品、世界规则和权限。

服务端库存回执与方块更新必须分别满足。客户端预测、其他格的作物、错误作物、非零龄作物或只有库存扣减均不能完成任务。回执还绑定目标维度与精确格坐标；取消、断线、失焦、接管或世界更换沿用原清理路径，已有部分效果继续保留为证据。

本地世界中找不到自然成熟作物、食物或空耕地时，明确记录不可执行条件；不生成测试农田、注入种子或调整饥饿来制造验收。实际采收、实际补种、实际进食及补给长链仍须逐项取得现场证据。
