# 世界会话、目标与后台复核

适用分支mc，A库schema3，OpenAPI业务版本1.3.0，内部WS仍为1.0。当前仅完成源码、本地协议及浏览器检查；真实游戏、正式DSH与平台整链验收未完成。完整发布范围仍由[08章](08-完整交付规划.md)约束，不减少交付域。

## 1. 数据职责

| 记录 | 权威与实际行为 |
|---|---|
| B任务 | 保留原安装、boot、世界/会话、request、epoch、version、goal、effect及evidence；A不编造终态 |
| task_recovery | A核对状态与独立revision，记录查询次数、核对boot和错误；不是任务执行版本 |
| task_dispositions | A人工决定及独立revision、原因、原任务规范化投影hash、实际停控观测上下文；不是成功证明 |
| world_sessions | A实际收到的会话观测历史；标记观测中、不可观测或观测会话结束 |
| world_goals / world_goal_tasks | A有界目标、步骤、批准会话、任务引用及实际条件证明；不写第二份人格记忆 |

任务接受记录与目标任务关联在同一A事务提交后才发给B；关联失败回滚任务与幂等记录，不派发动作。TaskCreate可带world_goal_ref，B任务正文不加入A目标元数据。game_start_task完成实际check_action后，自动关联与当前已批准下一步骤完全相同的固定goal。第007轮另增game_get_audience只读工具，并支持明确suggestion_id关联，详见[观众互动](观众建议投票与任务闭环.md)。

## 2. 未知结果的人工处理

1. 操作者先暂停；以实际新鲜观测确认非AUTO、输入释放、automation_ready=false、无A租约且B active_task_id为空。
2. 非终态任务先从B核对，只有missing/conflict且checked_bridge_boot_id属于当前boot时允许人工处理。已确认终态的unknown/partial也可记录未知结果；verified效果不走此入口。
3. 请求同时核对task version、recovery revision、当前boot/世界会话、control_epoch及观测seq。无recovery记录时其期望revision为0；填写原因并明确acknowledge_unknown=true。
4. 事务保存独立处置、核对状态operator_closed、请求幂等记录与审计。原任务state/version/effect/evidence保持原样；不会发出task_start、lease_grant或AUTO。
5. 解除的仅是该条A待处理任务对后续调度的拦截。关联目标步骤转blocked，须明确允许重新规划，再批准当前会话，之后另行明确授权AUTO。
6. 若B可靠转移或实际观测重新报告该非终态任务仍在运行，处置转reopened、核对转conflict、撤销A租约并请求PAUSED。可靠转移与重开拦截先持久提交，再发送ACK；它不是B已完成停控的证明。

同request_id同正文只返回已有结果；同id不同正文拒绝。原人工记录hash说明当时A保存的规范化任务投影，不声称是B磁盘文件的逐字节hash。以后收到B实际终态仍须按原上下文与版本规则核对。

## 3. 会话观测历史

新观察到的world_session_id保存首次/最近观测时间、实际seq、boot、connection_generation与连接次数。稳定world_id下同一会话重连增加连接次数；新会话单独建行。记录按15秒节流持久刷新，正常断线/退出会刷新内存中最后一次实际观测；突然断电可能丢失最近15秒的非关键会话摘要，关键任务仍走独立持久账本。界面标注“已保存序号”，不冒充最新观测序号。

断线或宿主重启标记unobserved，表示A无法继续观察，不推断MC世界已经关闭。实际世界会话变化时旧观测会话标记ended；这只描述A的观测生命周期。旧库v2只有最后登记会话，迁移标记legacy_registry且boot/seq/generation为空、连接次数0；不补造缺失的整段历史。

历史分页默认20、上限100；当前硬限10000条会话，到限拒绝新增、关闭桥连接并撤销A租约，不自动删除，也不声称已收到B输入释放确认。B已归档可靠事件向A的完整历史投影、历史摘要/保留与维护页面仍待实现；A会话记录不等于收到全部B事件。

## 4. 世界目标

每个世界最多128条目标，每条1–16步骤；每步骤最多10个任务引用。同一世界最多一条active目标，摘要最多返回16条非归档目标，完整历史由分页读取。步骤内容为固定技能goal加明确完成条件：实际库存阈值、实际位置范围、实际饱食度或有验证证据的成功任务。

草稿只能在新鲜停控且A/B均无活动任务时登记。批准、暂停、归档与允许重试均需当前世界上下文和目标revision；不会自动开启控制。断线、A重启或新游戏会话使active目标转needs_review；历史完成步骤保留为当时的里程碑，不能据此宣称当前仍持有物品。

未关联任务且新鲜、已知的实际观测已满足条件时，可以完成步骤，proof.source=observation且task_id=null，不声称由AI执行。有关联任务时先等B succeeded/verified及有效核对，再等实际观测满足后置条件，且证据世界及序号有效；proof记录task_and_observation、任务id、实际会话/seq/时间。未知字段、未知效果、运行中任务及过新的证据不能推进。

失败或未知任务使步骤blocked；人工确认未知不算完成。允许重新规划只把该步骤改为pending并将目标转needs_review，保留旧任务引用；下一次动作仍需新规划、当前前置检查、显式目标批准和AUTO授权。不因旧检查点、旧目标或旧task_id重放动作。

## 5. 操作者界面与运行边界

已有后台增加“MC 世界管理”导航，页面路径`/mc-control`，样式和脚本使用固定的同源资源。8010的原生代理提供页面/API/SSE；应用继续免登录，不创建第二位Humanity写入者，也不打开音视频播放器。

页面提供当前世界/观测/生命/饱食及已确认模式、模式请求及异步结果、目标草稿编辑/批准/复核/归档/重新规划、会话与任务分页、账本核对、人工未知结果处置。人工处置提交前重新读取状态，核对原boot/世界会话/epoch，再绑定最新seq；任务/recovery版本继续使用操作者打开时的版本，变化即拒绝。表单保留并展示失败原因，不将请求受理显示为游戏成功。
