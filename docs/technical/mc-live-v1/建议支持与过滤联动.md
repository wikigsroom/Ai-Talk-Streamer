## 来源账本与数值口径

`backend/game/audience-sources.mjs`在既有GameStore的objects表保存`audience_support`和`audience_support_manifest`。沿用schema3的扩展对象机制，不建立第二个游戏或Humanity写入者。账本只保存建议、世界会话和消息编号，不复制昵称、弹幕正文或原始平台UID。

| 公共字段 | 含义 |
|---|---|
| `support_count` | 历史累计接受合并的来源事件数，兼容既有语义 |
| `support.historical_events` | 同一历史累计数，不能解释为独立人数 |
| `tracked_events` | 当前仍保留身份关联的完整来源数，独立于公开的32条来源摘要 |
| `visible_events` | 实际Room记录仍存在、平台与房间匹配、非测试、未隐藏、未被当前规则过滤的来源数 |
| `visible_viewers` | 可见来源中不同非空user_key数量；按平台/房间隔离，不按昵称去重，不代表独立自然人或平台认证 |
| `unidentified_events` | 可见来源中没有稳定账号关联的事件数，不猜测人数 |
| `source_availability` | Room可用时为available；不可用时为unavailable，可见数量全部为null，不能误报0 |
| `coverage` | complete、legacy_partial或retained_window_expired，分别表示完整来源、旧记录不完整、终态明细保留期已过 |
| `evaluated_at` | 最近一次数值变化/来源核对结果的时间，不是平台发生时间 |

新增来源与建议合并在既有GameStore事务内保存。公开`source_event_ids`继续最多32项，完整支持通过独立账本核对；即使这32项都被过滤，更早的有效来源仍能支持该建议。重复发言可增加事件数，同一账号仍只计一个可识别账号。

旧建议只能从仍保留的来源编号回填。历史累计数大于实际可回填数时明确为legacy_partial，不根据昵称或累计数构造缺失观众。

## 过滤、撤回与控制

屏蔽词、昵称或账号配置保存后，Room立即调用统一复核；主机tick另以1秒间隔核对缺失/被清理的来源。无关的留言换边、滤镜和声音配置不触发完整支持扫描。批量读取Room消息时每次最多200个SQL参数。

1. 投票按实际选票来源撤回并重算，关闭结果受到影响时作废，不自动选择另一目标。
2. 普通建议重算当前有效来源与账号数；最后来源失效时取消。解除过滤可以恢复仍开放建议的数值，但不自动重投旧票、不重新开启已取消建议、不提交游戏任务。
3. 数值变化推进建议修订号，旧审批/派发请求不能越过CAS复核。前置查询返回后仍须重新验证修订与来源。
4. 已转成任务的历史关联与实际世界效果保留；来源变化不伪造游戏回滚。游戏停止继续使用显式取消/接管路径。
5. Room暂时不可用不销毁选票归属或取消建议；执行前仍因无法证明有效来源而拒绝派发。存储错误则沿用主机故障停控，保存的过滤配置用于重启后重新核对。

公开口播沿用既有来源复核、取消屏障和真实声音回执。过去确实播完的事实与当前来源是否仍可用分别记录，不以过滤操作伪造过去未播。

建议结果与关联任务的回应引用从完整支持账本选取当前仍有效的最多32条来源。即使最初的32条公开摘要全部失效，其他实际来源仍可支持核对；生成中来源改变继续走原期限/尝试次数限制及取消屏障。投票结果与投票建议以真实投票记录为依据，不要求内部`vote:`编号在Room中冒充一条留言。正式声音完成仍须实际回执。

## 容量、保留和接口

每建议最多4096个完整来源，全库最多32768个支持来源。旧记录累计数已达到既有1000000上限时同样拒绝继续合并，不接受“收到来源但累计不变”的输入。达到容量时新输入仍保留为弹幕，不继续虚增累计支持，也不绕过导播确认创建任务。`AudienceSummary.support_budget`报告实际容量；后台显示建议已满或历史明细待清理。

终态建议在原`expires_at`后24小时可清理支持关联明细，保留建议历史、累计数、原有有界来源摘要及任务关联。开放建议不会被此清理提前删除；到期建议先走既有expire。已清理的终态明细不因再次浏览而回填。完整去身份化、Humanity删除、全库保留、联合备份与恢复仍由D07/D14继续实现，不能把本明细清理当作隐私删除已完成。

结构版本1.9.0增加`AudienceSupport`和`AudienceSupportBudget`；既有建议没有support字段时仍兼容，后台显示“当前支持待核对”。本地接口结构检查不是完整OpenAPI规范验证。

## 所有权和故障退出

同步输入连续占用事件循环时，GameStore的定时续约可能得不到执行。既有有效所有者在剩余租约不超过20秒的写入中取得SQLite写锁，再次核对当前所有者和实际时钟，续为原有30秒租约，并在同一事务完成写入。外层事务继续控制提交和回滚；过期或其他所有者不得通过该路径恢复写入。原9秒定时续约保留；游戏控制、声音与正式消费者的租约不随此修改。

关闭主机时，即使回应终态无法写入游戏账本，仍尝试取消独立StreamState中的待播请求、释放规划与派发、监听器、连接和SQLite。关闭错误保留在主机`closeErrors`，不补造历史终态；下次正常接管继续按HOST_RESTART标记未知，不自动重播。释放所有权记录报错时SQLite仍在finally中关闭。本地故障注入不代表跨进程、磁盘和真实音频的全面恢复验收。

## 验收边界

验证范围包括真实SQLite/Room、实际过滤配置、投票与建议、CAS前置查询、重启及生产后台页面。容量边界使用明确标记的持久化数据夹具；浏览器使用本地协议夹具，全部专用页面和进程在检查后关闭。

真实平台样本、网络延迟、MC效果、模型与正式声音、Humanity多观众记忆读写/删除、全部过滤变化的跨进程恢复与完整负载仍须统一实机验收。
