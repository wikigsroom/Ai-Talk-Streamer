# 成熟作物与离线补给

适用当前3080原生NeoForge单人测试。原有普通采集只能获得木石矿物；进食执行器虽可使用库存食物，却不能由这些采集目标取得农作物补给。v41将成熟作物和已掉落的白名单食物接入同一`gather`技能、任务账本、输入仲裁器与库存后置确认，不增加第二操作者或物品生成渠道。

| 来源 | 采集目标 | 成熟条件 |
| --- | --- | --- |
| 小麦 | `minecraft:wheat` | age=7；取得后需通过真实配方合成面包 |
| 胡萝卜 | `minecraft:carrot` | age=7 |
| 马铃薯 | `minecraft:potato` | age=7；毒马铃薯不作为补给目标 |
| 甜菜根 | `minecraft:beetroot` | age=3 |
| 西瓜方块 | `minecraft:melon_slice` | 实际普通西瓜方块 |
| 已掉落食物 | 面包、熟肉、熟鱼、烤马铃薯、苹果及上述安全蔬果 | 客户端实际物品实体；不得据此推断生产来源或必然可达 |

只破坏成熟作物，保留原有危险地形、支撑、射线、工具、任务代次、时间界限与输入释放约束。不破坏未成熟作物，不为获取苹果盲目破坏树叶，不破坏有伤害的浆果灌木，不注入物品、修改饥饿值或使用作弊。现阶段采收不自动补种，掉落数量和额外种子由实际服务器与库存确认；不能根据方块消失就记采集成功。

v42统一食物观测与采集器的瞄准方法：使用方块实际外形的中心。整合包原生射线检查证实，固定的半格高度瞄准点会漏掉半格高及更低的外形；两处世界位置、四种高度的生产函数回归共26项通过，8条射线均命中。完整方块仍命中，几何检查不代表现场作物采收。首轮独立检查的Windows参数文件编码失败保留，更正后使用同一整合包库完成验证。

`details.nearby_food`是可选的原生客户端观测：成熟作物以所在方块为中心，距离6格、垂直偏移最多3格，只读已加载且射线无遮挡的来源；`vertical_radius=3`描述这部分作物扫描。白名单掉落物按玩家实际位置计算6格球形距离，不使用作物的垂直层限制。两类来源合计最多8条。扫描结果最多缓存一秒，世界、玩家、连接或所在方块变化立即重采；`sampled_at`给出实际扫描时间，`truncated`区分截断。每条只提供来源种类、物品、方块、位置和距离，不把未来掉落或来源当作现有库存。

该字段保留在规划上下文中；`action_precondition_required=true`明确要求随后执行原生`game_check_action`。射线无遮挡不等于安全可达、无服端限制或保证掉落；空列表不代表扫描区域之外没有食物。旧观测缺少此字段仍然有效，不生成虚构的空食物事实。普通补给优先使用真实库存；小麦需要面包配方，马铃薯可以走既有熔炼链。自主进食沿用原任务许可，并扩展到采得的安全蔬果，不食用腐肉、毒马铃薯、蜘蛛眼和河豚。

原生构建、策略夹具、契约和规划上下文检查与真实采收、实际进食分开记证。正式接入须正常停机、审查升级、原生重编译、环境准备和设备核对；实际世界是否有可用食物来源须现场观察，不能通过植入测试作物或修改存档来制造通过。执行结果见[实现进度](实现进度.md)与[083证据](../../evidence/mc-runtime-round-083.json)。
