## 已有双机环境的入口

| 页面 | A 人物服务上的路径 | 用途 |
| --- | --- | --- |
| 导播台 | `/admin` | BGM、滤镜、留言、私聊和会话管理 |
| 原工作室 | `/studio.html` | 原有交互与渠道设置 |
| 平台管理 | `/platforms` | 房间、采集器、自动互动模式 |
| 人格与记忆 | `/memory` | 已有 DSH/Humanity 管理 |
| 音色 | `/voice-settings` | O07 / F07 试听、下一请求切换 |
| 静音预览 | `/output.html?renderer=preview` | 查看正式包装，无播放权威 |
| 透明弹幕姬 | `/overlay?layer=chat` | 无人物、无音频，只含评论与可选飘屏 |
| 透明留言姬 | `/overlay?layer=messages` | 无音频，只含留言卡/置顶 |
| 透明礼物层 | `/overlay?layer=gifts` | 无音频，只含礼物/关注/醒目留言提醒 |
| 完整透明层 | `/overlay?layer=all` | 无人物、无音频的全部包装 |

B 设备的本地管理台同样可通过 `http://127.0.0.1:8020/admin` 访问；这是在 **B 设备本机** 输入的地址，不能在另一台电脑使用该 loopback 地址。

## 第一次使用：建议顺序

1. 打开 A 的 `/admin`。确认 A 人物在线、B 播放端在线、当前音色 O07。后台人物预览默认不拉实时流，点“打开静音实时预览”才连接，用完关闭。
2. “音乐与声音”选择内置配乐，先保持 BGM 22%、人声 100%、说话自动压低。自带原生配乐可直接使用。需要自己的曲目时上传音频，并等待探测和保存成功。
3. “画面与包装”选择主题，调整标题、公告和滤镜；原生日光是默认。可点击本地测试评论、礼物和关注观察位置，完成后清理测试消息。
4. “弹幕与留言”写一条导播留言并上墙，或选中收到的评论上墙。可置顶或标记已答。上墙和“填入回复”均不自动开口。
5. 点击“开始本地会话”，在总览输入一句文字并选择“按原文播报”。它经真实本地 TTS、人物口型、B 接收器播放；选择 AI 回复则使用既有云端渠道。
6. “与知夏私聊”用于拟话题和问答。满意后点回复下方“送到直播播报”，先进入总览草稿，检查后再提交。私聊本身不会发声。
7. 公开开播仍由 B 的官方直播姬完成。管理台不声称本地会话按钮等同平台开播，也不代替平台人脸核验或房间状态检查。

## 官方直播姬的音画源

沿用 [A/B 双机方案](../deployment/SPLIT_DEVICE.md)和 [B3080 接收手册](../deployment/RTX3080_RECEIVER.md)。B 画布 720×1280，浏览器素材使用：

```text
http://127.0.0.1:8020/output.html?output=platform&renderer=livehime&buffer_ms=4000&rev=room-v1.2
```

启用素材内部音频，素材音量 100%；监听关闭但允许声音输出到流，桌面音频和麦克风静音，防止重复收音。默认完整包装已经嵌入素材，**只需一个素材**。

若确实需要独立拖动弹幕/留言，则在管理台关闭“将互动叠层嵌入正式直播画面”，再添加对应 `/overlay?...` 透明素材，画幅仍是 720×1280。透明层没有音频，不应额外开输出播放器。上墙和评论列有独立开关，避免同一消息重复显示。

## 音乐管理

支持 WAV、MP3、OGG、FLAC、M4A，单次不超过 128 MiB、1 秒到 2 小时，曲库最多 103 首（含三首内置）。真实 ffprobe 要求只有音频流，不接受视频伪装、服务端 URL 或用户提供的磁盘路径。一次只允许一个上传；失败清理临时文件，成功保存元数据与 SHA。大文件通过 B8020→A8010→DSH 流式转发，未用默认小 JSON 请求体限制读取整个文件。

“本机试听”只在导播明确点击时播放；切换工作区结束试听。正式音乐从 B 的节目素材发声。后台视频保持静音，不要把后台试听或桌面声音一起推流。音乐状态重启后暂停，需人工恢复。删除只能删除自建曲目。

## 屏蔽、停止和紧急静音

屏蔽词按正文大小写不敏感包含匹配，昵称按完整昵称匹配；API 也支持 hash user_key 精确匹配。每种规则最多 200 条。隐藏只影响该条显示，屏蔽还影响后续显示与尚未派发的自动回复。

“停止当前回复”只取消当前 DSH 请求；“紧急静音”取消当前和排队请求、暂停 BGM 并设置总静音。恢复前检查收件箱和队列，在“音乐与声音”取消总静音后重新播放音乐。紧急静音不是平台下播按钮；公开下播仍在直播姬操作。

## 安装、更新、回滚

本版本复用 [O07/F07 原生环境](../deployment/BASELINE_O07_F07.md)，不重新安装模型。需 Node 24（node:sqlite）、现有 Python/aiohttp 环境、原生 ffprobe、官方直播姬和支持 Web Audio/WebCodecs 的现有浏览器内核。禁止 Docker、WSL、虚拟机。

新增代码位于 `backend/room/`、`web/admin.*`、`web/room-*`，随 DSH 和人物服务启动，不注册新的开机任务或端口。完整变更清单见发布清单和验收哈希。

1. 在本地/测试环境先执行 Node、Python 和路由回归；保留历史验收文件。
2. 确认本地会话及公开直播均结束，再做一致备份。将新源文件同步到 A 项目根，按既有安装映射把 `integration/dsh_bridge.py` 放入 LiveTalking 的 `server/dsh_bridge.py`，把 `web/` 对应文件放入其 web 目录；`integration/obs.html` 保持根目录源文件。
3. 使用现有 `scripts/dsh_control.py` 管理唯一 DSH 进程。首次安装改变了 Python 路由时，按原生启动器顺序重启人物/声音服务；以后仅 RoomManager/前端变更可只重启 DSH、刷新素材。不要启动第二个实例复制运行中的状态库。
4. B 接收器实际运行根目录是 `receiver-b`。同步 `scripts/receiver_service.py` 与 `scripts/receiver_control.py` 到该根目录对应位置，用已有 receiver_control 重启接收器，不关闭官方直播姬。原生 venv 的 launcher/child 需按脚本与配置精确匹配后同时收尾。
5. 刷新 B 的浏览器素材一次，检查 `/api/dsh/room/state` 的 version 是 `room-v1.2`、正式 player connected，再本地播报。仅有 A 文件更新或 Git 同步不证明 B 已刷新。
6. 回滚时先结束本地会话，停止唯一 DSH；恢复源文件和对应一致备份，再按原启动顺序恢复。只回滚代码不自动回退记忆、更正或删除账本；不要用旧主文件覆盖活跃 WAL。

## 备份和清理

`/room/export` 仅保存包装设置，适合换主题前留档。完整备份须使用 SQLite backup API 或在唯一进程完全停止后备份主库及必要的 WAL/SHM，并同时备份自建音频和曲目索引。不要将私人消息、私聊、模型或 API 配置提交到 Git。

下播后暂停音乐、结束本地会话、清理本地测试消息。关闭自己打开的静音预览、透明层预览和无用浏览器标签；不要关闭用户其他窗口。三首原始配乐与历史测评素材不是临时文件。现有定时记忆维护沿用 DSH/Humanity 原策略，本次没有将预算延后等旧问题改成“已通过”。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 上传 2 MiB 以上返回 413 | 核对 B 实际 `receiver-b` 根目录及正在运行的解释器/脚本；不能只更新父目录。确认 B 与 A 都启用了上传流式转发 |
| A 后台正常、B 没包装 | 刷新 B 浏览器素材，检查 room-v1.2 和 player.connected；使用同一素材地址，避免开第二个正式消费者 |
| BGM 按钮成功但听不见 | 查看正式播放器 audio_state、music_playing、error；确认曲目上传成功、素材启用内部音频、总静音关闭。后台预览静音是正常行为 |
| 有回声 | 关闭桌面音频/麦克风，停止导播试听；只保留一个正式素材的源内音频 |
| 设置冲突 | 刷新当前设置后再修改，409 表示另一个页面已保存新版本 |
| 礼物动画重连后没重放 | 属于预期行为；历史礼物仍在收件箱，重连不会重新感谢旧礼物 |
| Agent 没发声 | 私聊默认不发声；转入草稿并明确提交。云端不可用时显示生成失败，不能据此声称本地人物故障 |
| 开了深色主题仍是白天 | 深色只改变包装配色，不替换既定日光宿舍场景 |
| 屏蔽后角色还说上一句 | 该回复可能已经排队；停止当前回复或使用紧急静音 |
